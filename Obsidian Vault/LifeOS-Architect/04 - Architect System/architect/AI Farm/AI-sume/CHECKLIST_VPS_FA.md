# چک‌لیستِ راه‌اندازیِ LANGAR روی سرورِ مجازی (VPS) — برای آماتور

> این پروژه با **Docker** بالا می‌آید (۴ کانتینر: bot + api + db + redis).
> پس روی سرور فقط کافی است **Docker** نصب باشد؛ بقیه خودکار است. قدم‌به‌قدم برو و هر تیک را بعدِ انجام بزن.

---

## مرحله ۰ — VPS چیست و کدام را بخرم؟ (تصمیم، نه دستور)

**VPS** یعنی یک کامپیوترِ همیشه‌روشن در اینترنت که اجاره می‌کنی تا بات شبانه‌روزی کار کند (نه روی لپ‌تاپِ خودت).

**این پروژه چقدر منبع می‌خواهد؟** حداقل **۲ گیگ RAM**، راحت با **۴ گیگ**. دیسک ~۲۰ گیگ کافی است.

| گزینه | مشخصات | هزینه | برای چه کسی |
|---|---|---|---|
| **Hetzner CX22** (پیشنهادِ من) | 2 vCPU / 4GB / 40GB | ~€۴.۳۵ (~$۴.۶) در ماه | ساده، پایدار، x86 — بی‌دردسر |
| **Oracle Cloud — Always Free** | 2 OCPU / 12GB (ARM) | **رایگانِ همیشگی** | ارزان‌ترین، ولی ARM و ثبت‌نامش سخت‌تر |
| **Contabo / DigitalOcean / Vultr** | ۴GB | ~$۶–۱۲ در ماه | جایگزین‌ها (alternative) |

- **ضروری یا اختیاری؟** ضروری (بدونِ سرور، ۲۴ ساعته نمی‌شود).
- **ارزان‌ترین:** Oracle رایگان است ولی چون **ARM** است باید دقت کنی imageها arm64 باشند (همه‌ی imageهای این پروژه arm دارند، ولی setupش حوصله می‌خواهد). برای شروعِ بی‌دردسر **Hetzner** را پیشنهاد می‌کنم.
- **vendor lock-in:** چون همه‌چیز Docker است، هر وقت خواستی کلِ پوشه را به سرورِ دیگری منتقل می‌کنی و `docker compose up` می‌زنی. قفلِ فروشنده تقریباً صفر است. ✅

- [ ] یک VPS با حداقل ۲ (ترجیحاً ۴) گیگ RAM گرفتم، **Ubuntu 24.04** را به‌عنوان سیستم‌عامل انتخاب کردم.
- [ ] **IP** سرور و **رمز/کلیدِ ورود** را یادداشت کردم.

---

## مرحله ۱ — اتصال به سرور (SSH)

«SSH» یعنی از کامپیوترِ خودت واردِ ترمینالِ سرور می‌شوی.

- [ ] روی ویندوز برنامه‌ی **PowerShell** را باز کردم (یا [PuTTY](https://www.putty.org/)).
- [ ] دستور زدم: `ssh root@<IP-سرور>` و رمز را وارد کردم.
- [ ] (توصیه‌ی امنیتی) به‌جای رمز از **SSH key** استفاده می‌کنم — امن‌تر است.

---

## مرحله ۲ — آماده‌سازیِ سرور و نصبِ Docker

این دستورها را داخلِ سرور (بعدِ SSH) بزن:

```bash
# ۱) به‌روزرسانیِ سیستم
sudo apt update && sudo apt upgrade -y

# ۲) نصبِ Docker + Compose با اسکریپتِ رسمی
curl -fsSL https://get.docker.com | sudo sh

# ۳) تست
sudo docker version          # باید Client و Server هر دو بیایند
sudo docker compose version
```

- [ ] `docker version` هم Client هم **Server** را نشان داد. ✅

## مرحله ۳ — امنیتِ پایه (مهم، رد نکن!)

- [ ] **فایروال** را روشن کردم و فقط پورت‌های لازم را باز گذاشتم:
  ```bash
  sudo ufw allow OpenSSH
  sudo ufw enable
  ```
- [ ] ⚠️ **پورتِ دیتابیس (۵۴۳۲) را به اینترنت باز نکردم.** در این پروژه db فقط داخلِ شبکه‌ی داکر دیده می‌شود — همین درست است، دست نزن.
- [ ] پورت **۸۰۰۰** (api) را فقط اگر واقعاً از بیرون لازم داری باز کن؛ وگرنه بسته بماند (بات از داخل به api وصل است).
- [ ] ورودِ root با رمز را خاموش و SSH key را فعال کردم (اختیاری ولی توصیه‌ی جدی).

## مرحله ۴ — انتقالِ پروژه به سرور

- [ ] کلِ پوشه‌ی **`AI-sume`** را به سرور آوردم. دو راه:
  - ساده: با برنامه‌ی [WinSCP](https://winscp.net/) پوشه را drag & drop کن.
  - یا با Git: روی سرور `git clone <آدرسِ ریپوی خودت>` (اول باید روی GitHub گذاشته باشی‌اش).
- [ ] ⚠️ **فایل‌های `.env`ِ واقعی را در GitHub نگذاشتم** (`.gitignore` این کار را می‌کند) — کلیدها فقط روی سرور باشند.

## مرحله ۵ — ساختِ فایلِ `.env` (کلیدهای واقعی)

```bash
cd AI-sume
cp .env.example .env
nano .env        # ویرایش
```

این خط‌ها را پر کن:

- [ ] `BOT_TOKEN` — از ربات **@BotFather** در تلگرام
- [ ] `OWNER_ID` — آیدیِ عددیِ خودت از **@userinfobot**
- [ ] `POSTGRES_PASSWORD` — یک رمزِ قوی بساز
- [ ] `DATABASE_URL` — **همان رمزِ بالا** را داخلش بگذار (باید یکی باشند)
- [ ] (اختیاری) `CLAUDE_KEY` یا `OPENAI_KEY` و `BRAVE_API_KEY` — بدون‌شان آفلاین کار می‌کند

برای ذخیره در nano: `Ctrl+O` بعد `Enter` بعد `Ctrl+X`.

## مرحله ۶ — بالا آوردنِ کلِ سیستم با یک دستور

```bash
sudo docker compose -f docker-compose.unified.yml up -d --build
sudo docker ps
```

- [ ] در `docker ps` این چهارتا **Up** هستند: `langar-bot` · `langar-pro-api` · `langar-pro-db` · `langar-redis` ✅
- [ ] اگر یکی بالا نیامد، لاگش را بخوان:
  ```bash
  sudo docker compose -f docker-compose.unified.yml logs <اسمِ سرویس>
  ```

## مرحله ۷ — تست‌های پذیرش (همه باید سبز شوند)

- [ ] سلامتِ بک‌اند: `curl http://localhost:8000/health` → باید `status: ok` بدهد
- [ ] در تلگرام: `/start` و `/menu` جواب می‌دهند
- [ ] **kill-switch:** `/halt` → بات ساکت می‌شود → `/resume` → دوباره کار می‌کند
- [ ] `/research یک سؤال` → جواب می‌دهد و منبع را نشان می‌دهد
- [ ] `/ailab` و `/ai_budget` جواب می‌دهند

## مرحله ۸ — ۲۴ ساعته‌سازی + بکاپ

- [ ] `restart: unless-stopped` روی همه‌ی سرویس‌ها هست (در compose هست ✅) — یعنی اگر سرور ری‌استارت شود، خودکار بالا می‌آیند.
- [ ] یک **بکاپِ روزانه** بگذار (با `cron`). حداقل این‌ها:
  - دیتابیسِ بات: `langar/langar.db`
  - دیتابیسِ pro: با `pg_dump` از کانتینرِ db
  - پوشه‌ی `langar/patches/`
  - ⚠️ `.env` را در بکاپِ ناامن نگذار (یا رمزگذاری‌شده).
- [ ] هر چند هفته `sudo apt upgrade` بزن تا سرور امن بماند.
