# LANGAR — چک‌لیست راه‌اندازی، کاستومایز و همیشه‌روشن‌کردن

> تو رئیس و طراحی. دو نیرو داری:
> **👤 خودت** — کارهای دستی (تلگرام، خرید سرور، تأیید).
> **🤖 Cowork Claude** — کارهای فنی (کد، deploy، دیباگ). پرامپتِ آماده‌ی هر مرحله را کپی کن و بهش بده.
>
> ترتیب را به‌هم نزن. هر مرحله یک «خروجیِ قابل‌تأیید» دارد — تا آن را ندیدی، نرو مرحله‌ی بعد.

---

## تصمیم‌های اولیه (۲ دقیقه — رئیس تصمیم می‌گیرد)

- [ ] **میزبانی کجا باشد؟**
  - گزینه‌ی A (توصیه‌شده): **VPS ابری** ~۴–۶ دلار در ماه (Hetzner / DigitalOcean). همیشه‌روشن، مستقل از کامپیوترت.
  - گزینه‌ی B: **کامپیوتر همیشه‌روشنِ خانه / رزبری‌پای**. رایگان، ولی اگر خاموش شود بات می‌خوابد.
- [ ] **شاخص اصلی همان RMSSD می‌ماند؟** (اصلِ LANGAR: شاخص قفل‌شده). اگر می‌خواهی عوضش کنی، در مرحله‌ی ۳ بگو.
- [ ] **زبان و سؤال‌های /log همین است یا تغییر می‌خواهی؟** (مرحله‌ی ۳).

---

## مرحله ۰ — فایل‌ها را روی کامپیوترت بیاور (👤 + 🤖)

هدف: پوشه‌ی `langar` با ۸ فایل، روی کامپیوتر خودت باشد و در دسترس Cowork.

- [ ] یک پوشه بساز، مثلاً `C:\Users\Armin\Documents\langar`
- [ ] در Cowork آن پوشه را وصل کن (Connect folder) و این پرامپت را بده:

```
این پوشه را برای پروژه‌ی LANGAR وصل کردم. فایل‌های بات تلگرام
(main.py, bot.py, db.py, requirements.txt, .env.example,
langar_bot.service, .gitignore, README.md) را داخلش بساز/کپی کن.
بعد محتوای هر فایل را یک‌بار برایم خلاصه کن تا مطمئن شوم کامل است.
```

**خروجی قابل‌تأیید:** ۸ فایل داخل پوشه دیده شوند.

---

## مرحله ۱ — ساخت بات تلگرام و گرفتن کلیدها (👤 دستی — ۳ دقیقه)

- [ ] در تلگرام به **@BotFather** برو → `/newbot` → یک نام و یک username (که به `bot` ختم شود) بده.
- [ ] **توکن** را کپی کن و جایی امن بگذار (شبیه `123456:ABC-...`).
- [ ] به **@userinfobot** پیام بده → عددِ `Id` خودت = **OWNER_ID** را بردار.

**خروجی قابل‌تأیید:** دو رشته داری: `BOT_TOKEN` و `OWNER_ID`.
> ⚠️ توکن رمز است. در چت عمومی، گیت، یا اسکرین‌شات نگذارش.

---

## مرحله ۲ — تست محلی روی کامپیوتر خودت (👤 + 🤖 — ۱۰ دقیقه)

اول مطمئن شو کد روی دستگاه خودت کار می‌کند، بعد برو سراغ سرور.

- [ ] فایل `.env` را بساز. این پرامپت را به 🤖 بده:

```
در پوشه‌ی langar یک فایل .env از روی .env.example بساز.
مقدار BOT_TOKEN را «<توکنت>» و OWNER_ID را «<آی‌دی‌ات>» بگذار.
بعد دستورهای دقیقِ ترمینال ویندوز را بده تا venv بسازم،
وابستگی‌ها را نصب کنم و python main.py را اجرا کنم.
اگر خطا دادم، متنش را می‌فرستم و تو دیباگ کن.
```

- [ ] دستورها را در ترمینال اجرا کن (venv → نصب → `python main.py`).
- [ ] در تلگرام به بات `/start` بزن.

- [ ] **تستِ kill-switch (حیاتی — رد نکن):**
  - `/halt` → باید بگوید «متوقف شد»
  - `/log` → باید **هیچ پاسخی ندهد**
  - `/resume` → باید بگوید «فعال شد»
  - `/log` → حالا باید کار کند
- [ ] **تستِ verdict برگشت‌ناپذیر:** یک `/insight` بساز، تگ بزن؛ فردا (یا با تغییر دستی تاریخ) `/recheck` → تأیید کن → دوباره داوری کن → باید بگوید «برگشت‌ناپذیر است».

**خروجی قابل‌تأیید:** بات روی کامپیوترت جواب می‌دهد و هر چهار تست سبز است.

---

## مرحله ۳ — کاستومایز (🤖 — هرچقدر خواستی)

حالا که کار می‌کند، شخصی‌اش کن. هر تغییری خواستی، یکی از این پرامپت‌ها را بده. **بعد از هر تغییر، دوباره مرحله‌ی ۲ را سریع تست کن.**

**سؤال‌های /log را عوض کن:**
```
در bot.py مرحله‌های ConversationHandler دستور /log را این‌طور تغییر بده:
[سؤال‌های جدیدت را اینجا بنویس — مثلاً اضافه‌کردن «کافئین؟» یا حذف «مکان»].
schema جدول log در db.py را هم متناسب به‌روزرسانی کن و مطمئن شو
مهاجرت دیتابیسِ موجود نمی‌شکند. بعد تست بنویس و اجرا کن.
```

**متن‌ها / لحن بات را عوض کن:**
```
همه‌ی پیام‌های بات در bot.py را به این لحن بازنویسی کن: [خشک/صمیمی/کوتاه].
محتوای منطقی را دست نزن، فقط متنِ reply_text ها را.
```

**زمان داوری بینش (recheck) را عوض کن:**
```
در bot.py الان recheck یک روز بعد تنظیم می‌شود. عوضش کن به [مثلاً ۳ روز بعد].
```

**یک شاخص دوم اضافه کن (با احتیاط — اصلِ «شاخص قفل‌شده» را بخوان):**
```
می‌خواهم کنار RMSSD یک شاخص دوم هم ثبت کنم: [نامش].
ولی در /trend هرگز این دو را مخلوط نکن؛ هر کدام جدا گزارش شود.
schema و /log و /trend را به‌روز کن و تست بنویس.
```

**خروجی قابل‌تأیید:** تغییر اعمال شده و تست‌های مرحله‌ی ۲ هنوز سبزند.

---

## مرحله ۴ — گرفتن سرور و انتقال کد (👤 + 🤖 — ۱۵ دقیقه)

> اگر گزینه‌ی B (کامپیوتر خانه) را انتخاب کردی، این مرحله را رد کن و مستقیم برو مرحله‌ی ۵ روی همان دستگاه.

- [ ] یک VPS بخر: **Hetzner CX11** یا **DigitalOcean Droplet**، سیستم‌عامل **Ubuntu 22.04**.
- [ ] IP و رمز/کلید SSH سرور را بردار.
- [ ] این پرامپت را به 🤖 بده:

```
یک VPS با Ubuntu 22.04 گرفتم. IP اش <IP> است.
قدم‌به‌قدم دستورهای دقیقِ ترمینال را بده تا:
۱) با SSH وصل شوم
۲) Python و venv نصب کنم
۳) پوشه‌ی langar را به /home/ubuntu/langar منتقل کنم (روش ساده‌ی بدون git هم بگو)
۴) .env را روی سرور بسازم و پر کنم
۵) با python main.py یک تستِ دستی بگیرم
هر جا خطا دادم متنش را می‌فرستم؛ دیباگ کن.
```

**خروجی قابل‌تأیید:** `python main.py` روی سرور بالا می‌آید و بات در تلگرام جواب می‌دهد. بعد `Ctrl+C`.

## مرحله ۵ — همیشه‌روشن‌کردن با systemd (👤 + 🤖 — ۵ دقیقه)

هدف: بات حتی بعد از ریستارت سرور خودکار بالا بیاید.

- [ ] این پرامپت را به 🤖 بده:

```
می‌خواهم بات با systemd همیشه‌روشن شود. فایل langar_bot.service را
طبق مسیر و کاربر واقعی سرورم تنظیم کن، و دستورهای دقیق را بده تا:
copy به /etc/systemd/system/، daemon-reload، enable، start، و status.
بعد بگو چطور لاگ زنده را با journalctl ببینم.
```

- [ ] دستورها را اجرا کن؛ خروجی `systemctl status langar_bot` باید **active (running)** باشد.
- [ ] سرور را یک‌بار `reboot` کن و بعد از بالا آمدن، در تلگرام `/status` بزن — باید جواب بدهد.

**خروجی قابل‌تأیید:** بعد از reboot، بات بدون دخالت تو بالاست.

---

## مرحله ۶ — تستِ دنیای واقعی (👤 — چند روز)

- [ ] چند روز پشت‌سرِ هم صبح `/log` بزن (حداقل ۳ روز تا /trend معنا پیدا کند).
- [ ] `/trend` را امتحان کن؛ همبستگی‌ها را ببین (یادت باشد: همبستگی ≠ علیت).
- [ ] `/insight` و فردا `/recheck` را در چرخه‌ی واقعی تجربه کن.
- [ ] `/export` بگیر تا از داده‌هایت نسخه‌ی پشتیبان داشته باشی.
- [ ] هر اشکالِ تجربه‌ی کاربری را یادداشت کن → برگرد مرحله‌ی ۳.

**خروجی قابل‌تأیید:** بعد از ۱۴ روز یک ترندِ واقعی داری.

## مرحله ۷ — فاز بعدی: اتوماسیون بیشتر (🤖 — اختیاری، وقتی واقعاً خواستی)

```
به بات LANGAR یک پینگ صبحگاهی خودکار اضافه کن: هر روز ساعت <۸ صبح>
به وقت <منطقه‌ی زمانی‌ام> پیام بدهد و یادآوری کند /log بزنم.
از JobQueue کتابخانه‌ی python-telegram-bot استفاده کن
(نصب: python-telegram-bot[job-queue])، و حتماً قاعده‌ی gate را رعایت کن:
اگر halted بود، پینگ هم نباید بفرستد. بعد تست بنویس.
```

ایده‌های بعدی: مرور هفتگیِ خودکار · ثبت RMSSD مستقیم از اپلیکیشن سلامت با Apple Shortcut → HTTP.

## قواعد طلایی (رئیس این‌ها را نگه می‌دارد)

1. **هیچ مرحله‌ای بدون «خروجی قابل‌تأیید» تمام‌شده حساب نمی‌شود.**
2. **توکن هرگز در چت عمومی یا گیت نرود.** فقط در `.env` روی دستگاه خودت/سرور.
3. **بعد از هر کاستومایز، تستِ kill-switch را دوباره بگیر.** این مهم‌ترین گاردریل است.
4. **اول محلی، بعد سرور.** هرگز اول روی سرور دیباگ نکن.
5. **از داده‌ها `/export` بگیر** قبل از هر تغییرِ بزرگِ schema.
