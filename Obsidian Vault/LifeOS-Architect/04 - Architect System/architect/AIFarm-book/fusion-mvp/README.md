# Fusion MVP — دستیار تحقیقاتی چندعاملی با کنترل انسانی

پیاده‌سازی فاز ۱ چک‌لیست فیوژن ۲۰۲۶: یک سیستم چندعاملیِ کوچک اما واقعی که
انسان می‌تواند آن را اجرا، تست و **هر لحظه متوقف** کند.

سه ایجنت با نقش‌های تفکیک‌شده:
**Researcher** (جمع‌آوری) → **Analyst** (تحلیل) → **Supervisor** (داوری) → **انسان** (تأیید نهایی).

## اصول رعایت‌شده
- قدرت پخش است؛ هیچ ایجنتی کنترل کامل ندارد (تفکیک نقش + ابزار scoped).
- انسان همیشه در حلقه است (HITL gate قبل از نهایی‌سازی).
- شفافیت کامل: هر اقدام در audit log و روی کنسول.
- توقف فوری: kill-switch نرم‌افزاری + فایل `logs/STOP`.
- هزینه محدود: سقف بودجه per-agent و کل + قطع خودکار.

نگاشت کامل ۷ مورد چک‌لیست → `CHECKLIST.md`.

## اجرا

```bash
# ۱) (اختیاری) کلید واقعی Claude؛ بدون آن، حالت MOCK بدون هزینه اجرا می‌شود
cp .env.example .env        # و ANTHROPIC_API_KEY را بگذار

# ۲) اجرا
python run.py "موضوع تحقیق تو"            # تأیید انسانی تعاملی روی کنسول
python run.py "موضوع" --auto-approve      # تأیید خودکار (برای تست)
python run.py "موضوع" --auto-reject       # رد خودکار انسان (تست مسیر توقف)
```

برای کار با مدل واقعی: `pip install -r requirements.txt` و کلید را در `.env` بگذار.
بدون کلید، سیستم خودکار به حالت MOCK می‌رود (لایه‌ی کنترل کامل کار می‌کند، فقط متن مدل ساختگی است).

## کلید قطع فوری (kill-switch)
وسط اجرا، در ترمینال دیگری:
```bash
touch logs/STOP        # سیستم در گام بعدی آنی متوقف می‌شود
```

## تست
```bash
python run_tests.py          # رانر سبک، بدون نیاز به نصب (۹ تست)
# یا اگر pytest داری:
python -m pytest -q
```

## سناریوهای تست‌شده (واقعی)
1. **مسیر کامل موفق** — `--auto-approve` → جستجو، تحلیل، تأیید ناظر، تأیید انسان، نهایی‌سازی. صحت audit log تأیید شد.
2. **رد انسانی** — `--auto-reject` → سیستم در دروازه‌ی HITL متوقف می‌شود (انسان بالاتر از ایجنت).
3. **kill-switch بیرونی** — فایل `logs/STOP` → توقف آنی با هزینه‌ی صفر.
4. **عبور از بودجه** — سقف کوچک → `BudgetExceeded` و قطع خودکار.
5. **least-privilege** — Analyst نمی‌تواند ابزار جستجو را صدا بزند → `ToolPermissionError`.

## فاز ۲ — شفافیت و کنترل (انجام‌شده)
**داشبورد محلی هزینه/فعالیت** (بدون هیچ وابستگی):
```bash
python dashboard.py        # dashboard.html را می‌سازد و در مرورگر باز می‌کند
```
نشان می‌دهد: هزینه‌ی هر ایجنت، خط‌زمانیِ کارها، وضعیت هر اجرا، و صحت زنجیره‌ی audit.
(اول چند بار `run.py` را اجرا کن تا داده ساخته شود.)

**Langfuse (اختیاری، ابزار رصد ابری ۲۰۲۶):** اگر کلیدها را در `.env` بگذاری
(`LANGFUSE_PUBLIC_KEY`/`LANGFUSE_SECRET_KEY`)، رویدادها به داشبورد ابری هم می‌روند.
بدون کلید، بی‌صدا غیرفعال می‌ماند و فقط داشبورد محلی کار می‌کند. برای فعال‌سازی:
`pip install langfuse` و کلیدها را از حساب رایگان Langfuse بردار.

## فاز ۳ — آزمون‌پذیری و سیستم خوداپدیتی (انجام‌شده)
**سیستم خوداپدیتیِ پرامپت** (اعمال خودکار + rollback خودکار، مطابق فیوژن):
```bash
python self_update.py researcher        # پرامپت researcher را خودکار بهتر می‌کند
python self_update.py --show researcher  # تاریخچه‌ی نسخه‌ها
python self_update.py --rollback researcher  # یک نسخه به عقب (دستی)
```
Optimizer نسخه‌ی بهترِ پرامپت را پیشنهاد و **خودکار اعمال** می‌کند، اما سه محافظ:
1. فقط اگر نمره‌ی eval بالاتر برود نگه می‌دارد؛ وگرنه **rollback خودکار**.
2. **گاردریل امنیتی**: پرامپتی که نقش را حذف کند یا injection باشد رد می‌شود.
3. **kill-switch** + سقف دور + تاریخچه‌ی کامل نسخه‌ها (در `prompts.json`).

تغییراتِ تأییدشده ماندگارند: دفعه‌ی بعد که `run.py` اجرا شود، ایجنت‌ها پرامپتِ بهبودیافته را استفاده می‌کنند.

**تست فاز ۳:**
```bash
python test_phase3.py        # ۵ تست: eval، گاردریل پرامپت، سناریوی شکست، rollback
```

## فاز ۴ — پنل چندداور (مورد ۵، انجام‌شده)
تصمیمِ تأیید دیگر دست یک ناظر نیست: یک **پنل سه‌داورِ مستقل** (strict/lenient/balanced)
رأی می‌دهند و تأیید نیازمند حد نصاب (۲ از ۳) است. هیچ داوری به‌تنهایی تصمیم نمی‌گیرد،
و اگر آرا نصفه‌نیمه شود به انسان ارجاع می‌شود. داوران بین providerها پخش می‌شوند
(`src/providers.py` آماده‌ی چند مدل واقعی است). در اجرای عادی خودکار فعال است:
```bash
python run.py "موضوع" --auto-approve     # خط «🧑‍⚖️ پنل: X/3 رأی» را می‌بینی
```
