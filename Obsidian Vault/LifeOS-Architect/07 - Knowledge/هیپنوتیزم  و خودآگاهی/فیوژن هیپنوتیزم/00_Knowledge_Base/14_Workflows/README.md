# 14_Workflows — گردش‌کارهایِ تکرارشونده

## آیتمِ ۱ — CI/CD Gated (SERVER_ARCHITECTURE.md, اول‌دست)
`push به main → test → gitleaks(secret scan) → build(docker) → push(GHCR) → trigger deploy → health-check → اگر ناسالم: rollback خودکار + alert تلگرام`. اصلِ حاکم: «کاملاً اتوماتیک ولی gated» — بدونِ کلیکِ دستی، اما کدِ خراب هرگز live نمی‌ماند.
**اولویت:** بالا (زیرساختِ همه‌یِ پروژه‌هایِ دیگر). **اطمینان:** بالا.

## آیتمِ ۲ — HITL (Human-In-The-Loop) قبل از Finalize (fusion-mvp, دایجست)
جریان: researcher→analyst→guardrail→panel(۳داور)→grounding→**HITL**→finalize. LeadAgent هم همین قاعده را دارد: «finalize فقط با HITL و حکمِ grounding باید در پرامپت تأییدِ انسان نمایش داده شود» — یکی از سه گیتِ غیرقابلِ‌دورزدنِ آن.
**اتصال:** 🔗 نمونه‌یِ دیگری از Risk-Governance (`Frameworks.md` §۳).

## آیتمِ ۳ — حلقه‌یِ روزانه‌یِ Neuro-HRV (اول‌دست)
صبح (baseline، ۲ دقیقه) → بلافاصله (تنفسِ رزونانس ۵/۵، ۱۰-۱۵د) → حینِ روز (sigh on-demand) → هفتگی (مرورِ ترند). این یک گردش‌کارِ فیزیولوژیک-رفتاری است، نه نرم‌افزاری، اما همان منطقِ «چرخه‌یِ منظم + مرورِ دوره‌ای» را دارد.

## آیتمِ ۴ — چرخه‌یِ Silabi-Bot (اول‌دست)
ثبتِ لحظه‌ای (چند ثانیه) → `/today` روزانه → `/mirror`+`/learned` هفتگی → بازنگریِ مشترک با Claude هر چند هفته (فازِ ۳ در roadmap) → ارتقایِ کد بر اساسِ داده‌یِ واقعی. **گیت‌کیپینگِ صریح:** فازِ N+1 شروع نمی‌شود تا فازِ N با داده‌یِ واقعی تأیید شود (roadmap دقیقاً این را می‌گوید: فازِ ۴ فقط بعد از فازِ ۳).

## آیتمِ ۵ — حلقه‌یِ بیزیِ Rung 0→1→2 (Fusion-World)
`prior بنویس → ارزان‌ترین آزمونِ تمایزدهنده را بزن → posterior حساب کن → فقط اگر از آستانه رد شد escalate کن`. قاعده‌یِ سخت: آستانه هرگز وسطِ راه جابه‌جا نمی‌شود.

## الگویِ مشترکِ همه‌یِ این گردش‌کارها

هرکدام یک **گیتِ عدم‌پیشرفت** دارند: کدِ ناسالم rollback می‌شود، ایجنت بدونِ تأییدِ انسان finalize نمی‌کند، فازِ روباتِ شخصی بدونِ داده جلو نمی‌رود، و آستانه‌یِ فیزیک قبل از دیدنِ داده قفل می‌شود. 🔗 [واقعی، ساختاری] — این پنجمین جایی است که همین الگو (تصمیمِ ازپیش‌قفل‌شده + گیتِ پیشروی) در این پایگاه‌دانش ظاهر می‌شود، تقویت‌کننده‌یِ یالِ ۲ در `KnowledgeGraph.md`.
