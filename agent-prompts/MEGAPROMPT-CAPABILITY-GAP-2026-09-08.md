## ۰ — تشخیص صادقانه: پنج دلیل ریشه‌ای

**۱. مغز.** qwen-0.6b روی برد ۱۸۰ ثابت شده که:
- استخراج ساده: ۳۳% pasŝ⁵
- روی خروجی خراب: ۵۴% جعل
- تودرتو: ۰%
- هرگز ABSTAIN نمی‌کند

**۲. چرخهٔ قفل.** مدل ضعیف → نمی‌تواند کار واقعی انجام دهد → پول نمی‌آید → مدل بهتر نمی‌خریم → مدل ضعیف می‌ماند. این چرخه را چیزی جز پولِ بیرونی یا تصمیمِ مدل نمی‌شکند.

**۳. تئاتر زیرساخت.** ما ۵۲۷۳ رویداد «task.completed» داریم ولی صفر دلار درآمد. ارگانیسم «مشغول» است ولی «مولد» نیست. داشبورد، مینی‌اپ، کنترل‌پنل، spine، gate، router — همه کار می‌کنند ولی هیچ‌کدام پول نمی‌سازند.

**۴. سه‌نقشی ناتمام.** هدایت‌گر/اجراکننده/ارزیاب پذیرفته شد ولی پیاده نشد. الان یک مغز ضعیف همه کارها را می‌کند — همان چیزی که ACD اثبات کرد غلط است.

**۵. زمان.** standing GO تا ۰۹-۱۴ فعال است (۶ روز). msg38 امروز ظهر ددلاین دارد. بدون اقدام، هر دو می‌گذرند.

## ۲ — کارهای ایجنت (بدون رأی مالک)

### G-1: پیاده‌سازی سه‌نقشی واقعی

الان سه نقش «منطقی»‌اند نه واقعی. تبدیلشان کن:

```python
# Director: انتخاب کار، تخصیص، بازبینی
# → اینجا مغز استفاده می‌شود (فهم/انتخاب/اولویت‌بندی)

# Executor: اجرای کد، استخراج، اعتبارسنجی
# → اینجا کد قطعی استفاده می‌شود (capability_router مسیر را تعیین می‌کند)

# Evaluator: خواندن نتیجه، مقایسه با انتظار، ثبت تجربه
# → ترکیب: کد برای read-back قطعی، مغز برای تفسیر
```

شرط قبولی G-1: یک مأموریت واقعی (نه تست) که از هر سه نقل عبور کند:
- Director یک کار انتخاب کند (با مغز)
- Executor انجام دهد (با کد)
- Evaluator نتیجه را ببیند (با کد) و به Director برگرداند

### G-2: اولین مأموریت درآمدزا

نه infrastructure، نه governance، نه ACD. یک کار که **پول بسازد**:
- زیمان: یک محصول را آمادهٔ فروش کن (قفسه هست، قیمت هست، مسیر پول = PayPal Invoice)
- نقاشی: یک lead را qualify کن و برای ارسال آماده کن (مجوز top-5 داری)
- هر دو: `checkout1_poll.py` را وینداز کن (الان Linux path هاردکد دارد)

شرط قبولی G-2: `VERIFIED_CASH > 0` یا حداقل یک ارسال واقعی با رسید.

### G-3: تست سه‌نقشی با مأموریت واقعی

```
مأموریت: "بررسی کن که محصول ZM-GALLERY-0013 هنوز در قفسه هست و قیمتش درست است"
  ↓ Director (مغز): تسک را بفهم، ابزار لازم را انتخاب کن
  ↓ Executor (کد): API بزن، قیمت را بخوان، اعتبارسنج کن
  ↓ Evaluator (کد): نتیجه را با انتظار مقایسه کن، ثبت کن
  ↓ Director: نتیجه را تفسیر کن و بگو "بله/نه/نامشخص"
```

این یک مأموریت ساده است ولی **کل زنجیره** را تست می‌کند.
