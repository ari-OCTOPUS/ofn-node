# 🚀 اجرای خودمختارِ یک‌ماهه — «جسور ولی محافظت‌شده»

این راهنمای اجرای بی‌مراقبِ یک‌ماهه است (تصمیمِ مالک: پرریسک‌تر، سقفِ پولی، روزی
۲–۳ پیام، بعد نتایج را بسنجیم).

## چه چیزی روشن شد
- **خودتغییریِ کد (.py):** سیستم بهبودِ کد را **پیشنهاد** و **آزمون** می‌کند؛ هیچ‌چیز
  به کدِ زنده نمی‌رسد مگر پس از سبزشدنِ **کلِ سوییتِ تست** و **تأییدِ تو** در داشبورد.
- **سقفِ بودجه:** ~۱۰۰۰ تماسِ ابری در روز؛ بعد از آن خودکار به Ollamaی محلیِ رایگان می‌رود.
- **کم‌نویز:** پیام‌ها در یک digest دسته می‌شوند، حداکثر ۳ بار در روز.
- **بی‌مراقب:** یک daemonِ headless (مستقلِ مرورگر) که یک ماه می‌چرخد.

## ۱) تنظیم (در `.env`)
```dotenv
SELF_CODE_ENABLED=1        # اجازه‌ی پیشنهادِ تغییرِ کد (پیش‌فرض خاموش)
LLM_DAILY_CALL_CAP=1000    # سقفِ تماسِ ابری در روز
NOTIFY_MAX_PER_DAY=3       # حداکثر digest در روز
DAEMON_TICK_SECONDS=30     # فاصله‌ی هر گام
# (اختیاری) TELEGRAM_BOT_TOKEN / TELEGRAM_CHAT_ID برای پیام به گوشی — ن.ک. TELEGRAM_SETUP.md
```

## ۲) شروعِ اجرای بی‌مراقب
```bash
python -m brain.daemon
```
یک ترمینال باز بماند (یا با Task Scheduler ویندوز در پس‌زمینه). داشبورد را هم می‌توانی
هم‌زمان باز کنی تا وضعیت را ببینی (`streamlit run run.py`) ولی برای اجرا لازم نیست.

## ۳) در طولِ ماه
- **تأییدِ پیشنهادهای کد:** داشبورد → پنلِ «🧩 خودتغییریِ کد». هر پیشنهاد را ببین
  (کدِ کامل + نتیجه‌ی تست)، بعد **✅ تأیید** یا **❌ رد**. تا تأیید نکنی، کدِ زنده عوض نمی‌شود.
- هر تغییرِ اعمال‌شده یک بکاپِ `<file>.selfcode.bak` دارد؛ در داشبورد قابلِ بازگردانی.
- پیام‌ها (خلاصه/هشدار/درخواستِ تأیید) در تلگرام یا صفِ محلی (`outputs/decision_packets.jsonl`).

## ۴) توقف
- فایلِ توقف: `touch outputs/daemon.stop` (یا `New-Item outputs/daemon.stop`)
- یا `Ctrl+C` در ترمینالِ daemon.
- توقفِ حفاظتیِ خودکار: اگر لنگرِ ریاضی نقض شود، daemon خودش می‌ایستد و پیام می‌دهد.

## ۵) سنجشِ نتایج (پایانِ ماه)
```bash
python -m brain.evaluation      # چاپِ گزارش
```
یا در پایتون: `from brain import evaluation; evaluation.save_report()` →
`outputs/self_evolved/monthly_report.md`. گزارش شامل: مدتِ اجرا، پوششِ مرزِ دانش،
نسلِ تحول، پیشنهادهای کد و سرنوشتشان، مصرفِ بودجه، شمارِ پیام‌ها، رویدادها، و
نتیجه‌گیریِ ریاضیِ SOG.

## 🛡️ مدلِ ایمنی (پس از بازبینیِ خصمانه — صادقانه)
یک بازبینیِ خصمانه‌ی ۴۴-ایجنتی این سیستم را حمله کرد و چند رخنه‌ی واقعی پیدا کرد که
همه رفع شدند. مدلِ نهایی:

- **daemonِ بی‌مراقب هرگز کدِ پیشنهادی را اجرا نمی‌کند** — فقط تحلیلِ **ایستا**
  (AST + نحو + TCB) و صف‌کردن. یعنی کدِ نامطمئن بی‌حضورِ تو اجرا نمی‌شود.
- **کد فقط موقعِ approveِ تو اجرا می‌شود**، آن هم: در کپیِ throwaway، با env
  **پاک‌سازی‌شده** (بدونِ کلید/توکن → نشتِ راز بسته)، با **تشخیصِ دستکاری**: اگر اجرا
  هر فایلِ زنده‌ای را دستکاری کند (فرارِ مسیرِ مطلق) → کلِ درخت بازگردانی و پیشنهاد رد
  می‌شود. فقط اگر سالم و سبز بود، با نوشتنِ متنیِ ساده اعمال می‌شود.
- **هسته‌ی موردِاعتماد (TCB) هرگز هدف نمی‌شود:** `core/`, `tests/`, کلِ `config/`،
  **هر `__init__.py`** (در import اجرا می‌شود)، گاردها، `budget`, `router`, کلاینت‌ها،
  `langchain_models`, `automation`, `daemon`, `telegram_bot`, `run.py`, `4D/`. گیتِ TCB
  در برابرِ rebindِ درون‌فرایندی مقاوم است.
- **اسکنِ AST** (نه فقط substring): importِ شبکه‌ای/پویا، eval/exec، open-write،
  os.system، reflection — الگوهای خطرناکِ **تازه** را رد می‌کند.
- **سقفِ هزینه:** همه‌ی مسیرهای ابری (httpx + langchain) زیرِ سقفِ روزانه؛ حلقه‌ی
  بازتاب سقفِ سختِ بی‌قیدوشرط دارد.

> ⚠️ **صداقتِ کامل:** بدونِ sandboxِ سیستم‌عامل (container/VM)، اجرای کدِ خودنوشته را
> نمی‌توان کاملاً مهار کرد — کدِ **تأییدشده** با اختیارِ کاملِ فرایند اجرا می‌شود.
> دفاع‌های بالا ریسکِ **خودکار/تصادفی** را به‌شدت کم می‌کنند، ولی مرزِ نهایی **تأییدِ
> آگاهانه‌ی توست: کدِ کاملِ هر پیشنهاد را در داشبورد/تلگرام ببین**؛ «سبزشدنِ اسکن» =
> بی‌خطر نیست. اگر این ریسک را نمی‌خواهی، `SELF_CODE_ENABLED=0` بگذار (پیش‌فرض) —
> سیستم فقط بهبود را **پیشنهاد** می‌دهد و تو/من دستی اعمال می‌کنیم.
