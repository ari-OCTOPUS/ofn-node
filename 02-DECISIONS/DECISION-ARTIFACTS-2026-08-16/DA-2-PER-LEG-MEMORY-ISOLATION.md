# DA-2 — جداسازی حافظه به‌ازای هر پا

**مسئله:** حافظهٔ اشتراکی L4 بدون مرزِ پا: یک پای آلوده شواهدِ همه را آلوده می‌کند. T1 نشان داد حافظه «موطوراً خوانده می‌شود» — یعنی مسمومیت حالا **پرخط‌تر** است، نه کم‌خط‌تر (دقیقاً ارزیابی V3 تصحیح‌شده). ریشهٔ مشترک با C-013/C-014: نبود خودمدلِ ماشین‌خوان از مالکیتِ حافظه.

**پیشنهاد (سه پله، بدون بازنویسیِ موتور حافظه):**

1. **Namespace به‌ازای پا** (پایه): کلیدِ `leg=<id>` در همهٔ مخازن (SQLite/JSONL/Chroma) الزامی؛ نوشتنِ بین‌پا فقط از مسیرِ `promotion` با بازبینی. هزینه: ~۲ روز.
2. **ACL + سهمیه**: هر پا فقط ناحیهٔ خودش را می‌نویسد؛ سهمیهٔ نوشتن/خواندن جدا (مسمومیتِ حجمی را هم می‌بندد). هزینه: ~۲ روز روی هر مخزن.
3. **Provenance-domain + برچسبِ آلودگی**: هر ردیف، دامنهٔ منشأ + taint label؛ ارتقای بین‌پا فقط با بازبینیِ مستقل (به DA-1 گره می‌خورد). هزینه: ۳-۵ روز.

**چرا نسخهٔ کامل به manifest ارگانیسم گره خورده:** بدون manifest (R13 سطح بعد)، «پا» و «مرزش» تعریفِ معتبر ندارد — C-013 همان درس برای کد بود؛ برای حافظه تکرار می‌شود.

**توصیه:** پلهٔ ۱+۲ در فاز بعدِ نزدیک؛ پلهٔ ۳ همراه ارزیاب مستقل. **فعال‌سازیِ R29 (4d live) بدون پلهٔ ۱ ممنوع بماند** (نردبان شورا: نیازمند memory isolation).

**پذیرش:** تست منفی: پای A نتواند ردیفِ پای B را بنویسد (رفضِ سخت، نه هشدار)؛ مسموم‌کردنِ عمدیِ پای A در هلدِ ۳۰روزه، نتیجهٔ پای B را تغییر ندهد؛ گزارشِ provenance برای هر ردیفِ ارتقایافته وجود داشته باشد.
