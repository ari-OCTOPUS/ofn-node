# RFC — پل دادهٔ HRV برای E3 (Propose-only)

> **وضعیت: پیشنهاد (draft). هیچ اجرایی صورت نگرفته و هیچ دسترسی واقعی به داده گرفته نشده.** این RFC فقط طرح است و پشت Security Gate + verdict آری قفل می‌ماند.

## ۱. هدف

آزمون E3: «آیا رخداد استرس در دادهٔ HRV قابل‌تشخیص است؟» (رد می‌شود اگر هیچ رخدادی دیده نشود). این RFC مسیرِ ممکنِ استفاده از دادهٔ HRV موجود را پیشنهاد می‌کند، بدون هیچ لمسِ واقعیِ داده.

## ۲. قیدهای غیرقابل‌مذاکره

- **فقط مسیر/اندازه/نوع.** هیچ محتوای HRV، هیچ PII، هیچ رکورد خام در چت/نوت/لاگ echo نمی‌شود.
- طبق قید موجود O-04 حوزهٔ هیپنوتیزم: دادهٔ HRV **فقط روی لپ‌تاپ** می‌ماند و به VPS/بیرون نمی‌رود.
- بدون auto-execute · بدون run هیچ اسکریپت · بدون نوشتن روی دادهٔ منبع.
- Security Gate مقدم است: تا باز شدن ۴ CRITICAL secret، این RFC اجرا نمی‌شود (`autonomy_level: read-only`).

## ۳. طرح پیشنهادی (در صورت verdict و باز شدن گیت)

1. **Inventory فقط‌متادیتا:** ثبت مسیر/اندازه/فرمتِ فایل‌های HRV موجود (مثلاً منبع در حوزهٔ هیپنوتیزم، `Marathon/` یا `Neuro-HRV`) — بدون باز کردن محتوا.
2. **تعریف رخداد:** پیش از هر تحلیل، تعریف عملیاتیِ «رخداد استرس» و آستانه‌ها به‌صورت pre-registered نوشته شود.
3. **تحلیل محلی:** هر پردازش فقط روی لپ‌تاپ، خروجی فقط aggregate/آماری (نه رکورد خام).
4. **گزارش:** فقط نتیجهٔ رد/تأییدِ E3 + آمار تجمیعی به area برگردد.

## ۴. ریسک و تخفیف

| ریسک | تخفیف |
|---|---|
| نشت PII در نوت/چت | فقط متادیتا؛ hook منع secret؛ بازبینی خروجی پیش از ثبت |
| خروج داده از لپ‌تاپ | O-04؛ پردازش محلی؛ بدون sync به VPS |
| اجرای زودهنگام | قفل پشت Security Gate + verdict آری |
