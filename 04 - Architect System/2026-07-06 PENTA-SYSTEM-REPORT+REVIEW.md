# گزارشِ کامل + بازنگری — سیستمِ GOVERNOR + MUSE (پنج‌گانه)

> **وضعیتِ یک‌خطی:** کلِ کار **propose-only** است — **صفر** تغییرِ عملیاتی، صفر ویرایشِ ژنوم/کد، صفر نصب. شش سندِ پیشنهادی ساخته شد؛ اجرا فقط با verdictِ صریحِ آری و به ترتیبِ §۴.

---

## ۰. چه خواستی، چه شد
از «تطبیقِ تحقیق با ژنوم» شروع شد، رسید به طراحیِ دو ایجنتِ جدید در قالبِ یک **پرامپتِ پنج‌گانه**، و حالا کامل + بازنگری‌شده. همه‌چیز زیرِ قانونِ موجودت نشست: propose→approve، read-only، whitelist، ledger، kill-switch، بودجه.

## ۲. سیستم در یک نگاه
```
                          👤 آری (تنها امضای نهایی — verdict)
                                   ▲ propose-only
        ┌──────────────────────────┼───────────────────────────┐
        │                          │                            │
   [GOVERNOR]                 [دکترِ تکاملی]                [learning-loop]
   همیشه‌روشن                  انتخاب (forward)              خودجهشِ محدود
   uptime·دکتر·                     ▲                        (whitelist·۱/روز)
   genome-diff·routing              │ فقط بازمانده‌ها
        │                     [MUSE — جعبه‌سیاه]
        │ می‌خواند/گزارش          read-only همه‌جا
        ▼                     ایده با «ترسِ بی‌نهایت»
   ┌─────────────────────────────────────────────────────────────┐
   │  GENOME (charter·contract·whitelist·rubricِ دکتر) — immutable │  ◄ read-only فنی (فاز ۵)
   ├─────────────────────────────────────────────────────────────┤
   │  MEMORY: ledgerهای append-only + STATE + vault + git         │
   │  BACKUP: off-box رمزنگاری‌شده + restore-drill (BACKLOG-10)     │
   │  INTERLOCKS: STOP · بودجهٔ مشترک · خطِ فاجعهٔ $500             │
   └─────────────────────────────────────────────────────────────┘
```
MUSE تنوع می‌سازد → دکترِ تکاملی غربال می‌کند → آری امضا → ledger وراثت. GOVERNOR کل را زنده نگه می‌دارد. حلقهٔ تکاملی، با ایمنیِ انسانی.

## ۳. بازنگریِ Adversarial (صادقانه — ۸ یافته)
| # | یافته (ضعف/ریسک) | شدت | مهار (در طراحی) |
|---|---|---|---|
| R1 | **دو حلقهٔ پیشنهاد موازی:** MUSE→دکتر و learning-loop هر دو «پیشنهاد» می‌دهند → تداخل/دوبار‌خرجی | متوسط | مرزِ صریح: learning-loop = خودجهشِ *پرامپت خودش* (whitelist)؛ MUSE = ایدهٔ *cross-project*. هر دو در یک قیفِ verdict. **باید در فاز ۱ منشور تصریح شود.** |
| R2 | **یکپارچگیِ خودِ دکترِ تکاملی:** اگر آستانه/rubric شل شود، غربال بی‌اثر می‌شود | **بالا** | rubric+آستانه+گیتِ سخت = **genome/immutable**؛ هیچ حلقه‌ای شل‌شان نمی‌کند (فاز ۵ §۴). |
| R3 | **ایزولاسیونِ نرم تا پیش از پروسهٔ مستقل:** الان read-only فقط prompt-enforce است، نه OS | **بالا** | interim = صفر write-path + چکِ genome/project-diff دکتر؛ سختِ OS-level فقط با پروسهٔ مستقل (فاز ۵). **تا آن‌موقع تضمین ضعیف‌تر است — صادقانه.** |
| R4 | **جهشِ «همیشه‌روشن»:** رفتن از interactive به پروسهٔ مستقل = بیشترین ریسک | **بالا** | shadow-first در پایلوتِ ۳۰روزه؛ live فقط با verdict بعد از پایلوت (فاز ۵ §۳). |
| R5 | **بودجهٔ مرکب:** ۴ مصرف‌کننده هرکدام زیرِ سقف ولی جمعشان بالا | متوسط | **شمارندهٔ بودجهٔ مشترکِ تک‌منبع**، نه per-agent (فاز ۵ §۴). |
| R6 | **حریمِ Project-F در قرنطینه:** MUSE از پروژهٔ حساس می‌خواند؛ ایده‌های مشتق در ledger می‌مانند | متوسط | فقط کدِ «Project-F» در متن (منشور §۶)؛ قرنطینه laptop-only، هرگز VPS. |
| R7 | **تک‌نقطهٔ تأیید (آری):** در نبودِ آری، سیستم فقط منتظر می‌ماند (بی‌autonomy) | پایین (طراحی‌شده) | fail-closed = DENY؛ امنیت بر سرعت مقدم (منشور D-13). ترید‌آفِ پذیرفته‌شده. |
| R8 | **وابستگیِ بک‌اپ:** بدونِ off-box، از‌دست‌رفتنِ دیسک = نابودیِ ledger (وراثت) | **بالا** | **بک‌اپ باید اولِ همه اجرا شود** — پیش از هر always-on (نقشهٔ §۴). |

**جمع‌بندیِ بازنگری:** طراحی از نظرِ *ایمنی* محکم است (همه propose-only، evaluator منجمد، fail-closed)، ولی سه ریسکِ «بالا» (R2/R3/R4/R8) همگی به یک چیز اشاره می‌کنند: **قدرتِ واقعی وقتی می‌آید که سیستم مستقل و همیشه‌روشن شود — و دقیقاً همان‌جا باید محتاط‌ترین بود.** پس ترتیبِ ساخت (§۴) خودش بخشی از ایمنی است.

## ۴. نقشهٔ ساخت (وابستگی‌محور — این ترتیب مهم است)
1. **بک‌اپِ off-box + restore-drill** (R8) — *قبل از هر چیزِ همیشه‌روشن.*
2. **read-only فنیِ ژنوم + چکِ genome-diff دکتر** (R2/R3).
3. **GOVERNOR در shadow** با NSSM (R4) — فقط نظارت/گزارش، بی‌اعمال.
4. **MUSE + دکترِ تکاملی در dry-run** — قرنطینه پر می‌شود، هیچ‌چی forward نمی‌شود تا کالیبره شود.
5. **شمارندهٔ بودجهٔ مشترک** (R5) فعال.
6. **پایلوتِ ۳۰روزهٔ shadow → verdictِ live.** لاین‌های پرفرکانس تا آن‌موقع dark.

## ۵. verdictهای بازِ تجمیع‌شده (فقط آری)
- **#۴ مدل/بودجه:** ✅ تأییدشده («بله اجرا کن»).
- **دریفت‌های تطبیق (سندِ ۱):** D1 (mode قرارداد)، D2 (گیتِ STATE=OPEN در برابر منشورِ LIFTED)، D3 (تک‌whitelist) — هنوز منتظرِ verdict.
- **R1:** تصریحِ مرزِ MUSE در برابر learning-loop در منشورِ فاز ۱ — تأیید می‌کنی؟
- **ترتیبِ §۴:** موافقی «بک‌اپ اول»؟
- **پیست:** بلوکِ منشورِ فاز ۱ را خودت در `ARCHITECT_CHARTER` می‌گذاری (فقط دستِ تو).

## ۷. خطِ آخر (صادقانه)
- **قوت‌ها:** ژنومِ تو از قبل محافظه‌کار و درست بود؛ این طراحی چیزی را شل نکرد — فقط دو کارمندِ جدید (یک سرپرستِ ۲۴ساعته + یک مغزِ خلاقِ قرنطینه‌ای) و یک حلقهٔ انتخاب اضافه کرد، همه پشتِ امضای تو.
- **ریسکِ باقی‌مانده:** تا وقتی سیستم مستقل/همیشه‌روشن نشده، ایزولاسیون نرم است (R3) و قدرت هم کم؛ لحظهٔ روشن‌شدنِ همیشه‌روشن، هم‌زمان لحظهٔ اوجِ ریسک است.
- **اولین کارِ درست:** **بک‌اپِ off-box.** بدونِ آن، هیچ‌چیزِ دیگری نباید همیشه‌روشن شود.
