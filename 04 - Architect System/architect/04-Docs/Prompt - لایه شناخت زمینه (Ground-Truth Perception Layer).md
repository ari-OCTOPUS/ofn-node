# پرامپت اهداف — «لایهٔ شناختِ زمینه» (Ground-Truth Perception Layer)

> **فقط پرامپت است؛ هیچ‌چیزی ساخته یا اجرا نشده.** گام بعدیِ مصوبِ verdict آری (2026-07-05) پس از سند اهداف دکتر تکاملی.
> این لایه **پیش‌نیاز ستون ۱** دکتر است: قبل از اینکه دکتر «فکر» کند، باید نقشهٔ درست داشته باشد.

## ۱. مسئله

ممیزیِ ۲۰۲۶-۰۷-۰۵ ثابت کرد اسناد vault (رجیستری، HANDOFF، HEARTBEAT) با واقعیت drift دارند: زمان‌بندِ زنده ~۴۰ تسک enabled دارد ولی رجیستری «۶» می‌گوید؛ ناوگان Research Radar مستند نیست؛ ۳ فایل `.env` زنده و ~۶۰MB PII از چشم دکترِ md-محور جا مانده. هر ایجنتی که از markdown شروع کند، **روی نقشهٔ غلط عمل می‌کند** — این ریشهٔ resetها، ناوگان تاریک و دوباره‌کاری‌های ثبت‌شده در [[EXPERIENCE-LEDGER]] است.

آن ممیزی یک‌بار **دستی** انجام شد. این لایه همان کار را **تکرارپذیر، قطعی و canonical** می‌کند.

## ۲. مأموریت

یک اسکنرِ قطعی که از **فایل‌سیستم + خروجیِ زندهٔ زمان‌بند** (نه اسناد) یک سند واحدِ `SYSTEM-STATE` تولید می‌کند — **تنها منبعِ شناختِ اولیه** برای دکتر، حلقهٔ فکری، و هر ایجنت دیگر (از جمله ربات اصلی). جایگزینِ ممیزی‌های دستیِ موازی.

## ۳. اصول (غیرقابل‌مذاکره)

1. **قطعی، صفر-LLM:** فقط شمارش، hash، stat، diff — هیچ قضاوت مدلی.
2. **فقط-خواندنی** به‌جز نوشتنِ خودِ `SYSTEM-STATE` (خروجی regenerable؛ هر اجرا بازتولید می‌شود، دست‌نویس نمی‌شود).
3. **منبع حقیقت = فایل‌سیستم + زمان‌بند زنده.** اسناد vault فقط برای «تشخیص drift» خوانده می‌شوند، نه به‌عنوان حقیقت.
4. **stable-read gate** طبق [[DOCTOR-BLUEPRINT-v1]]: هر خواندن باید از فیلتر stale-view عبور کند؛ برای چک‌های بایتی، اوراکل سمت ویندوز اجباری است (یافتهٔ ۰۷-۰۵: snapshotِ خودسازگارِ کهنه ممکن است).
5. **امنیت:** secret/PII فقط با مسیر/اندازه/نوع گزارش می‌شود — **هرگز محتوا echo نشود**؛ `.agentignore` مطلق است.

## ۴. محتوای SYSTEM-STATE (بلوک‌ها)

| بلوک | محتوا | مصرف‌کننده |
|---|---|---|
| Inventory | حجم/تعداد فایل به تفکیک پوشه، تعداد نوت md، بار غیردانشی (venv/dump/باینری) | ستون ۱ (قاعدهٔ ۴ قانون) |
| Task Reconciliation | آشتیِ زمان‌بند زنده ↔ AGENT_REGISTRY ↔ HANDOFF ↔ HEARTBEAT؛ لیست drift با شدت | ستون ۱ + کاندیدهای جهش ستون ۲ |
| Security Flags | `.env` زنده، wallet/key، وضعیت گیت rotation (مسیر/اندازه فقط) | Security Gate |
| PII Flags | فایل‌های ژنتیکی/بیومتریک + تکرارشان در `_Duplicates` | خط‌مشی laptop-only |
| Gates | وضعیت `git init`/rollback · وضعیت Security Gate → **آیا L2 مجاز است؟** (قید §۹.۳ سند اهداف) | حلقهٔ فکری |
| Live Runtimes | پردازه‌ها/خروجی‌های زنده (مثل `fusion-mvp` → `audit.jsonl`) | ستون ۲ (جهش رفتاری) |
| Fitness Proxies | متریک‌های قطعیِ تابع برازندگیِ مصوب: فعالیت/خروجی هر پروژهٔ درآمدی + شاخص‌های سادگی/سرعت workflow (تعداد گام، نرخ خطای تسک‌ها) | ارزیابی جهش (§۹.۲) |
| Kill-Switch State | وضعیت سه سطح (Pause/Kill/Revert) و آخرین فعال‌سازی | آرتیفکت انسانی (§۹.۶) |
| Delta | تفاوت با اجرای قبلی SYSTEM-STATE — «چه چیزی عوض شد؟» | همه؛ ورودی observe حلقه |

## ۵. رابطه با اکوسیستم

```
فایل‌سیستم + زمان‌بند زنده ──► [لایهٔ شناخت] ──► SYSTEM-STATE
                                                    │
             ┌──────────────┬───────────────┬───────┘
             ▼              ▼               ▼
        دکتر ستون ۱     جهش‌یاب ستون ۲   observe حلقهٔ ستون ۳
```

دکتر دیگر خودش اسکن خام نمی‌کند؛ از SYSTEM-STATE می‌خواند و فقط قضاوتِ انطباق می‌افزاید. حلقهٔ فکری **هرگز بدون SYSTEM-STATE تازه شروع نمی‌شود** (قاعدهٔ §۵.۸ سند اهداف: آشتی حقیقت پیش از فکر).

## ۶. متریک‌های موفقیت

- دو اجرای پشت‌سرهم بدون تغییرِ واقعی → خروجی byte-identical (قطعیت).
- drift مصنوعیِ تزریق‌شده (تسک تستی در زمان‌بند بدون ثبت در رجیستری) → آشکارسازی ۱۰۰٪.
- صفر echo از محتوای secret/PII در هر اجرا.
- زمان اجرا در حدی که بتواند پیش از هر چرخهٔ فکری بدون هزینهٔ محسوس تازه شود.

## ۷. تصمیم‌های باز برای آری

1. **محل و فرمت خروجی:** `SYSTEM-STATE.md` انسان‌خوان + `system-state.json` ماشین‌خوان؟ کجا (پیشنهاد: `01 - Dashboard`)؟
2. **ریتم اجرا:** فقط ابتدای هر جلسه/چرخه، یا تسک زمان‌بندی‌شدهٔ دوره‌ای هم؟
3. **دسترسی به زمان‌بند زنده:** خروجی زمان‌بند از چه مسیری خوانده شود (API/فایل state) — نیاز به تأیید مسیر واقعی.
4. **آستانه‌ها:** چه حجمی «بلوت»، چه سنی «کهنگی» حساب شود؟

## ۸. آنچه عمداً اجرا نشد

هیچ کدی نوشته نشد، هیچ اسکنی اجرا نشد، هیچ تسکی زمان‌بندی نشد. تنها خروجی = همین سند. ساخت، پس از verdict آری روی §۷ و طبق ترتیب مصوب: Security Gate + git → لایهٔ شناخت → ستون ۱ → ستون ۲ → ستون ۳.
