# مگاپرامپت — امروز فقط زیمان، کامل

**پیوندها:** [[INDEX]] · [[CLAUDE]] · [[HANDOFF]] · [[MEGAPROMPT]] · [[DECISIONS]]

> این را کامل در `claude` روی اورنج‌پای بخوان و اجرا کن.
> **دامنهٔ امروز: فقط `ziman`.** به lead و studio دست نزن مگر جایی که
> اشتباهی مشترک پیدا کردی — آن را یادداشت کن، اجرا نکن.

---

## چرا فقط یکی

سه پوسته را هم‌زمان زنده کردن یعنی وقتی چیزی می‌شکند، سه متغیر داری. یکی را
تا ته ببر، **اشتباهاتش را جمع کن**، بعد آن درس‌ها را روی دوتای دیگر اعمال کن.

توکن ملیحه از قبل پر است. او نزدیک‌ترین شریک به خط پایان است.

---

## ۱) مدل کسب‌وکار — این را اول بفهم

زیمان یک گالری هدیهٔ **دست‌ساز** است. الگوی عملیاتی این صنعت در ۲۰۲۶
تثبیت‌شده است و ابزارهای تخصصی‌اش (Craftybase و مشابه) همه حول یک محور
می‌چرخند:

```
مواد خریداری‌شده  →  موجودی مواد  →  COGS واقعی هر محصول  →  قیمت کف
```

و مسئلهٔ شمارهٔ یک این صنعت این است:

> **بیشتر سازندگان روی پرفروش‌ترین محصولشان ضرر می‌کنند** — چون COGS واقعی
> را هرگز حساب نمی‌کنند. دستمزد خودشان را صفر می‌گیرند و پرت مواد را نادیده.

پس باارزش‌ترین خروجی برای ملیحه «داشبورد قشنگ» نیست. این است:

> «این محصول با این قیمت، بعد از مواد و وقتت، **ضرر می‌دهد**.»

پک `ziman.yaml` از قبل `offer.cogs_per_family` را به‌عنوان fact لازم دارد.
طراحی از اول به همین‌جا اشاره می‌کرده — کارِ امروز کامل کردن همان مسیر است.

---

## ۲) قرارداد ورودی/خروجی — این را بساز

### ورودی — چیزی که فقط ملیحه می‌داند

حداکثر **سه سؤال در روز**. کرنل خودش از شکاف factها استنتاج می‌کند کدام‌ها.

> **واحد پول: AUD.** («تومان» در نسخهٔ اول این سند stale بود و ۲۰۲۶-۰۸-۰۴
> اصلاح شد — به آن استناد نکن. بازار زیمان استرالیاست چون مشتریِ
> پرداخت‌کننده‌اش استرالیایی است، و locale در `packs/ziman.yaml` مرجع است.)

```
materials.cost_per_batch    هزینهٔ مواد یک دستهٔ ساخت      عدد · واحد: AUD
time.hours_per_item         چند ساعت برای هر عدد            عدد · واحد: ساعت
time.hourly_floor           ساعتی چقدر ارزش وقتت است        عدد · یک بار در ماه
offer.price_current         الان چند می‌فروشی               عدد
stock.units_left            چندتا مانده                      عدد
sales.units_last_7d         این هفته چندتا فروختی            عدد
```

⚠️ `time.hourly_floor` مهم‌ترین سؤال کل سیستم است و کسی نمی‌پرسدش. بدون آن،
COGS دروغ است. یک بار در ماه بپرس، نه هر روز.

### مشتق — کرنل، قطعی، رایگان، بدون مدل

```
cogs        = materials.cost_per_batch / batch_size + time.hours_per_item × time.hourly_floor
margin      = offer.price_current − cogs
margin_pct  = margin / offer.price_current
runway_days = stock.units_left / (sales.units_last_7d / 7)
```

هیچ‌کدام مدل لازم ندارند. **پلهٔ `rules`** — رایگان و لحظه‌ای.

### خروجی — سه چیز، نه بیشتر

```
🟢 سالم        margin_pct ≥ 0.30
🟡 زیر کف      margin_pct < 0.30  →  پیشنهاد افزایش قیمت در صف آری
🔴 ضررده       margin_pct < 0     →  RED · دو مرحله‌ای · فوری
⏳ رو به اتمام  runway_days < 7    →  «۳ روز دیگر تمام می‌شود»
```

### 🔴 قاعده‌ای که نباید بشکند

**اگر ملیحه هنوز جواب نداده، هیچ عددی نشان نده.** نه صفر، نه تخمین، نه
میانگین صنعت. یک `margin` که از fact غایب ساخته شده، بدترین نوع دروغ است —
چون بر اساسش قیمت عوض می‌شود.

به‌جایش: «برای این محاسبه هنوز ۲ چیز لازم است» + همان سؤال‌ها.

## ۳) کاری که امروز می‌کنی — به ترتیب

### گام ۱ — ملیحه واقعاً وارد شود

```bash
awk -F= '{printf "%-26s %s\n", $1, ($2==""?"خالی":"پر ✓")}' ~/.config/ofn/secrets.env
sudo systemctl restart ofn
journalctl -u ofn -n 20 --no-pager
```

آری در BotFather دکمهٔ منوی بات زیمان را روی
`https://ziman.master-painting.com` گذاشته. از او بخواه از گوشی‌اش باز کند و
بگوید چه دید.

سه حالت ممکن، و هر کدام معنی متفاوتی دارد:

```
«از داخل تلگرام باز می‌شود»  →  initData نرسیده. Menu Button غلط تنظیم شده.
نشان «نمونه»                 →  صفحه آمد، API جواب نداد. لاگ را ببین.
سؤال واقعی                   →  ✅ ورود کار می‌کند. برو گام ۲.
```

### گام ۲ — یک چرخهٔ کامل، از انگشت او تا لجر

از آری بخواه ملیحه یک جواب واقعی بدهد. بعد **هر پنج مرحله را تأیید کن**:

```
[ ] جواب در پوسته ثبت شد و بازخورد دید
[ ] fact در facts.sqlite نشست — با کلید subject.predicate
[ ] رویداد در لجر آمد و زنجیره تأیید می‌شود
[ ] در پنل آری دیده می‌شود
[ ] سؤال بعدی عوض شد (چون شکاف پر شده)
```

اگر مرحلهٔ ۵ کار نکرد، `questions.plan()` جواب را ندیده — و این یعنی همان
باگ کلید نقطه‌دار که قبلاً یک بار خوردیم.

### گام ۳ — خط لولهٔ COGS را بساز

اینجا کد تازه می‌نویسی. جایش `ofn/kernel/` **نیست** — قاعدهٔ کسب‌وکار است، نه
کرنل. دو انتخاب:

```
packs/ziman.yaml       فرمول‌ها به‌صورت داده
ofn/adapters/ziman.py  اگر منطقش از YAML بیرون زد
```

**ترجیح: پک.** اگر فردا عباس فرمول متفاوتی خواست، یک فایل عوض می‌شود نه کد.

هر خروجی باید بگوید **از کدام factها ساخته شده**. یک عدد بدون شجره‌نامه،
عددی است که نمی‌شود اشکال‌زدایی‌اش کرد.

### گام ۴ — جارو و دیباگ، فقط زیمان

```bash
cd ~/ofn && python3 -m pytest -q
python3 -m ofn.preflight
curl -s -o /dev/null -w '%{http_code} %{size_download}\n' -m5 http://127.0.0.1:8791/
journalctl -u ofn -p err -b --no-pager | tail -20
```

بعد این چهار سؤال را از پوستهٔ زیمان بپرس و جواب بنویس:

```
۱. اگر ملیحه وسط جواب دادن اینترنتش قطع شود، چه می‌شود؟
۲. اگر دو بار پشت هم دکمه بزند، دو fact ثبت می‌شود؟
۳. اگر عدد بی‌معنی بزند (۹۹۹۹۹۹۹)، کران‌ها می‌گیرندش؟
۴. کدام عدد روی صفحهٔ او از منبع واقعی نمی‌آید؟
```

سؤال چهارم را جدی بگیر. یک بار کل پنل ماکت بود و «قابل اعتماد به نظر
می‌رسید» — همان چیزی که خودت پیدایش کردی.

### گام ۵ — دفتر درس‌ها

```
~/ofn/LESSONS-ZIMAN.md
```

هر چیزی که در زیمان شکست، با این شکل:

```markdown
## <چه چیزی شکست>
علامتی که دیدم:
علت واقعی:
چطور درستش کردم:
آیا lead و studio هم دارند؟   بله / نه / باید چک شود
```

**این فایل دلیل وجود امروز است.** زیمان قربانی نیست؛ **جای یادگیری** است.

## ۴) الگویی که هر سه leg مشترک دارند

وقتی زیمان کار کرد، این ساختار برای هر سه یکی است — فقط factها فرق می‌کنند:

```
        ورودی انسانی            مشتق قطعی              خروجی
ziman   مواد · وقت · قیمت    →  COGS · حاشیه      →  «ضرر می‌دهی» · «تمام شد»
lead    کار · متریال · تیم   →  قیمت کف · ظرفیت   →  «این کار ضرر است» · «جا نداری»
studio  زمان · پلتفرم       →  نرخ تولید         →  «عقب افتادی» · «این جواب داد»
```

**هر سه یک شکل دارند: انسان چیزی می‌داند که ماشین نمی‌داند → ماشین حسابی
می‌کند که انسان نمی‌کند → نتیجه یک تصمیم است، نه یک نمودار.**

اگر جایی دیدی خروجی یک leg فقط «نمایش داده» است و به تصمیمی نمی‌رسد، آن leg
هنوز تمام نشده.

## ۵) دروازه‌ها

### 🚪 Z1 — ورود

```
[ ] ملیحه از گوشی واقعی وارد شد
[ ] سؤال واقعی دید، نه نشان «نمونه»
[ ] نشست منقضی شد و دوباره وارد شد بدون خطای گیج‌کننده
```

### 🚪 Z2 — چرخهٔ کامل

```
[ ] جواب → fact → لجر → پنل آری → سؤال بعدی عوض شد
[ ] زنجیرهٔ لجر تأیید می‌شود
[ ] جواب تکراری، fact تکراری نمی‌سازد
[ ] عدد بی‌معنی رد می‌شود
```

### 🚪 Z3 — خروجی واقعی

```
[ ] COGS از factهای واقعی محاسبه شد
[ ] هر عدد شجره‌نامه دارد
[ ] با fact غایب: هیچ عددی، فقط سؤال
[ ] یک محصول ضررده → پیشنهاد در صف آری
[ ] تست‌ها سبز · عدد را گزارش کن
```

### 🚪 Z4 — درس‌ها

```
[ ] LESSONS-ZIMAN.md پر شده
[ ] هر درس علامت خورده که lead/studio هم دارند یا نه
[ ] کامیت + push
```

شروع کن با گام ۱.
