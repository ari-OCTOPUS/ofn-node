چهار تصمیم باز که یکی‌شان جلوی اجرای واقعی را گرفته.

## ۱) هدف — چرا این با ماینینگ معمولی فرق دارد

```
سود ماهانه            ← ارزشش صفر است. وارد هیچ محاسبه‌ای نمی‌شود.
برق                   ← رایگان و تضمین‌شده. متغیر تصمیم نیست.
هدف واقعی             ← انباشت بلندمدت + تنوع زیاد. مثل قلک.
```

و مهم‌ترین نکته که اگر اشتباه بگیری کل سیستم را خراب می‌کند:

```
❌ «هزار دانه کوین»  →  توهم واحد. کوین تورمی راحت‌ترین راه رسیدن به این عدد است.
✅ سهم از انتشار     →  «چند درصد از کل سکه‌ای که این هفته منتشر شد، مال ما؟»
```

`allocation.Trial.share` این را حساب می‌کند. زیر `DEFAULT_MIN_SHARE = 0.001`
یعنی ما خطای گردکردنیم و آن arm حالت `MARGINAL` می‌گیرد.

## ۳) چهار چیزی که باید بسازی

### ۳‌الف) `ofn/adapters/fleet_store.py` — انبار حلقوی

**چرا حلقوی:** ۱۴۰ سنسور هر ۳۰ ثانیه = ~۴۰۰٬۰۰۰ نوشتن در روز. لجر ما
`synchronous=FULL` است — هر نوشتن یک fsync. این کارت فلش را ظرف چند ماه
می‌کشد و زنجیرهٔ حسابرسی را در دریای تله‌متری غرق می‌کند.

```python
class FleetStore:
    """Ring buffer per unit. Bounded by construction, not by a cron job."""

    def __init__(self, path: str, *, per_unit_rows: int = 2880): ...
    #   2880 = 24h at one reading per 30s

    def record(self, reading: Reading) -> None: ...
    def latest(self) -> Mapping[str, Reading]: ...
    def baseline(self, unit: str, arm_id: str) -> Baseline | None: ...
    def close(self) -> None: ...
```

قواعد سخت:

```
journal_mode = WAL          مثل بقیه
synchronous  = NORMAL       ← عمداً متفاوت از لجر
```

از دست دادن ۳۰ ثانیه هش‌ریت بعد از قطع برق هیچ هزینه‌ای ندارد؛ ۴۰۰ هزار
fsync در روز دارد. **این دو را با یک سیاست اداره کردن، یکی را غلط اداره
کردن است.**

حلقه با `INSERT OR REPLACE` روی `(unit, slot)` که `slot = seq % per_unit_rows`
— نه با `DELETE`، چون DELETE فایل را کوچک نمی‌کند.

`baseline()` میانهٔ hashrate را از همان حلقه می‌سازد. **کمتر از
`MIN_BASELINE_SAMPLES` نمونه یعنی `None`**، نه یک عدد ضعیف. `fleet.judge` روی
این حساب می‌کند.

### ۳‌ب) `ofn/adapters/pools.py` — خوانندهٔ سنجاق‌شده

```python
def load_pinned(path: str) -> tuple[Arm, ...]:
    """Read-only. Never writes. A test asserts no module opens this for write."""
```

فرمت `~/.config/ofn/pools.pinned` — TSV ساده، چون باید با `nano` قابل ویرایش
باشد:

```
# arm_id        coin    pool_url                   payout_address   algo      classes
xmr.p2pool      XMR     stratum+tcp://...:3333     4Axxxx...        randomx   opi5pro
newcoin.pool1   NEW     stratum+tcp://...:4444     Nxxxxx...        yespower  opi5pro,rpi
```

قواعد:

```
chmod 400 · مالک root · نود با کاربر ari می‌دود → نمی‌تواند بنویسد حتی اگر بخواهد
هر ردیف بد → کل فایل رد شود، نه اینکه ردیف بد نادیده گرفته شود
```

آن آخری مهم است: یک ردیف با آدرس خراب که بی‌صدا رد شود یعنی هش‌پاور به جای
دیگری می‌رود.

**تست AST بنویس** که هیچ ماژولی این فایل را در حالت `w`/`a`/`+` باز نمی‌کند —
همان الگویی که `http_api.py` را از import کردن روتر منع می‌کند.

### ۳‌ج) `ofn/adapters/scout_job.py` — کار روزانه

```
۱. brief(memory, constraints)  →  زمینه از حافظه
۲. research_focus(memory, trials, classes)  →  حداکثر ۳ سؤال
۳. برای هر سؤال: یک Job در worker (Rung.REMOTE، مدل fugu)
۴. جواب را به Candidate پارس کن
۵. triage(candidates, memory, constraints)  →  fresh + refused
۶. fresh → صف مالک   ·   refused → لجر (نه دور ریختن)
۷. Note ها را در حافظه بنویس
```

قواعد سخت:

```
❌ هرگز مستقیم مدل را صدا نزن — از worker برو تا سهمیه و scrub اعمال شود
❌ هرگز خودت به pools.pinned ردیف اضافه نکن — فقط پیشنهاد
❌ هرگز refused را دور نریز — اسکاوتی که ۹ از ۱۰ را بی‌صدا می‌اندازد،
   دقیقاً شبیه اسکاوتی است که یک چیز پیدا کرده
```

حافظه در `~/.local/share/ofn/scout.sqlite`. با حافظهٔ اولیه از بخش «رد
همیشگی» در `DECISIONS.md` بارگذاری شود تا از صفر شروع نکند.

تایمر: روزی یک بار، `RandomizedDelaySec` بگذار.

### ۳‌ه) `web/mine.html` — پورت ۸۷۹۵

شریک این leg خود آری است، پس **تکنیکال و متراکم** بساز، نه ساده مثل سه پوستهٔ
دیگر. اعداد خام، نمودار، بدون ساده‌سازی.

باید نشان دهد:

```
سلامت ناوگان     healthy / degraded / offline / broken / unknown
پوشش             چند arm×class هنوز unproven است  ← عدد پیشرفت جستجو
سهم هر arm       درصد انتشار — عدد اصلی
تعداد خام        چون آری خواسته ببیند (ولی تصمیمی رویش نیست)
صف پیشنهادها     از scout، با دکمهٔ تأیید/رد
```

و قاعده‌ای که خودت در سه پوستهٔ دیگر کشف کردی و اینجا هم باید باشد:
**در حالت قطع هیچ عددی نشان نده.** نه صفر، نه نمونه، هیچ.

پورت ۸۷۹۶ برای ورودی تله‌متری ناوگان — **فقط LAN، از تونل رد نشود.**

## ۴) مدل کنترل — بدون SSH

D-20 می‌گوید ایجنت هرگز SSH مستقیم نمی‌زند. ولی «کنترل کامل» یعنی باید بتوانی
ریگ را ری‌استارت کنی. راه‌حل هر دو: **مدل pull**.

```
دستگاه ──POST /fleet/beat (تله‌متری)──▶ نود
نود    ──پاسخ: {"cmd": "restart"}────▶ دستگاه
                                        عاملِ خودِ دستگاه اجرا می‌کند
```

نود هرگز به دستگاهی وصل نمی‌شود، فقط جواب می‌دهد. پشت NAT هم کار می‌کند، و
سطح حملهٔ ورودی صفر است.

احراز هویت تله‌متری: HMAC روی بدنه، یک راز به ازای هر **کلاس** نه هر دستگاه.
۱۴۰ راز مدیریت‌شدنی نیست. معامله‌اش را می‌دانیم و در `DECISIONS.md` نوشته
شده.

## ۵) 🔴 تصمیمی که با آری باید بگیری — قبل از هر اجرای واقعی

**O-1 در `DECISIONS.md`.** ماین کردن کوین یک‌ماهه یعنی اجرای باینری
بررسی‌نشده از تیم ناشناس، روی ۱۶ برد، **روی همان LANی که نود سه بیزنس رویش
است**.

خطر واقعی این استراتژی سود ازدست‌رفته نیست — **سخت‌افزار تسخیرشده** است.

سه گزینه در `DECISIONS.md` هست. با آری بررسی کن، تصمیم را در همان فایل ثبت
کن، و `miner_isolation` را فقط بعد از آن باز کن.

**تا آن موقع: هیچ کوین نوظهوری روی برد واقعی اجرا نمی‌شود.** کد بساز، تست
کن، ولی گیت بسته می‌ماند.
