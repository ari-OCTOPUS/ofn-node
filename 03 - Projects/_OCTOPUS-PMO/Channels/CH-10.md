# CH-10 · Git Watcher + Self-Evolution Trigger

> **Channel type:** Event-driven evolution trigger
> **Status:** ✅ Implemented — polling-based, propose-only
> **Wave:** 2 (P1 channel)

---

## Purpose

Transform the daemon from *tick-based* to *event-driven* for code changes:

1. Watch git repository for new commits / uncommitted changes
2. Filter changed `.py` files through TCB guardrails
3. Trigger `self_code.auto_propose_once()` for eligible files
4. Emit `approval.required` → human verdict queue

**Core constraint:** propose-only. Never auto-apply. Every proposal lands in the HITL queue.

## Architecture

```
git working tree (F:/backup)
    │
    ├──► polling loop (every 60s default)
    │         └──► git diff HEAD~1..HEAD
    │
    └──► (optional) post-commit hook signal
              └──► fast-path react

    ▼
_filter_:
  • skip: __pycache__, .git, .venv, node_modules, outputs, _ops, OCTOPUS
  • skip: non-.py files
  • TCB guard: guardrails.assert_code_target_allowed()
  • size guard: < 12 KB

    ▼
_pick targets_ (max 2 per run, cooldown 10 min)

    ▼
self_code.auto_propose_once(target_rel, goal)

    ▼
events.emit("approval.required", ...)  →  CH-14 queue
```

---

## Safety Design

1. **TCB Guard** — `guardrails.assert_code_target_allowed()` blocks core/, tests/, config/, guardrails.py
2. **Cooldown** — 10-minute minimum between proposal bursts
3. **Limit** — max 2 files per trigger
4. **Size cap** — 12 KB per file
5. **Windows-safe** — polling (not hooks) as primary; hooks are doc-only on Windows
6. **Propose-only** — `auto_propose_once` queues for human approval; never applies
