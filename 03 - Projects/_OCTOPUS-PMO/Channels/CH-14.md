# CH-14 · HITL Queue (Human-in-the-Loop)

> **Channel type:** Governance / unified approval queue
> **Status:** ✅ Implemented
> **Wave:** 2 (P1 channel)

---

## Purpose

A single queue merging approval requests from **both** `_ops` organism and `4d_system` brain.

**Invariant (TINV-7):** No irreversible effect without prior append + human verdict.

## Sources Merged

### 1. `_ops` (Organism)
- `pending_snapshot.json` — approval_channel pending effects
- `rfc_snapshot.json` — doctor RFC proposals
- `approvals.jsonl` — historical verdicts

### 2. `4d_system` (Brain)
- `self_code.list_pending()` — code change proposals
- Auto-imported with shadow-bypass (`_import_4d_brain()`)

## Queue Item Schema

```python
@dataclass
class UnifiedQueueItem:
    id: str
    source: str          # "_ops" | "4d_system"
    source_label: str    # "🐙 ارگانیسم" | "🌌 ایده‌یاب"
    type: str            # "money" | "code_change" | "rfc" | "operational"
    status: str          # "pending" | "approved" | "denied" | "settled"
    summary: str
    detail: str
    amount_aud: float
    priority: str        # "high" | "medium" | "low"
    created_at: str      # ISO timestamp
    effect_id: str | None
    risk_level: str      # "R1".."R4"
    actions: dict        # approve/reject callback patterns
    gate_status: str | None
```

---

## Risk Levels

| Level | Condition | Example |
|---|---|---|
| **R1** | Low risk, no money | Operational flag toggle |
| **R2** | Medium risk, no money | Code change proposal |
| **R3** | High risk or money | Spend > 0 AUD |
| **R4** | Critical / security | Security policy change |

## Refresh Flow

```
UnifiedApprovalQueue.refresh()
    │
    ├──► _pull_4d_system()  →  self_code.list_pending()
    │
    ├──► _pull_ops()        →  pending_snapshot + rfc_snapshot
    │
    ├──► _merge_items()     →  deduplicate by id
    │
    ├──► _reconcile_gate_status()  →  EffectorGate authoritative status
    │
    └──► _reconcile_approvals_jsonl()  →  historical verdicts
    │
    ▼
save() → unified-approval-queue.json
```

---

## Approval Flow

```
Owner approves via Telegram / Dashboard
    │
    ▼
UnifiedApprovalQueue.approve(item_id)
    │
    ├──► 4d_system: self_code.approve(pid)  →  apply + record
    │
    └──► _ops: status="approved" (settlement via EffectorGate only)
```

**Note:** For `_ops` items, queue approval = *intent only*. Actual settlement goes through `EffectorGate` (TINV-7).
