## Prompt 2 — Automation + Telegram Second-Brain Integration

```
# MISSION: Automate the "OnlyFans / Feet Content" Project & Wire It Into the Telegram Second-Brain

Prerequisite: load STATE-REPORT-<date>.md and _memory/onlyfans-project-memory-<date>.md from the previous mission first.

You are the lead architect + builder. Goal: turn the manual playbooks into an agent-driven, SEMI-automated content operation, with the existing Telegram bot as the primary command / capture / notification console ("second brain").

## Phase 0 — Discover the current automation surface (read first, assume nothing)
1. Read `backup/10 - Telegram processing/` fully: the existing bot's stack, entry points, message flow, how it writes into the vault, credential handling, any queue/DB.
2. Read `backup/05 - Agents/`, `backup/.claude/`, `CLAUDE.md`: existing agent definitions, conventions, tools already available.
3. Inspect `secrets-export/`, `.gitignore`, `.agentignore` to learn secret management — do NOT print any secret values.
4. Output a "Current Automation Map": what already runs, what's manual, and the exact integration point where the OnlyFans workflows plug into the Telegram bot.

## Phase 1 — Target architecture (design)
  1. System diagram as a Mermaid diagram: capture → planning → production → scheduling → cross-posting/repurposing → DM/lead handling → analytics → decision-log, and where the Telegram bot sits in each loop.
  2. Agent roster table: name | job | trigger | inputs | tools | output | model. Suggested: Content-Planner, Production-Checklist, Repurposing, Cross-Poster (X/Reddit), Lead/DM-Assistant, Analytics-Loop, Decision-Logger, Second-Brain-Router (Telegram front door).
  3. Model selection + rough per-task cost: cheap model for routing/classification, mid model for drafting content/DMs, top model for weekly strategy — use the ACTUAL current Claude model names and give a monthly cost estimate at a stated volume.
  4. Memory strategy: vault = long-term memory; Telegram bot = short-term capture; how state/queues persist between runs.
  5. Tool design: for each agent, concrete tools/APIs (platform APIs, scheduler, vault file writes) — each with pricing model, best alternative, and vendor lock-in risk.

## Phase 2 — Telegram second-brain integration (the core deliverable)
Specify how the bot becomes the operating console:
  - Capture: quick idea/task → routed to the right vault folder by Second-Brain-Router.
  - Briefings: daily/weekly digest generated from the knowledge base, pushed to Telegram.
  - Approvals (human-in-the-loop): bot presents queued content / drafted DMs; human approves, edits, or rejects before anything goes out.
  - Alerts: metric anomalies, tasks due, pipeline stalls.
  - Commands: e.g. /idea /queue /approve /brief /status.
Deliver the command spec AND the data contract between bot and agents (what JSON/markdown passes where).

## Phase 3 — Implementation plan + starter code
  1. Phased rollout: P1 capture + briefings (read-only) → P2 queue + human-approved posting → P3 analytics loop + experiments. NO fully-autonomous outbound messaging until approvals are proven.
  2. Production-grade starter code for the highest-ROI first piece (recommend: Second-Brain-Router + daily briefing). Clean Code / SOLID / DRY, with error handling, logging, retries, and secrets read from env — never hardcoded.
  3. Monitoring & logging: what to log, where, health checks/alerts per agent.
  4. Testing: unit tests for routing + parsing, a dry-run mode for ALL outbound actions, and an eval set to grade content/DM drafts before they're trusted.
  5. CI/CD outline + a backup/DR note (vault + queue are the persistent state to protect).

## Compliance & safety guardrails (bake in, do not skip)
  - Respect each platform's ToS and anti-spam rules (OnlyFans/X/Reddit); no mass-DM or impersonation patterns that violate them.
  - Keep a human in the loop for all outbound messages to real users; automation drafts and queues, humans approve.
  - Consent & privacy for the person(s) whose content is used.
  - Never expose secrets/API keys in logs, outputs, or committed files.

## Output
  1. AUTOMATION-ARCHITECTURE-<today>.md (design, diagram, agent roster, costs)
  2. TELEGRAM-INTEGRATION-SPEC-<today>.md (commands, flows, data contracts)
  3. An `/automation` starter folder with the Phase-1 code
Save all into the project folder, link from INDEX.md.
End with: the single next action to take today + the exact command to run the Phase-1 starter.
```
