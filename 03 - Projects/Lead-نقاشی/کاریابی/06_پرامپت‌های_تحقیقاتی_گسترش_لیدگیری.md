# ۱۰ پرامپت تحقیقاتی — بهبود و گسترش لیدگیری خودکار

> **نحوه استفاده:** هر پرامپت را در یک ابزار Deep Research (مثل Claude با web search، ChatGPT Deep Research یا Perplexity) کپی کن. پرامپت‌ها انگلیسی نوشته شده‌اند چون منابع بازار استرالیا انگلیسی است و نتیجه بهتری می‌گیری. خروجی هر تحقیق را در `10_knowledge_base/` یا کنار `01_الگوهای_مخفی` ذخیره کن.
>
> **زمینه مشترک همه پرامپت‌ها:** بیزنس نقاشی ساختمان در سیدنی + ربات فعلی (Harvester هر ۱۵ دقیقه از PlanningAlerts/AusTender/EstimateOne + Hunter agent با Claude + امتیازدهی لید + خروجی تلگرام).
>
> ترتیب پیشنهادی اجرا: پرامپت‌های ۱، ۸ و ۷ اول (بیشترین اثر روی سیستم فعلی)، بعد کانال‌های جدید (۲ تا ۶)، بعد ۹ و ۱۰.

## پرامپت ۱ — نقشه کامل منابع دادهٔ قابل‌اتوماسیون (گسترش Harvester)

**هدف:** پیدا کردن همه منابعی که می‌شود مثل PlanningAlerts به ربات وصل کرد.

```
I run an automated lead-generation bot for a building/commercial painting business in Sydney, Australia. It currently harvests leads every 15 minutes from: PlanningAlerts API, AusTender RSS, and EstimateOne. Leads are scored by an LLM and pushed to Telegram.

Research task: Build a complete map of MACHINE-READABLE lead sources for painting work in Sydney/NSW that can be automated (API, RSS, email alerts parseable via IMAP, or reliably scrapable pages).

Cover at minimum:
1. NSW eTendering (tenders.nsw.gov.au) — alert categories relevant to painting (T1), export/API options
2. Council-level tender portals: Tenders.Net, VendorPanel, SSROC and individual Sydney council procurement pages
3. Federal/state maintenance programs: Schools (NSW Dept of Education asset maintenance), Health Infrastructure NSW, Defence estate maintenance (EMOS), Sydney Water, Transport for NSW
4. Construction project databases: BCI Central LeadManager, Cordell Connect — current pricing, trial options, API/export capability
5. DA/CDC data beyond PlanningAlerts: NSW Planning Portal open data, individual council DA trackers
6. Any RSS/JSON feeds from builder tender platforms (EstimateOne paid tier, Felix, ProcurePro)

For EACH source output a table row: name | URL | access method (API/RSS/IMAP/scrape) | cost (AUD, current pricing) | signup requirements | data fields available | estimated painting-relevant leads per month for Sydney | automation difficulty (1-10) | legal/ToS risk of automated access.

Finish with a ranked "connect next" list: top 5 sources by (leads per month × lead quality) / (cost + effort), with justification.
```

## پرامپت ۲ — کانال Property Manager / املاک اجاره‌ای (repaint بین مستاجرها)

**هدف:** باز کردن کانالی که در تحقیق «۱۲ کانال مخفی» کم‌عمق مانده: نقاشی end-of-lease و turnover.

```
Context: Sydney painting business seeking recurring residential repaint work from real estate property managers (end-of-lease repaints, rental turnover, insurance touch-ups).

Research:
1. How do Sydney property management agencies dispatch maintenance jobs in 2025-2026? Map the trade-dispatch platforms: Tapi, Bricks + Agent, Maintenance Manager, PropertyMe marketplace, Console, PropertyTree — for each: how a tradie gets onboarded, fees/commission, volume of painting jobs, geographic coverage in Sydney.
2. Which of these platforms have APIs, tradie apps, or notification feeds that could be integrated into an automated lead pipeline?
3. What do property managers require from a painter to become a "preferred trade" (insurance, licence, response SLA, invoicing)?
4. Top 30 property management agencies in Sydney by rent roll size — names + suburbs covered.
5. Typical pricing and margins for end-of-lease repaints in Sydney (per room / per apartment benchmarks).

Output: (a) comparison table of dispatch platforms, (b) onboarding checklist, (c) a 90-day plan to get listed on the 3 highest-volume platforms, (d) automation opportunities (what my bot can monitor or auto-respond to).
```

## پرامپت ۳ — Strata عمیق: پیدا کردن ساختمان‌هایی که «الان» موعد نقاشی‌شان است

**هدف:** تبدیل کانال strata از «رابطه‌سازی دستی» به «لید data-driven».

```
Context: Painting contractor targeting strata (apartment building) repaint contracts in Sydney. Buildings typically repaint every 7-10 years. I want to identify buildings DUE for repainting using data, before they tender.

Research:
1. Data sources to estimate a strata building's last repaint / build date: NSW Planning Portal DA history, council DA archives, NSW Strata Hub public data (what fields are public?), capital works fund plans (are 10-year plans accessible?), Google Street View history as a manual check.
2. How strata repaint decisions actually get made: roles of strata manager vs building manager vs owners corporation committee; when in the AGM/budget cycle painting is approved; who to contact and when.
3. The realistic path onto preferred-contractor panels of PICA Group, Netstrata, Strata Plus, Bright & Duggan: application process, insurance/compliance requirements (SafeWork, SWMS), typical panel review cycles.
4. Is SCA (Strata Community Association) NSW membership worth it for a painter — cost vs access (events, directories)?
5. Any lead-gen services or databases specialising in strata maintenance (e.g., companies selling strata building lists)?

Output: (a) a scoring model draft: given a building (address, age, storeys, last DA), estimate repaint probability in next 12 months; (b) data acquisition plan with sources and cost; (c) outreach playbook per decision-maker role; (d) panel application checklist.
```

## پرامپت ۴ — اتوماسیون RFQ بیلدرها + پارس ایمیل (IMAP)

**هدف:** فرصت‌های هفتگی بیلدرهای Tier-1/2 مستقیم بیاید داخل دیتابیس ربات.

```
Context: My lead bot (Python, SQLite, Telegram) should capture subcontractor RFQs from major Australian builders. Builders email RFQs to registered subbies; I plan an IMAP harvester that parses these emails into structured leads.

Research:
1. Complete list of Tier-1 and Tier-2 builders active in NSW with subcontractor registration portals (Hutchinson subbies.hutchies.com.au, Lendlease, Multiplex, Built, Richard Crookes, John Holland, CPB, Growthbuilt, Buildcorp, FDC, Taylor, ADCO, Kane, etc.) — registration URL, requirements (insurances, SWMS, financials), and whether painting/finishing trades are in scope.
2. How RFQs are delivered per builder: email, portal notification, EstimateOne/Felix invitation? Which ones can be auto-monitored?
3. Best practices for parsing tender-invitation emails reliably (structure varies): rule-based vs LLM extraction; recommended Python approach for IMAP + LLM extraction into fields (project, trade, location, close date, contact, docs link).
4. EstimateOne paid tiers vs BCI Central vs Felix marketplace for a painting sub: current AUD pricing, invitations volume for Sydney painting packages, and which single subscription has best ROI.
5. Etiquette/qualification: what makes builders keep sending RFQs (response rate expectations, capability statements).

Output: (a) builder registration priority list (top 10 with links), (b) technical design for the IMAP+LLM harvester with field schema, (c) subscription ROI comparison table, (d) capability statement outline for a painting sub.
```

## پرامپت ۵ — لیدهای بیمه و رویداد-محور (طوفان/تگرگ)

**هدف:** ساخت harvester ای که بعد از هر طوفان، محله‌های آسیب‌دیده را هدف بگیرد.

```
Context: Painting/restoration work in Sydney triggered by insurance claims (storm, hail, water damage). I want both (a) entry into insurance repair supply chains and (b) an automated event-driven lead trigger.

Research:
1. How the Australian insurance repair supply chain works in 2025-2026: insurers (IAG, Suncorp, Allianz, QBE) → managed repair programs / builder networks (Johns Lyng Group, Bay Building Group, Ambrose, Claim Central, Chill/others) → trade subcontractors. How does a painter get onto these networks? Application links and requirements.
2. Which restoration builders operating in Sydney take on painting subcontractors, and what rates/terms are typical (insurance work often has fixed schedules of rates)?
3. Automated weather-event data: Bureau of Meteorology severe weather warnings API/feeds, hail swath maps, SES callout data — what is machine-readable and free? Can I get suburb-level severity within 24-48h of an event?
4. Post-event marketing rules: legal/ethical constraints on door-knocking or letterboxing storm-damaged areas in NSW (anti-hawking rules, fair trading guidance, insurer AOB issues).
5. Timeline: how long after an event do repair paint jobs actually get commissioned (weeks/months)? When should outreach happen?

Output: (a) supply-chain entry checklist ranked by effort/reward, (b) design spec for a "storm harvester" (data source, trigger logic, geo-targeting, Telegram alert format), (c) compliant post-event outreach playbook.
```

## پرامپت ۶ — لیدگیری پیش‌بینانه با Open Data

**هدف:** به‌جای صبر برای آگهی، پیش‌بینی کنیم کدام ساختمان‌ها به‌زودی نقاشی می‌خواهند.

```
Context: I have a Python bot with LLM access. Goal: predict which Sydney properties will need repainting BEFORE the owner advertises, using open data, then feed high-probability targets into a review queue.

Research:
1. Inventory of relevant open datasets: NSW Planning Portal / open data (DA & CDC approvals history), Geoscape GNAF & building data (what's free vs paid now), NSW Valuer General property sales, ABS building approvals, City of Sydney datasets, aerial/satellite imagery options (Nearmap pricing, free alternatives).
2. Signals that correlate with repaint demand: property just sold (new owner renovates), DA approved for renovation/addition (painting follows at the end), building age 7-10+ years since last paint, deferred maintenance indicators, commercial lease turnover.
3. Feasible modelling approaches for a solo developer: simple heuristic scoring vs logistic regression vs LLM-assisted enrichment. What sample sizes and validation approach make sense with few labelled outcomes?
4. Privacy and legal limits: Privacy Act 1988 / APPs on compiling property-owner data for marketing; what data can be stored about a property vs a person; NSW-specific constraints.
5. Has anyone productised this (property intelligence for trades)? Competitors or tools to learn from.

Output: (a) dataset table (name, access, cost, update frequency, key fields), (b) v1 heuristic scoring spec my bot can implement in a weekend, (c) privacy guardrails list, (d) validation plan tied to real quote outcomes.
```

## پرامپت ۷ — بهینه‌سازی امتیازدهی لید (Lead Scoring) با حلقه بازخورد

**هدف:** نمره‌های Claude الان کالیبره نیستند؛ باید با نتیجه واقعی (quote/won) تنظیم شوند.

```
Context: My bot scores each harvested lead 0-100 with an LLM (Claude) using a YAML rubric (relevance to painting, job size, location, urgency). Leads ≥85 push instantly to Telegram. Problem: scores are uncalibrated — I don't yet know if 85+ leads convert better. Pipeline stages: new → contacted → quoted → won/lost.

Research current best practice (2025-2026):
1. LLM-as-scorer calibration: techniques to make LLM numeric scores consistent and meaningful (rubric decomposition, pairwise comparison instead of absolute scores, few-shot anchoring with real examples, temperature/self-consistency, structured output).
2. Feedback-loop design with SMALL data: I might get only 5-20 outcome labels per month. What's the right approach — Bayesian updating of rubric weights, banked few-shot examples of won/lost leads, or periodic prompt revision? At what sample size does a simple logistic regression on structured features beat the LLM rubric?
3. Cost/latency optimisation: cheapest reliable model tier for scoring (e.g., Haiku-class vs Sonnet-class), batching, caching; benchmark cost per 1,000 leads scored.
4. Metrics: how to measure scorer quality (precision@k for the daily top-5 digest, correlation of score with quote-rate), and a minimal eval harness design.
5. Known pitfalls: score inflation, rubric drift, source bias (tenders always scoring higher than strata).

Output: (a) recommended scoring architecture v2 with justification, (b) YAML rubric improvements, (c) eval harness spec (can run as pytest), (d) decision rule for when to switch from LLM-only to hybrid ML.
```

## پرامپت ۸ — حقوق outreach خودکار در استرالیا (قبل از هر ارسال پیام)

**هدف:** خط قرمزهای قانونی دقیق برای فاز بعدی (ارسال خودکار ایمیل/SMS/تماس).

```
Context: Australian painting business planning AUTOMATED outreach (cold email, possibly SMS and calls) to leads found by a bot: builders, strata managers, property managers (B2B) and some homeowners (B2C). I need the precise legal boundaries before enabling any automated sending.

Research with citations to current legislation and ACMA guidance:
1. Spam Act 2003: does it apply to B2B cold email? What counts as "inferred consent" for a business email published on a website or tender document? Conspicuous publication exception — exact conditions. Required elements of every message (sender ID, functional unsubscribe, timing rules).
2. Do Not Call Register Act 2006: rules for calling businesses vs consumers; are numbers in tender documents callable; SMS treated as telemarketing?
3. Privacy Act 1988 + APPs (including the 2024-2026 reform tranche status): storing scraped personal data (names, emails, phones) in my CRM/SQLite — obligations for a small business (<$3M turnover exemption — does it still exist? current status of reforms), notification duties, data-in-Australia considerations.
4. ACCC/Fair Trading NSW rules on misleading outreach and door-knocking (unsolicited consumer agreements — do cooling-off rules apply to quotes initiated by my outreach?).
5. Penalties and real enforcement cases against small businesses (ACMA actions 2023-2026) to size the actual risk.

Output: (a) a decision tree per channel (email/SMS/call) and per audience (B2B/B2C): allowed / allowed-with-conditions / forbidden, (b) consent & suppression-list data model for my bot, (c) message template requirements checklist, (d) top 5 practices that keep me clearly safe.
```

## پرامپت ۹ — سیستم Outreach خودکار با تایید انسانی

**هدف:** طراحی موتور ارسالی که لید را به مکالمه تبدیل کند — بدون سوختن دامنه و بدون نقض قانون.

```
Context: My bot finds and scores painting leads (Sydney). Next phase: semi-automated outreach — the bot drafts personalised first-contact emails, I approve each one in Telegram before sending (human-in-the-loop is mandatory). Mostly B2B (builders, strata/property managers).

Research (2025-2026 state of the art):
1. Cold email infrastructure for a tiny sender (10-50 emails/day): separate sending domain vs subdomain, SPF/DKIM/DMARC setup, warmup — is warmup still effective/allowed with Google & Microsoft's 2024+ bulk-sender rules? Deliverability benchmarks for this volume.
2. Tooling: Instantly, Smartlead, lemlist, Apollo, or plain SMTP/Gmail API + own code — compare on AUD/month price, API access (my bot must create drafts programmatically), deliverability features, lock-in risk. For 10-50/day is a tool even justified?
3. LLM personalisation that works in construction/trades: what actually lifts reply rates (referencing the specific project/DA/tender vs generic flattery), evidence and benchmark reply rates for B2B trades outreach in Australia.
4. Sequence design: optimal touches/spacing for builders and strata managers, phone+email combo, when to stop (respecting Spam Act unsubscribe rules).
5. Measurement: reply/meeting/quote-rate benchmarks; minimum viable CRM states in SQLite; A/B testing with tiny volumes — what's statistically honest?

Output: (a) recommended stack with cost table and justification, (b) technical integration design (bot → draft → Telegram approve → send → track replies via IMAP), (c) 3 example email templates for builder RFQ follow-up / strata intro / post-DA homeowner, (d) KPI dashboard spec.
```

## پرامپت ۱۰ — ارتقای معماری Hunter Agent (کشف خودبهبود کانال)

**هدف:** Hunter از «جستجوگر هر ۶ ساعت» به یک agent یادگیرنده با حافظه و eval تبدیل شود.

```
Context: My "Hunter" agent (Claude + tool use: web_search, fetch_page, save_channel) runs every 6 hours to discover NEW lead channels for a Sydney painting business. It has a markdown memory file (hunter_memory.md). Discovered channels go to a human-approval queue in Telegram. Problems: repeats similar discoveries, memory is unstructured, no measure of channel quality over time, token costs unmonitored.

Research current best practice (2025-2026) for long-running autonomous discovery agents:
1. Memory architecture: unstructured markdown vs structured memory (SQLite facts + episodic log + periodic consolidation). Patterns from recent agent frameworks (Claude Agent SDK, LangGraph, etc.) for "don't rediscover what you know" — dedup strategies for semantic near-duplicates.
2. Self-evaluation: how should the agent score its own past discoveries (channel approved? produced leads? leads converted?) and feed that back into its search strategy? Multi-armed bandit / explore-exploit framing for choosing what to search next.
3. Search strategy: beyond generic web search — systematic enumeration strategies (competitor backlink analysis, "site:" patterns for council procurement pages, monitoring industry newsletters/LinkedIn), and which are automatable within Tavily/Serper/Brave APIs.
4. Cost control: token budgeting per run, model tiering (cheap model for triage, strong model for synthesis), caching fetched pages; realistic AUD cost per hunt run.
5. Evaluation harness: how to eval a discovery agent offline (golden set of known-good channels it should be able to find; regression tests for prompt changes).
6. Failure modes: hallucinated channels, dead links, ToS-violating sources — guardrail patterns.

Output: (a) Hunter v2 architecture diagram + component list, (b) structured memory schema (SQLite tables), (c) channel-quality scoring formula using approval/lead/conversion feedback, (d) eval plan, (e) migration steps from current code (agent.py, tools.py, hunter_memory.md).
```
