## خلاصهٔ بازار: چرا Painting-OS؟

هیچ ابزاری در بازار امروز **پایپ‌لاینِ یکپارچه، استرالیایی، مخصوص نقاشی** ارائه نمی‌دهد: مدیریت لید → کوتیشن هوشمند → فاکتور → پیگیری خودکار → وصول. رقبای اصلی:

| ابزار | قیمت | نقطهٔ ضعف |
|--------|-------|----------|
| **ServiceM8** | $0-79/ماه | بدون کوتیشن هوشمند، بدون پیدا کردن لید، بدون مخصوص نقاشی |
| **Tradify** | ~$70-80/یوزر/ماه | گران برای انفرادی، بدون AI، بدون لید |
| **AroFlo** | $120+/ماه (حداقل ۳ یوزر) | enterprise، $1000 onboarding، گران |
| **QuoteIQ** | $30-700 USD/ماه | آمریکایی، بدون استرالیایی‌سازی، بدون ایمیل لید |
| **hipages** | $129+/ماه + $20-50/لید | فقط لید، بدون ابزار مدیریت |
| **Airtasker+Oneflare** | 12-20% از مبلغ کار | خیلی گران، بدون ابزار |

**فاصلهٔ بازار:** ابزاری که ایمیل → کوتیشن → فاکتور → پیگیری → وصول را در یک جا، با قیمت ثابتِ مناسب برای نقاشِ انفرادیِ سیدنی انجام دهد. هدف قیمت: **$49-79/ماه AUD** (جایگزین ۳-۴ ابزار جداگانه).

## ۱۰ مرحلهٔ بعدی

### مرحله ۱: وایر کردنِ `/lead` در Telegram (۱-۲ روز)

**هدف:** فرمان `/lead` در تلگرام حالاً intake ساختاریافته بگیرد و کوتیشنِ تحقیق‌محور تولید کند.

**کارها:**
- [ ] `approval_channel.py` `_cmd_lead_parse` → وایر به `parse_lead_intake()`
- [ ] فرمت جدید: `/lead آشپزخانه 3BR | 6000 | lead.doer | 120 | interior | standard | residential`
- [ ] فرمت قدیمی: `/lead نام | مبلغ` → رفتار byte-identical (backward-compat)
- [ ] خروجی: `render_quote_html()` بجای `render_summary()` قدیمی
- [ ] تست: ارسالِ هر دو فرمت از تلگرام → خروجی درست

**پیش‌نیاز:** هیچ. فقط وایر.
**خروجی:** کوتیشن از تلگرام با نرخ‌های واقعی سیدنی.

### مرحله ۲: پر کردنِ ABN و اطلاعات کسب‌وکار (۱ ساعت)

**هدف:** اینویس‌ها واقعی شوند (نه تست).

**کارها:**
- [ ] ABN واقعی در `budgets.yaml` → `business.abn`
- [ ] نام تجاری واقعی → `business.trading_name`
- [ ] آدرس واقعی → `business.address`
- [ ] جزئیات بانک → `business.bank_details`
- [ ] بررسی: ایمیلِ تست یک کوتیشن → آیا Tax Invoice واقعی است؟

**پیش‌نیاز:** اطلاعات کسب‌وکار.
**خروجی:** فاکتور واقعی ATO-compliant.

### مرحله ۳: ایمیل لید (Gmail OAuth end-to-end) (۲-۳ روز)

**هدف:** ایمیل‌های جدید از مشتریان بالقوه → لید در سیستم.

**کارها:**
- [ ] Google Cloud Console → OAuth client ID (Internal, type="Testing")
- [ ] `OCTOPUS_WIRE_EMAIL=1` → فعال‌سازی
- [ ] اولین OAuth token → ذخیره در `state/email/gmail_token.json`
- [ ] تست: ارسال ایمیل تست → آیا `poll_and_digest()` آن را می‌بیند؟
- [ ] `parse_lead_from_email()` → تولید QuoteIntake از محتوای ایمیل
- [ ] اگر لید شناخته شد → خودکار `create_quote()` → notify در تلگرام

**پیش‌نیاز:** مرحله ۲ (business config), Google Cloud project.
**خطر:** Gmail quota = 1B/day (readonly) — برای انفرادی کافی.
**خروجی:** ایمیل → لید → کوتیشن خودکار.

### مرحله ۴: وب‌سایت/فرم لید (۳-۵ روز)

**هدف:** فرم تماس در وب‌سایت → ایمیل → سیستم (stage 3).

**تحقیق:**
- [ ] بررسی ابزارهای فرم: Tally (رایگان), Google Forms, Netlify Forms
- [ ] بررسی: آیا وب‌سایت فعلی دارد؟ اگرنه → ساده‌ترین راه؟

**کارها:**
- [ ] فرم ساده: نام، تلفن، ایمیل، نوع کار، توضیح
- [ ] فرم → ایمیل → `email_inbound.poll_and_digest()` → لید

**پیش‌نیاز:** مرحله ۳ (email pipeline).
**تحقیق بازار:** 76% از tradieها وب‌سایت دارند ولی بیشتر ساده هستند.
**خروجی:** مشتری بالقوه → فرم → ایمیل → کوتیشن.

## محدودیت‌ها (مثل همیشه)

- **propose-only:** هیچ ارسالی به مشتری بدون تأیید انسان
- **صفر راز جدید:** credentials فقط در `.env` / `budgets.yaml`
- **$0 stdlib:** وابستگی خارجی = صفر
- **backward-compat:** فرمت قدیمی `/lead` byte-identical
- **fail-soft:** هر تابع بدون data → {} یا [] بدون خطا
