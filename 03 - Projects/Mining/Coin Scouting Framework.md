# Coin Scouting Framework — چارچوب شکار و آزمایش کوین

## معیارهای انتخاب

1. الگوریتم CPU/ARM-پذیر (اجرا روی Orange Pi).
2. لانچ در **۳ ماه اخیر**.
3. **معیار اصلی: پتانسیل بقای آینده** — dev فعال، نقشه‌راه، جامعه واقعی.
4. مقاومت کوانتومی = امتیاز مثبت (نه شرط).

## قالب لاگ آزمایش (کپی per کوین)

```markdown
# آزمایش: <کوین> — شروع <YYYY-MM-DD>
- الگوریتم/فورک: __ · تاریخ لانچ: __ · نودهای درگیر: __
- هش‌ریت/نود: __ [To measure] · سکه/روز: __ [To measure]
- payback تخمینی: __ [اطلاعاتی — معیار قطع نیست]
- نقدشوندگی/مسیر فروش: __ [اطلاعاتی — نبودش در ماه‌های اول طبیعی است]

## Death-watch (معیار قطع — فقط این‌ها؛ D2)
- [ ] dev مرده: > __ هفته بدون commit/release (آستانه: ۸ هفته [Assumption])
- [ ] زنجیره متوقف / تولید بلوک نامنظم
- [ ] جامعه/شبکه عملاً خالی (کانال‌ها مرده، نود شبکه < __)
→ فقط اگر ≥۱ چک‌باکس قطعی شد: پیشنهاد ABANDON با evidence → verdict آری

## لاگ هفتگی
| هفته | سکه mined | dev activity | شبکه | نکته |
|---|---|---|---|---|
```

## قواعد

- **یک آزمایش فعال per نود-گروه**؛ همه اعداد سود `[To measure]` تا از دیتای واقعی بیاید.
- payback طولانی یا نقدنشدنی بودن فعلی ≠ دلیل قطع — فقط سیگنال‌های مرگ پروژه (بالا) قطع می‌کنند.
- فروش سکه‌های mined شده = تصمیم مالی → همیشه verdict انسانی (D-10).
