# معماریِ دو-ریله — شرکت جدا، خانواده جدا (رأیِ مالک 2026-07-16)

> حکمِ مالک: «حساب‌کتابِ شخصی‌ام با عباس از طریقِ PocketSmith باشد؛ برای خودِ شرکت از اپی
> استفاده کن که تمامِ کارهای مالیاتی را مرتب می‌کند — اینویس، ایمیل، کامل.»
> مکملِ [[RISK-DECISIONS|RD-003]]: اداره مالیات فقط یک طرف‌حساب دارد — خودِ شرکت.

## تصویرِ کلان

```
┌─────────────── ریلِ A: شرکت (موضوعِ ATO) ───────────────┐
│  دفترِ رسمی و مالیاتی = اپِ حسابداریِ حرفه‌ای (برنده‌ٔ تحقیق) │
│  bank feeds خودِ اپ · GST/BAS خودِ اپ · اینویس + ایمیل خودِ اپ │
│                                                          │
│  اختاپوس = رهبرِ ارکستر، نه دفتردار:                        │
│   • company_books.py → API اپ (خواندن + پیش‌نویسِ اینویس)   │
│   • موتورِ لید → پیش‌نویسِ اینویس مستقیم داخلِ اپ            │
│   • ارسالِ ایمیلِ اینویس = دکمهٔ خودِ اپ (با تأییدِ مالک)      │
│   • recon.py → چکِ متقابلِ مستقلِ بانک/اپ (ضدِ خطای پنهان)   │
│   • کارتِ تلگرام → وضعِ اینویس‌ها/BAS در /finance            │
└──────────────────────────────────────────────────────────┘

┌────────── ریلِ B: خانوادگی (آرمین ↔ عباس، غیرِ مالیاتی) ──────────┐
│  منبع = PocketSmith (همین حالا وصل است، read-only)                │
│  حلقهٔ موجود: /sync → /review → /books → /finance                 │
│  دفترِ داخلی (ledger_core + حسابِ 2200) = تسویهٔ خانوادگی           │
│  «کی به کی چقدر داده/بدهکار است» — هیچ ربطی به ATO ندارد          │
└──────────────────────────────────────────────────────────────────┘
```

## قواعدِ مرزی (تغییرناپذیر)

1. **دفترِ مالیاتی = فقط اپِ شرکت.** دفترِ داخلیِ اختاپوس (`ledger_core`) از این پس **دفترِ
   خانوادگی/عملیاتی** است، نه دفترِ ATO. GST/BAS فقط در اپ.
2. **پول هرگز توسطِ اختاپوس جابه‌جا نمی‌شود** — در هیچ‌کدام از دو ریل. اپِ شرکت هم فقط از
   طریقِ داشبوردِ خودش و دستِ مالک پرداخت می‌گیرد.
3. **نوشتن در اپ = فقط پیش‌نویس (propose-only).** اختاپوس اینویسِ DRAFT می‌سازد؛
   تأیید/ارسالِ ایمیل با مالک (داخلِ خودِ اپ یا با تأییدِ تلگرامیِ صریح).
4. **ارسالِ ایمیل کارِ خودِ اپ است** — اختاپوس SMTP ندارد و نخواهد داشت (safety-by-absence
   حفظ می‌شود؛ اپ با برندِ شرکت و قالبِ Tax Invoice ایمیل می‌زند).
5. **چکِ متقابلِ مستقل:** اختاپوس ماهانه bank-feedِ اپ را با دادهٔ خامِ PocketSmith/raw_store
   مقایسه می‌کند (recon تراکنش‌به‌تراکنش) — اگر اپ چیزی جا انداخت، کارتِ قرمز.
6. **PII/Secrets:** توکن‌های OAuth فقط در `.env` (gitignored)؛ هرگز در چت/گزارش/git.
7. رابطهٔ آرمین↔عباس در ریلِ B می‌ماند — خانوادگی، با ثبتِ 2200، بدونِ هیچ برچسبِ مالیاتی.

## نقشِ ماژول‌های موجود بعد از این تقسیم

| ماژول | نقشِ تازه |
|---|---|
| `pocketsmith_api` + `raw_store` + `txn_store` + `attributor` + `acct_review` | ریلِ B (خانوادگی) — بدونِ تغییر |
| `journal_bridge` + `ledger_core` | دفترِ داخلیِ خانوادگی/عملیاتی (نه ATO) |
| `recon` | چکِ متقابلِ هر دو ریل (بانک↔اپ، بانک↔PocketSmith) |
| `invoice.py` (پیش‌نویسِ محلی لید) | جایگزین می‌شود با پیش‌نویس مستقیم در اپ (`company_books.create_draft_invoice`) — محلی به‌عنوانِ fallbackِ آفلاین می‌ماند |
| `company_books.py` **(نو)** | آداپتورِ ریلِ A — رابطِ واحد با اپِ برنده |
| کارتِ `/finance` | دو بخش: ریلِ شرکت (اپ) + ریلِ خانوادگی (دفترِ داخلی) |

## چرخهٔ کاریِ مالک بعد از راه‌اندازی

- **شرکت:** لید می‌آید → اختاپوس پیش‌نویسِ اینویس را داخلِ اپ می‌سازد → تو در اپ (یا با تأییدِ
  تلگرام) approve/send می‌زنی → اپ ایمیل می‌کند و پیگیری/یادآوری می‌کند → BAS را اپ آماده
  می‌کند → حسابدارِ ثبت‌شده lodge می‌کند.
- **خانوادگی:** همان چهار دستورِ همیشگی: `/sync` → `/review` → `/books` → `/finance`.

## برنامهٔ راه‌اندازی (فازبندی)

- **C0 — انتخاب + خرید (مالک):** اشتراکِ اپِ برنده + ساختِ developer app (طبقِ راهنمای
  خروجیِ تحقیق). کلیدها در `.env`.
- **C1 — اتصالِ read-only:** `company_books.status()` سبز؛ کارتِ /finance بخشِ شرکت.
- **C2 — پیش‌نویسِ اینویس از لید:** موتورِ لید → DRAFT در اپ (propose-only، تستِ e2e با sandbox).
- **C3 — چکِ متقابل:** recon بانک↔اپ ماهانه + کارتِ هشدار.
- **C4 — BAS workflow:** خلاصهٔ BAS از اپ در تلگرام (فقط نمایش؛ lodge با حسابدار).

## 🏆 تصمیمِ ریلِ A: **Xero (استرالیا)** — Ignite + Custom Connection

تحقیقِ ۵-ایجنتی (`wf_d09b47b7`؛ Xero/MYOB/QBO/Zoho/Reckon با منابعِ وبِ روز) + قاضی. دلایلِ برد:
1. **Custom Connection = client_credentials**: توکنِ ۳۰دقیقه‌ای، **بدونِ refresh-token** —
   تنها گزینه‌ای که برای لپ‌تاپِ بی‌مراقب «توکن‌پرستاری» ندارد (QBO چرخشِ ~۲۴h،
   Reckon تک‌مصرف، MYOB توکنِ ۲۰دقیقه‌ای با چرخش).
2. endpointِ واقعیِ ایمیلِ اینویس (`POST /Invoices/{id}/Email`) — اپ خودش می‌فرستد.
3. عمیق‌ترین پشتهٔ AU: Simpler/full BAS با e-lodgment در UI، گزارش‌های GST، STP2،
   آمادهٔ Payday Super (از ۱ جولای ۲۰۲۶ اجباری).
4. bank feeds مستقیمِ بانک‌های بزرگِ AU داخلِ پلن.
5. مستندترین API + معافیتِ single-org از قیمت‌گذاریِ developerِ مارس ۲۰۲۶.

- **هزینه:** A$37 (Ignite، ≤۲۰ اینویس/ماه) + A$10 (Custom Connection) = **A$47/ماه**؛
  اگر اینویس بیشتر شد → Grow: جمعاً A$88/ماه. نایب‌قهرمان: MYOB Business Lite.
- **scopeها (granular، اجباری از مارس ۲۰۲۶):** accounting.transactions ·
  accounting.contacts · accounting.settings.read · accounting.reports.read · accounting.attachments.
- **محدودیت‌ها که دورشان طراحی کردیم:** reconcile و BAS-lodge فقط در UI (اختاپوس nudge
  می‌دهد) · webhook عملی نیست → poll با If-Modified-Since · سقفِ 60/min و 5k/day (زیر 1k/day
  طراحی شد) · ToS ۲۰۲۶: **آموزشِ مدلِ AI با دادهٔ Xero ممنوع** (inference آزاد).
