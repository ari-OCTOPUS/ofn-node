# DecisionRecord — kill switch RAM-only (یافته ۲۰)

**نوع: intentional · تاریخ: ۲۰۲۶-۰۸-۱۰**

## وضعیت
`node.killed` فقط RAM است؛ ری‌استارت آن را به False برمی‌گرداند (disengage).

## چرا عمدی
- ری‌استارت برای رفع یک state گیرکرده انجام می‌شود. اگر kill بعد از
  restart هم بماند، مالک که برای رفع قفل reboot کرده، دستگاه را هنوز
  منجمد می‌یابد — بدترین تجربه برای دقیقاً همان سناریویی که reboot
  برایش هست.
- audit trail بادوام است (`release_switch_events` + ledger) — خودِ حالت
  نیست که مهم است، تاریخچه‌اش هست.

## Trade-off (برجسته در panel)
بنر kill حالا صریح می‌گوید: «پس از راه‌اندازی مجدد، توقف خودبه‌خود
برمی‌دارد». مالک این را می‌داند و اگر بخواهد حالت بادوام، تصمیم می‌گیرد.

## حکم
**بدون تغییر.** RAM-only می‌ماند + یادداشت صریح در UI. تغییر به حالت
بادوام نیازمند حکم آری جداگانه است (چون fail-safe جهت را عوض می‌کند).
