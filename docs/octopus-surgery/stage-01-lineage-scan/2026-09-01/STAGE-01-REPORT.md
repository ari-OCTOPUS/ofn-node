# STAGE-01 — اسکن خط‌نسب روی `ofn-node`

تاریخ: 2026-09-01 · اجراکننده: ایجنت ابری Cursor · حالت: **PROPOSE_ONLY**

پاکت داور: `00-VANTAGE.yaml` — `scope=this_host_only` ·
`vantage=cursor-cloud-agent` · `may_authorize=false`.

این میزبان برد ۱۸۰ نیست. `eth0` این‌جا `192.168.0.180` نیست.
غیبت درخت والت روی دیسک یعنی `body_not_on_this_host`، نه «هرگز وجود نداشته».

## حکم یک‌جمله‌ای

چهار سند آپلودشده یک بدن والت/چک‌لیست را توصیف می‌کنند؛ این مخزن یک
خط‌نسب دیگر است. کار درست روی `ari-OCTOPUS/ofn-node` ساختن Envelope دوم
یا «رفع H1» به معنی باگ مالی NBB نیست — ثبت اختلاف، و حفظ قراردادی که
همین‌جا هست.

عدد زندهٔ تست در نثر این پرونده نوشته نمی‌شود. منبع:
`tools/repo_baseline.py --tests` و رسید `tools/gap_scan.py --tests`.

| منبع | چیست | روی این میزبان |
|---|---|---|

| CB Insights × Hugging Face (دو فایل) | نقشهٔ بازار + پنج گام اجرایی | دو فایل **بایت‌به‌بایت یکی** بودند؛ یک کپی ذخیره شد |

هش‌ها: `receipts/INTAKE-SHA256.json`. اگر فایل منبع عوض شود،
`tools/gap_scan.py` قرمز می‌شود.

## این خط‌نسب چه دارد — و چه ندارد

اندازه‌گیری مستقل در `CONCEPT-REGISTRY.json` است. ادعا =
`expected_status`. درخت = `derived_status`. اختلاف = شکست اسکن.

**اینجا هست (کد + تست):**

- H1 به معنی برداشت tender/buy.nsw (`C-H1-HARVEST`)
- outbox با کلید یکتای idempotency (`C-OUTBOX-IDEM`)
- envelope سه‌بردی فقط‌ورود (`C-EDGE-ENVELOPE` / `B-01` جزئی)
- propose-only روی لبه و حلقهٔ بقا (`B-05`, `C-SURVIVAL`)
- لجر hash-chain و `Ledger.verify` (`C-LEDGER`)
- گیت‌ها و سوییچ انتشار؛ `OCTOPUS_WIRE_*` فقط نیت (`C-GATES`, `C-WIRE-DRIFT`)
- رصدخانهٔ فیکسچر Brier (`C-OBS-FIXTURE`) — نه L1–L7 زنده
- هدرهای امنیتی در `http_api` (`C-SEC-HEADERS`)
- هشت حوزهٔ پوشش CLAUDE.md (`DOM-*`)

**اینجا نیست؛ بدن روی میزبان دیگر است:**

- runtime رصدخانه، hypothesis-engine، NBB-CP، چک‌لیست ۲۰۰، `_ops`،
  sync-engine، بازسازی Obsidian، VBAA، باگ مالی H1 (`C-H1-IDEM`)

**غایب واقعی روی همین خط‌نسب (نه والت):**

- اسکن pip ایجنت‌محور (`S-05`)
- توکن قابلیت به‌ازای تسک (`CBHF-1`)
- زنجیرهٔ شاهد روی حافظهٔ معنایی (`CBHF-2`)
- سرور MCP (`C-MCP`)

`O-3` و `S-04` و امضای مالک `owner_gated` می‌مانند. این اسکن بازشان نمی‌کند.

شمارش طبقهٔ STAGE-00 (`5+10+13+8+14`) به ۵۰ می‌رسد، ولی فایل آپلودشده فقط
شش شناسه را نام می‌برد. `STAGE00-C50` = `incomplete_enumeration`.
۴۴ شناسهٔ باقی ساخته نشد؛ حدس زدن آن‌ها یعنی همان خودتأییدی که §۸-ب منع می‌کند.

## تلاقی CBHF با این مخزن

پنج گام CBHF روی ماژول‌های **والت** نوشته شده‌اند
(`capability_flags`, `EvidenceStore._append_chain`, gateway). معادل‌های
این خط‌نسب چیز دیگری‌اند:

| گام CBHF | معادل اینجا | حکم پیشنهادی |
|---|---|---|
| ۱. توکن به‌ازای تسک | گیت سطح‌ماژول + کلیدهای ممنوع در observation.v1 | نساز مگر قرارداد لبهٔ موجود بشکند؛ ماژول جدید = خانوادهٔ دوم |
| ۲. زنجیره روی حافظه | `Ledger.verify` برای رویداد، نه حافظهٔ معنایی | capability-world-fit همین بازار را saturated دانسته — کلون Mem0/Letta نساز |
| ۳. مدل صوری + teeth | `test_kernel_purity` + denylist؛ TLA+ نیست | teeth همین اسکن است: مدل شکسته باید قرمز شود (`test_broken_expectation_is_visible`) |
| ۴. MCP به‌جای اسکرپ | کدی نیست؛ D-11 بازاریابی معوق | ردیف allowlist هم YELLOW است و از outbox رد می‌شود |
| ۵. استخر هزینهٔ ترکیبی | `quota` + `callbudget` | KPI-link نیست؛ ساخت پلتفرم هزینه از دستور این مرحله خارج است |

یعنی CBHF استراتژی والت را تأیید می‌کند، نه یک بک‌لاگ پیاده‌سازی روی
`ofn-node`. path A در capability-world-fit (دموی ممیزی فورنزیک) با
همین STAGE-01 هم‌جنس است.

## ترتیب — سه بدن، سه صف

STAGE-00 ترتیب والت را غیرقابل‌مذاکره می‌داند:

> Envelope و Run Store و اصلاح H1 → قرارداد لبه → بردها

روی **این** مخزن آن جمله این‌طور ترجمه می‌شود:

1. خانوادهٔ envelope دوم ساخته نشود. `board_events` قرارداد لبهٔ موجود است
   (ingest-only، بدون send).
2. «رفع H1» اینجا یعنی باگ مالی NBB نیست. H1 این مخزن harvest است و تست دارد.
3. Run Store واحد والت (`_ops/cognitive/run_store.py`) روی این میزبان نیست.
   JSONL بقا و SQLite برد جایگزین کامل آن نیستند و نباید با یک کلاس سوم
   «کامل» شوند مگر مالک بدن والت را به این خط‌نسب مهاجرت بدهد.
4. nftables / VLAN / ESP32 / امضای مالک از این VM قابل اجرا نیستند و
   owner_gated می‌مانند.
5. گام بعدی GREEN روی همین خط‌نسب: نگه داشتن `gap_scan` سبز؛ باز نکردن
   WIRE؛ نفرستادن چیزی به مشتری.

صف رأی مالک (NBB-V2/V3/V4، فاز ۸ رصدخانه، VBAA) از اسناد والت است.
این ایجنت به‌جای مالک تصمیم نمی‌گیرد، حتی اگر جواب بدیهی به نظر برسد.

## آنچه این مرحله کرد و نکرد

کرد: چهار منبع را با هش ثبت کرد؛ ادعاها را به مسیر فایل گره زد؛ تضادها را
با `resolution: null` نگه داشت؛ یک اسکن فقط‌خواندنی با تست منفی نوشت.

نکرد: هیچ فلگ خروجی روشن نشد. هیچ گیت بسته‌ای دور زده نشد. هیچ Envelope یا
Run Store جدیدی پیاده نشد. هیچ MCP یا توکن قابلیت ساخته نشد. هیچ رازی
خوانده نشد. هیچ چیزی به بیرون نرفت.
