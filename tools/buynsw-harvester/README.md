# OFN buy.nsw Harvester — پل دستی دادهٔ مناقصه‌های NSW

**مسئله:** `tenders.nsw.gov.au` (API قدیمی OCDS) مرده است و `buy.nsw.gov.au` نه API عمومی دارد نه به هیچ کلاینت غیر-مرورگری جواب می‌دهد (WAF از ایران، از curl، و حتی از ابزار fetch ایجنت — همه ۴۰۳).

**راه‌حل:** همان مرورگری که آری در سیدنی دارد، صفحه را برای WAF «یک انسان» جلوه می‌دهد. این اکستنشن فقط همان صفحه‌ای را می‌خواند که انسان باز کرده است — هیچ درخواست شبکه‌ای اضافه‌ای نمی‌فرستد، هیچ کد از راه دوری ندارد. صفحات buy.nsw سرور-رندر هستند (داده داخل خود HTML است)، پس متن تمیزتر و دقیق‌تر از عکس/OCR است و عکس لازم نیست.

## نصب (روی کامپیوتر سیدنی)

1. کروم را باز کن → آدرس: `chrome://extensions`
2. بالا-راست: **Developer mode** را روشن کن.
3. دکمهٔ **Load unpacked** → پوشهٔ `tools/buynsw-harvester` این repo را انتخاب کن.
4. آیکون اکستنشن را با سنجاق کنار نوار آدرس پین کن.

## گردش کار روزانه (۲ دقیقه)

1. در کروم سیدنی، صفحهٔ نتایج جستجوی مناقصه‌های buy.nsw را باز کن
   (URLهایی با `/opportunity/search` یا آرشیو `event=public.RFT.archived`).
2. روی آیکون اکستنشن بزن → **«برداشت از این صفحه»**.
   - شمارش «پیش‌نمایش نقاشی» فقط برای نمایش است؛ فیلتر نهایی سمت پایتون است.
3. اگر چند صفحه نتیجه هست: چک‌باکس **«صفحه‌بندی خودکار»** را بزن و دوباره «برداشت» بزن
   (حداکثر ۱۰ صفحه، با مکث ۵–۸ ثانیه‌ای بین صفحات — ریتم انسانی).
4. آخر کار: **«خروجی JSON»** → فایل `buynsw-harvest-<تاریخ>.json` ذخیره می‌شود.
5. فایل را به board138 منتقل کن (همان راه همیشگی) و آن‌جا اجرا کن:

```bash
cd ~/ofn-node
python tools/ingest_buynsw_batch.py buynsw-harvest-20260902-093000.json
```

خروجی، JSON حساب‌وکتاب است: `accepted` / `rejected_filter` / `rejected_dup` / `rejected_invalid`.
کد خروج `0` = موفق، `2` = بچ رد شد (هیچ چیزی نوشته نشده)، `1` = خطای عملیاتی.
مسیر DB از `--db` یا متغیر محیطی `OFN_PAINTING_DB` می‌آید، وگرنه پیش‌فرض نود.

رکوردها با `access_mode=owner_upload` و `evidence_status=unverified` و همان فیلتر/امتیازدهی
`h1_buysw` (کلیدواژه نقاشی + منطقه سیدنی + حداقل ارزش ۴۰۰ دلار + UNSPSC) ذخیره می‌شوند —
یعنی دقیقاً همان دروازه‌هایی که مسیر API مرده از آن‌ها می‌گذشت. اجرای دوبارهٔ همان بچ
بی‌ضرر است (idempotent): رکورد تکراری فقط شمرده می‌شود، دوباره ساخته نمی‌شود.

## حلقهٔ قفل‌کردن سلکتورها (یک‌بار، ۵ دقیقه)

سلکتورهای `content.js` heuristic هستند (لنگر به `/notices/` + بالا رفتن تا کارت +
الگوی برچسب:مقدار)، چون DOM زنده از پشت WAF دیده نمی‌شود. اگر «برداشت» گفت
«هیچ لینکی پیدا نشد» یا فیلدها خالی بودند:

1. روی همان صفحه → **«دامپ دیباگ DOM»** بزن.
2. فایل `buynsw-debug-*.json` را برای ایجنت بفرست (شامل `linkCount`، `sampleCards`، `nextPage`).
3. ایجنت سلکتورها را با DOM واقعی قفل می‌کند و نسخهٔ جدید می‌دهد.

اگر در DevTools → Network یک درخواست XHR به JSON دیدید، آن endpoint حتی از DOM بهتر است —
URL و پاسخش را بفرستید.

## قرارداد بچ (برای توسعه‌دهنده)

- Schema: `buynsw-harvest-batch/1` — تولیدکننده: `mapping.js` (پس‌زمینهٔ اکستنشن)،
  مصرف‌کننده: `ofn/agents/h1_buysw_dom.py`.
- تست `tests/test_h1_buysw_dom.py` با fixture دقیقاً به شکل خروجی اکستنشن، پل را پین می‌کند.
  تغییر کلید = تغییر هم‌زمان دو طرف + تست، در یک commit.
- لیست‌های کلیدواژه/منطقه در `mapping.js` فقط آینهٔ UI هستند؛ حقیقت فقط در
  `ofn/agents/h1_buysw.py` است.

## آنچه این ابزار عمداً نمی‌کند

- درخواست خودکار به buy.nsw نمی‌فرستد (WAF/ robots — و لازم هم نیست).
- داده‌ای را به هیچ سروری POST نمی‌کند؛ خروجی فقط یک فایل محلی است که خودتان ذخیره می‌کنید.
- فیلتر را نهایی نمی‌کند؛ فقط پایتون داخل نود حکم می‌دهد.
