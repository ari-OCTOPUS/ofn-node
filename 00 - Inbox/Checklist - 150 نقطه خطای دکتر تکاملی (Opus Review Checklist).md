# چک‌لیست ۱۵۰ نقطهٔ خطا — دکتر تکاملی (Opus Review Checklist)

> **کاربرد:** هر جلسهٔ طراحی/ساختِ دکتر (توسط Claude Opus یا هر ایجنت دیگر) باید قبل از تحویل، این لیست را مرور کند. هر مورد = چیزی که به‌تجربه (ledger + ممیزی ۰۷-۰۵) یا به‌تحلیل «محتملِ جاافتادن یا اشتباه‌شدن» است. ✅ = پوشش داده شد · ❌ = نقض · ⬜ = هنوز نامربوط به فاز جاری.

## الف) منبع حقیقت و stale-view (۱–۱۰)

- [ ] ۱. اعتماد به اسناد markdown به‌جای فایل‌سیستم + زمان‌بند زنده (اصل بنیادی §۱٫۵ سند اهداف).
- [ ] ۲. جا انداختن stable-read gate در «هر» نقطهٔ خواندن، نه فقط چک‌های حساس.
- [ ] ۳. تکیه به double-read: snapshotِ کهنهٔ خودسازگار ۵ بار یکسان خوانده می‌شود ولی غلط است — برای چک بایتی، اوراکل سمت ویندوز اجباری است (یافتهٔ زندهٔ ۰۷-۰۵).
- [ ] ۴. اجرای/خواندن فایلِ همین‌الان-ویندوز-ویرایش‌شده از همان mount بدون fresh-fd/inode تازه (ledger row-27).
- [ ] ۵. تفکیک‌نکردن `stale` (محیطی، وزن ۰) از `corrupt` (پایدار، CRITICAL).
- [ ] ۶. نشناختن خودترمیمیِ remount → ثبت FP دائمی به‌جای گذرا (row-40).
- [ ] ۷. اعتماد به mtime/size منجمدِ FUSE به‌عنوان «تغییر نکرده».
- [ ] ۸. فراموشی کش attr/page بعد از نوشتنِ out-of-band ویندوز.
- [ ] ۹. فرض اینکه Read tool و bash یک نمای یکسان از فایل می‌بینند (مسیر و کش جدا دارند).
- [ ] ۱۰. یافتهٔ stale بدون `ledger_ref` قابل‌ممیزی.

## ب) امنیت secretها (۱۱–۲۰)

- [ ] ۱۱. اسکن secret فقط روی `.md` — سه `.env` زنده و wallet/key دقیقاً همین‌طور جا ماندند.
- [ ] ۱۲. echo محتوای secret در لاگ، چت، ledger یا آرتیفکت (فقط مسیر/اندازه مجاز است).
- [ ] ۱۳. **فرستادن محتوای فایل‌ها به Fugu API بدون فیلتر secret — نشت مستقیم به سرویس بیرونی.**
- [ ] ۱۴. نادیده‌گرفتن `.agentignore` در هر لایه (اسکنر، حلقه، آرتیفکت).
- [ ] ۱۵. ماندن secret در حافظه/کش بین‌چرخه‌ایِ حلقهٔ فکری.
- [ ] ۱۶. نمایش مسیر دقیق فایل secret در آرتیفکت انسانیِ قابل‌share.
- [ ] ۱۷. روشن‌کردن هر بخشی از ستون ۳ قبل از بسته‌شدن گیت rotation (۴ ردیف CRITICAL باز).
- [ ] ۱۸. «بسته» اعلام‌کردن گیت بدون اجرای واقعی gitleaks.
- [ ] ۱۹. الگوهای secret فقط-ASCII — کلیدِ چسبیده به متن فارسی/RTL جا می‌ماند.
- [ ] ۲۰. ذخیرهٔ API key خودِ Fugu داخل vault (باید بیرون vault و در چرخهٔ rotation باشد).

## پ) PII و داده‌های بیومتریک (۲۱–۳۰)

- [ ] ۲۱. شمردن ~۶۰MB دادهٔ ژنتیکی به‌عنوان «فایل عادی» به‌جای CRITICAL.
- [ ] ۲۲. فراموشی نسخه‌های تکراری PII در `_Duplicates`.
- [ ] ۲۳. آپلود هر PII به هر API بیرونی (Fugu، web، هرچه) — نقض مطلق laptop-only.
- [ ] ۲۴. `.gitignore` بدون الگوهای DNA/بیومتریک → PII وارد تاریخچهٔ git ابدی می‌شود.
- [ ] ۲۵. گزارش آماری‌ای که خودش PII را بازسازی/لو دهد.
- [ ] ۲۶. نخواندن خط‌مشی privacy در `ARCHITECT_CHARTER` قبل از طراحی آشکارساز.
- [ ] ۲۷. پرچم PII با شدتی پایین‌تر از CRITICAL.
- [ ] ۲۸. تشخیص PII فقط با پسوند فایل، نه امضا/اندازه/مسیر (فایل rename شده جا می‌ماند).
- [ ] ۲۹. عکس‌های تلگرام حاوی چهره/مدرک در `08 - Assets` — خارج از رادار PII.
- [ ] ۳۰. حذف/جابه‌جایی خودکار PII به‌جای پیشنهاد + verdict (صفر-حذف قاعدهٔ vault است).

## ت) git و rollback (۳۱–۴۰)

- [ ] ۳۱. فعال‌کردن L2 قبل از `git init` — verdict آری صریحاً مشروط است.
- [ ] ۳۲. `git init` بدون `.gitignore` سختِ از-قبل-نوشته → اولین `git add` همهٔ venv/secret/DNA را stage می‌کند.
- [ ] ۳۳. commit پایه بدون اسکن secret → افشا در تاریخچهٔ ابدی، بدتر از نبودِ git.
- [ ] ۳۴. دست‌زدن/‌dedup داخل `.git` و `_code` (قاعدهٔ ۴ قانون اساسی — رپو خراب می‌شود).
- [ ] ۳۵. Revert سطح ۳ بدون تعریف دقیقِ «آخرین جهش» (کدام commit؟ کدام فایل‌ها؟).
- [ ] ۳۶. فرض «هر جهش = یک commit اتمیک» بدون enforce کردنش در کد.
- [ ] ۳۷. rollback فایل‌ها ولی نه stateِ زمان‌بند — تسک‌های زنده داخل git نیستند.
- [ ] ۳۸. CRLF/LF ویندوز → false-diff انبوه و commitهای شلوغ.
- [ ] ۳۹. نام‌فایل‌های فارسی/RTL در git روی ویندوز (encoding مسیر، `core.quotepath`).
- [ ] ۴۰. کندشدن/ایندکس‌شدن `.git` توسط Obsidian — محل repo و exclude باید سنجیده شود.

## ث) drift و آشتی حقیقت (۴۱–۵۰)

- [ ] ۴۱. مقایسهٔ رجیستری با HANDOFF به‌جای خروجیِ زندهٔ زمان‌بند (هر دو سند می‌توانند هم‌زمان کهنه باشند).
- [ ] ۴۲. فرضِ دسترسی برنامه‌ای به لیست تسک‌های زمان‌بند بدون تأیید مسیر واقعی API/state (تصمیم باز §۷.۳ لایهٔ شناخت).
- [ ] ۴۳. نادیده‌گرفتن تسک‌های disabled/paused در آشتی (فقط enabled شمردن).
- [ ] ۴۴. آمادگی‌نداشتن برای resetِ ناگهانی ناوگان وسط چرخهٔ فکری (دو بار رخ داده — حفرهٔ bootstrap).
- [ ] ۴۵. HEARTBEAT یک‌طرفه به‌جای دوطرفه (watchdog بدون پاسخ = سکوت نامرئی).
- [ ] ۴۶. هر drift را «خطا» شمردن — بعضی drift جهش است و باید به ستون ۲ برود، نه kill شود (Research Radar).
- [ ] ۴۷. بازسازی تسک ratified غایب از حافظه به‌جای متن کامل در `RATIFIED-TASKS`.
- [ ] ۴۸. تغییر cron/پرامپت تسک‌ها توسط خود حلقه بدون verdict (خارج از هر whitelist).
- [ ] ۴۹. ساخت لایهٔ سرکوب/وضعیت موازی دوم — تک‌منبع سرکوب درسِ قفل‌شدهٔ تابلو v10 است.
- [ ] ۵۰. sync تمام‌عیار هر بار به‌جای دلتا-محور (بلوک Delta در SYSTEM-STATE).

## ج) ستون ۱ — چک‌های قطعی (۵۱–۶۰)

- [ ] ۵۱. خزیدن قضاوت LLM به داخل چک‌های «قطعی» (باید صفر-LLM بماند).
- [ ] ۵۲. نوشتن هر چیزی حین چک، جز خروجی regenerable مصوب (صفر-نوشتن).
- [ ] ۵۳. suppress کردن یافته بدون `ledger_ref` و verdict.
- [ ] ۵۴. ادغام raw و effective در یک نمره — هر دو باید جدا گزارش شوند.
- [ ] ۵۵. hard-code کردن آستانه‌ها (کهنگی، bloat) بدون تصمیم آری (§۷.۴ لایهٔ شناخت).
- [ ] ۵۶. محاسبهٔ «کهنگی» با timezone غلط — vault به‌وقت سیدنی زندگی می‌کند.
- [ ] ۵۷. تشخیص تکراری با نام فایل به‌جای hash (فقط byte-identical تکراری است — قاعدهٔ ۴ قانون).
- [ ] ۵۸. اعمال چک فرانت‌متر روی مسیرهای خارج از scope (مثل `scripts/`) → نویز کاذب.
- [ ] ۵۹. تطبیق wikilink بدون نرمال‌سازی RTL/ZWNJ → لینک سالم «شکسته» گزارش می‌شود.
- [ ] ۶۰. شمردن `_Archive`/`_Duplicates` در متریک‌های سلامت (محدودهٔ منفی‌اند).

## چ) ستون ۲ — جهش‌نامه و چرخهٔ تکامل (۶۱–۷۰)

- [ ] ۶۱. اصلاح فوریِ انحراف به‌جای قرنطینه — کل ایدهٔ ستون ۲ همین تفکیک است.
- [ ] ۶۲. overwrite شدن جهش‌نامه — باید append-only باشد مثل EXPERIENCE-LEDGER.
- [ ] ۶۳. «قرنطینه‌کردن» جهشِ روی invariant به‌جای halt فوری — invariant قرنطینه ندارد.
- [ ] ۶۴. `mutation-id` بدون schema یکتا/تاریخ‌دار → تصادم و گم‌شدن ارجاع.
- [ ] ۶۵. ارزیابی جداگانهٔ جهش‌های همبسته که فقط باهم معنا دارند.
- [ ] ۶۶. نبود «حافظهٔ ایمنی»: جهشِ reverted دوباره کشف و دوباره قرنطینه می‌شود، بی‌نهایت بار.
- [ ] ۶۷. قرنطینه بدون TTL/مهلت ارزیابی → انباشت ابدیِ جهش‌های معلق.
- [ ] ۶۸. promote بدون سنجش قبل/بعد با متریک برازندگی (§۶ سند اهداف).
- [ ] ۶۹. معاف‌کردن خودِ جهش‌نامه از چک‌های ستون ۱ (فرانت‌متر، secret، سلامت).
- [ ] ۷۰. برخورد با ناوگان Research Radar به‌عنوان drift-برای-حذف به‌جای جهشِ زندهٔ نیازمند ارزیابی.

## ح) تابع برازندگی (۷۱–۸۰)

- [ ] ۷۱. پذیرش proxy درآمد بدون شاهد مشخص → reward hacking (قید صریح §۹.۲ مصوب).
- [ ] ۷۲. بهینه‌سازی «سادگی» که گام ایمنی/گیت را هم حذف کند — سادگی روی invariant ممنوع.
- [ ] ۷۳. ادعای «سریع‌تر شد» بدون baseline اندازه‌گیری‌شدهٔ قبل.
- [ ] ۷۴. ترکیب دو معیار مصوب (درآمد + سادگی) بدون قاعدهٔ وزن/تعارض — جهشی که یکی را بهتر و دیگری را بدتر کند چه می‌شود؟
- [ ] ۷۵. Goodhart: وقتی متریک هدف شود، متریک خراب می‌شود — چرخهٔ بازبینی خود تابع برازندگی لازم است.
- [ ] ۷۶. جهش برازنده برای یک پروژه ولی مضر برای پروژهٔ دیگر — دامنهٔ اثر باید per-project سنجیده شود.
- [ ] ۷۷. اثر تأخیریِ درآمد (لید امروز → پول هفته‌ها بعد) — پنجرهٔ سنجش کوتاه = نتیجهٔ کاذب.
- [ ] ۷۸. پذیرش خوداظهاری Fugu («این جهش مفید است») به‌عنوان شاهد برازندگی.
- [ ] ۷۹. محاسبهٔ Fitness Proxies از SYSTEM-STATE کهنه به‌جای اجرای تازه.
- [ ] ۸۰. نبود مقایسه/کنترل: «بعد از جهش بهتر شد» بدون بررسی اینکه بدون جهش هم بهتر می‌شد.

## خ) ادغام Fugu API (۸۱–۹۰)

- [ ] ۸۱. اتکا به قیمت/رفتار API از حافظهٔ مدل به‌جای راستی‌آزمایی روز (قیمت‌ها تغییر می‌کنند؛ promo ژوئیه تمام می‌شود).
- [ ] ۸۲. نبود fallback برای down/deprecated شدن Fugu — vendor lock-in بدون پلن B (سازگاری OpenAI-API = مهاجرت آسان، ولی فقط اگر کد به آن قفل نشده باشد).
- [ ] ۸۳. مدیریت‌نکردن rate-limit/429/5xx با backoff — حلقه در خطا نباید تند-تند retry بزند.
- [ ] ۸۴. عبور بی‌صدا از آستانهٔ ۲۷۲K context → پرش قیمت به $۱۰/$۴۵ بدون اطلاع.
- [ ] ۸۵. تزریق کل vault یا فایل‌های عظیم به context به‌جای خلاصهٔ SYSTEM-STATE.
- [ ] ۸۶. نگه‌داشتن حافظهٔ بین‌چرخه‌ای فقط در context — با اولین قطع session همه می‌میرد؛ persist در ledger/فایل.
- [ ] ۸۷. اعتماد به ساختار خروجی Fugu بدون schema validation — یک پاسخ بدفرم نباید حلقه را خراب کند.
- [ ] ۸۸. نبود معیار هم‌گرایی/توقف → حلقهٔ think بی‌پایان روی یک مسئله (متریک §۸ سند اهداف).
- [ ] ۸۹. استفاده از Ultra برای پایش روتین یا مدل سبک برای ارزیابی جهش — routing هزینه-کیفیت معکوس.
- [ ] ۹۰. retry بدون idempotency-key → یک «دستور بعدی» دو بار اعمال می‌شود.

## د) هزینه و بودجه (۹۱–۱۰۰)

- [ ] ۹۱. سقف روزانه «تعریف‌شده در سند» ولی enforce-نشده در کد — سقف باید پیش از اولین کال چک شود.
- [ ] ۹۲. شمارش هزینه با تخمین توکن به‌جای usage واقعیِ برگشتی از API.
- [ ] ۹۳. استفاده‌نکردن از cached input ($۰٫۵ در برابر $۵) برای پرامپت‌های تکرارشونده.
- [ ] ۹۴. هزینهٔ ابزارهای داخلی Fugu (web_search) جدا از توکن — در سقف لحاظ نشود.
- [ ] ۹۵. فراموشی اینکه پلن Max با استفادهٔ تعاملی خود آری مشترک است — حلقه می‌تواند سهم آری را بخورد.
- [ ] ۹۶. توقف در سقف بدون ذخیرهٔ state چرخهٔ نیمه‌تمام → از‌سرگیری = دوباره‌کاری و هزینهٔ مضاعف.
- [ ] ۹۷. نمایش هزینهٔ انباشته در آرتیفکت با تأخیر/کهنگی — آری باید «الان» را ببیند.
- [ ] ۹۸. خطای تبدیل توکن↔دلار (نرخ ورودی/خروجی/کش متفاوت‌اند؛ تک‌نرخ حساب‌کردن غلط است).
- [ ] ۹۹. بنای بودجه بر «ماه دوم رایگان» — بعد از ژوئیه هزینهٔ واقعی برمی‌گردد.
- [ ] ۱۰۰. نبود آلارم نرم (مثلاً ۸۰٪ سقف) قبل از توقف سخت.

## ذ) استقلال L2 و whitelist (۱۰۱–۱۱۰)

- [ ] ۱۰۱. whitelist مبهم («فایل‌های کم‌اهمیت») به‌جای الگوهای مسیر/عمل صریح و بسته.
- [ ] ۱۰۲. دورزدن whitelist با مسیر نسبی/لینک/rename — نرمال‌سازی مسیر قبل از چک.
- [ ] ۱۰۳. فراموشی سقف روزانهٔ L2=۳ از منشور استقلال — L2 نامحدود نیست.
- [ ] ۱۰۴. اقدام مرکب: هر گام جدا داخل whitelist ولی ترکیبشان اثر خارج-از-whitelist دارد.
- [ ] ۱۰۵. self-modification: حلقه پرامپت/کد/whitelist خودش را جهش بدهد — این invariant است.
- [ ] ۱۰۶. escalation ضمنی: خروجی L2 چیزی بسازد (تسک، اسکریپت) که خودش با اختیار بالاتر عمل کند.
- [ ] ۱۰۷. گزارش فقط-استثنا بدون ثبت کامل موفق‌ها در ledger — بی‌صدا ≠ بی‌ثبت.
- [ ] ۱۰۸. تعریف whitelist در دو جا (سند + کد) که از هم drift کنند — تک‌منبع.
- [ ] ۱۰۹. اقدام خودکار هم‌زمان با جلسهٔ تعاملی آری روی همان فایل‌ها → تصادم ویرایش.
- [ ] ۱۱۰. محاسبه‌نکردن شاخص استقلال (متریک مصوب §۸) → ارتقا/تنزل سطح بدون داده.

## ر) دکمهٔ اضطراری سه‌سطحی (۱۱۱–۱۲۰)

- [ ] ۱۱۱. دکمهٔ UI بدون مسیر halt واقعی در backend — دکمه‌ای که فقط «به نظر» متوقف می‌کند.
- [ ] ۱۱۲. polling کند: بین فشردن و توقف، چند اقدام دیگر اجرا می‌شود — چک halt-flag قبل از «هر» اقدام.
- [ ] ۱۱۳. فعال‌بودن سطح ۳ (Revert) وقتی git هنوز آماده نیست — باید disabled و علتش نمایان باشد.
- [ ] ۱۱۴. ابهام دامنهٔ سطح ۲ (Kill): فقط ناوگان دکتر یا همهٔ تسک‌های زمان‌بند؟ باید صریح قفل شود.
- [ ] ۱۱۵. persist نشدن حالت halted → با restart جلسه/ناوگان، حلقه بی‌صدا دوباره زنده می‌شود.
- [ ] ۱۱۶. تست‌نشدن halt-on-invariant-violation خودکار — kill switch فقط دستی نیست.
- [ ] ۱۱۷. نبود مسیر دوم توقف (فایل flag / دستور چت) وقتی خود آرتیفکت خراب یا offline است.
- [ ] ۱۱۸. resume بعد از halt بدون verdict صریح آری — halt باید sticky باشد.
- [ ] ۱۱۹. توازن غلط تأیید: لمس اشتباه = kill ناخواسته، یا برعکس تأییدِ چندمرحله‌ای که در بحران کُند است.
- [ ] ۱۲۰. سه سطح بدون تمایز بصری/متنی واضح — در لحظهٔ استرس، آری نباید فکر کند کدام دکمه چیست.

## ز) آرتیفکت انسانی (۱۲۱–۱۳۰)

- [ ] ۱۲۱. خواندن دادهٔ آرتیفکت از mdهای کهنه به‌جای SYSTEM-STATE/زمان‌بند زنده — همان stale در UI.
- [ ] ۱۲۲. اتکای state حیاتی به localStorage-only (سابقهٔ مانیفست خالی/reset) — state حیاتی در vault.
- [ ] ۱۲۳. فرض شکل خروجی MCP بدون probe واقعی — `structuredContent` در آرتیفکت با نمای چت فرق دارد.
- [ ] ۱۲۴. نشت secret/PII/مسیر حساس در نمای آرتیفکت (قاعدهٔ Project-F: حتی نام/مسیر بعضی پروژه‌ها ممنوع).
- [ ] ۱۲۵. خراب‌بودن RTL/فونت فارسی — اعداد و جهت متن در جدول‌ها به‌هم می‌ریزد.
- [ ] ۱۲۶. refresh فقط-دستی — آرتیفکت باید در باز‌شدن، دادهٔ تازه بکشد (Reload header موجود است؛ دکمهٔ تکراری نساز).
- [ ] ۱۲۷. stream نشدن چرخهٔ فعلی/فرضیه/هزینه — خواستهٔ صریح آری: «الان دارد به چه فکر می‌کند».
- [ ] ۱۲۸. writable شدن آرتیفکت فراتر از دکمه‌های کنترل — قرارداد: فقط-خواندنی + کنترل حیاتی.
- [ ] ۱۲۹. عدم sync نسخهٔ HTML داخل vault با آرتیفکت Cowork (درس تابلوی تمرکز — hash یکسان).
- [ ] ۱۳۰. نمایش وضعیت «سبز» بدون timestamp تازگیِ داده — سبزِ کهنه خطرناک‌تر از قرمزِ صادق است.

## ژ) دفاع تزریق (۱۳۱–۱۴۰)

- [ ] ۱۳۱. عبور خروجی web_search (داخل Fugu) به‌عنوان دستور به حلقه — همهٔ محتوای بیرونی = داده.
- [ ] ۱۳۲. فراموشی اینکه خود نوت‌های vault ورودیِ نیمه‌بیرونی‌اند — تسک‌های تلگرام/اسکات‌ها در آن می‌نویسند؛ متن نوت هم قرنطینه می‌خواهد.
- [ ] ۱۳۳. جهش‌نامه به‌عنوان بردار تزریق: «توصیف جهش» مخرب که در چرخهٔ ارزیابی به‌عنوان دستور اجرا شود.

- [ ] ۱۳۵. دستور جعلیِ «از طرف آری» داخل فایل/دیجست — verdict فقط از کانال تعاملی معتبر است، نه متن فایل.
- [ ] ۱۳۶. دنبال‌کردن لینک‌های خارجی داخل دیجست‌های اسکات بدون قرنطینه.
- [ ] ۱۳۷. نام فایل/فرانت‌متر به‌عنوان payload (نامی که خودش instruction است).
- [ ] ۱۳۸. بازتاب (echo) دستور تزریقی در خروجی Fugu که چرخهٔ بعد آن را بخورد — حلقهٔ آلودگی خودتقویت‌شونده.
- [ ] ۱۳۹. فیلتر تزریق فقط-انگلیسی — payload فارسی/RTL/مخلوط از فیلتر رد می‌شود.
- [ ] ۱۴۰. تغییرپذیریِ system-prompt حلقه توسط جهش/ورودی — پرامپت هسته invariant است.
