# طرح — خودمختاریِ اجرای کد (رأی مالک «جدی می‌خواهم»)

> **وضعیت: طرح — propose-only. هیچ‌چیز فعال نمی‌شود تا رأیِ گام‌به‌گامِ مالک.** این سند نقشه + سیفگاردهاست تا با آگاهیِ کامل تصمیم بگیری، نه تستِ خودکار.

## ۰. 🫀 قانونِ قلب — قانونِ اساسیِ خودمختاری (رأی مالک ۲۰۲۶-۰۷-۱۱)

> **«یک قانون که به قواعدِ اساسی و اهداف آسیب نزند، و رییسش قلب و ضربانش باشد.»**

حلقهٔ خودمختاریِ کد یک **اندامِ زیرِ فرمانِ قلب** است — هرگز خودش تصمیم نمی‌گیرد کِی بزند؛ **قلب اجازه می‌دهد.** پنج بندِ تخطی‌ناپذیر:

۱. **اجازهٔ قلب (precondition):** فقط وقتی قلب آرام است اجازه دارد — استرسِ ارگانیسم < آستانه، σ در ناحیهٔ امن، velocity در باندِ زیست‌پذیر، **صفر «ترس»**. ترس/بی‌ثباتی → **freeze**. *(همین حالا نطفه‌اش هست: ترس، `auto_approve.self_test` را متوقف می‌کند — این بند فقط رسمی‌اش می‌کند.)*
۲. **کادنسِ قلب (rate):** refractory از **دورهٔ ضربانِ قلب** می‌آید، نه ساعتِ ثابت. قلب کند بتپد (استراحت) → خودمختاری هم کندتر. قلب پرتپش/تحتِ فشار → خوابیده.
۳. **مرزِ اساسی (§قانون‌اساسی):** هرگز قواعدِ اساسی را نقض نمی‌کند — deny-list سخت: `.git`/ژنوم/ledger/سکرت/پول/schema/kill-switch/σ/human_append_guard. تغییرِ این لیست = رأیِ مالک.
۴. **خدمت به هدف (اهداف):** فقط patchی که به هدفِ واقعیِ پروژه خدمت کند (`goal_directed` — همان لایه‌ای که دایره‌ای‌های درخودمانده را دور می‌ریزد). آسیب به اهداف = رد.
۵. **کیل‌سوئیچِ قلب:** قلب بایستد (halt/freeze) یا σ بحرانی شود یا کانالِ حیاتی باز شود → خودمختاری **فوراً می‌خوابد** (fail-closed).

**نتیجه:** قلب یک دروازهٔ **هشتمِ زنده و هومئوستاتیک** روی ۷ سیفگاردِ §۳ است. حتی اگر همه‌چیز فنی سبز باشد، اگر قلب ناآرام باشد، دست نمی‌زند. این دقیقاً «جهش روی مرزِ نظم/فروپاشی، با ترمزِ زیستی».

## ۱-الف. چرا این سخت‌ترین خط است
خودتغییریِ کدِ بازگشتی (recursive self-modification) تنها قابلیتی است که کلِ معماریِ ایمنیِ اختاپوس برای **جلوگیری‌اش** ساخته شده: §۷، مرزِ `auto_approve`، لدرِ ریسک (کد=قرمز). دلیلِ واقعی: یک patchِ بد + یک حلقهٔ خودکار = فروپاشیِ خودِ ارگانیسم، بدونِ انسان در مسیرِ بحرانی. پس اینجا با احتیاطِ حداکثری طراحی می‌کنیم.

## ۱. خبرِ خوب: ۹۰٪ ماشینِ امن از قبل هست
حلقهٔ امن از قطعاتِ **موجود** ساخته می‌شود — فقط سیم‌کشیِ گام‌به‌گام لازم است:

| قطعه | نقش در حلقه | وضعیت |
|---|---|---|
| `cortex/improve` + `vault_updater.py` | **پیشنهاد**: مغز patch را می‌نویسد (هرگز دیسک) | ✅ هست (propose-only) |
| worktree ایزوله + `run_all` | **شادو-تست**: patch در درختِ جدا، سوییتِ کامل | ✅ الگو هست (همین جلسه بارها) |
| `capability_gate` (CAPABILITY-OK) | گیت: فقط با سوییتِ سبزِ fingerprint‌دار | ✅ هست |
| تلگرام + `human_append_guard` | **تأییدِ انسانی**: تپِ ✅ = توکنِ HMAC جعل‌ناپذیر | ✅ هست (همین جلسه) |
| `vault_updater` EffectorGate | **تنها نویسنده**: اعمالِ کنترل‌شده | ✅ هست |
| git | **rollback**: revert خودکار روی قرمز | ✅ هست |

## ۲. دو سطح — تفاوتشان «انسان در مسیر» است

### 🟢 سطح A — خودمختاریِ کمکی (انسان دروازهٔ تأیید را نگه می‌دارد) — **پیشنهادی**
```
مغز patch می‌نویسد → شادو-تست (worktree + سوییتِ کامل) → اگر سبز:
   کارتِ تلگرام با diff + نتیجهٔ تست → تپِ ✅ تو (HMAC) →
   EffectorGate اعمال می‌کند → canary (سوییتِ زنده) → سبز؟ بماند / قرمز؟ auto-revert
```
- «خودش با api و یادگیریِ مغزش اعمال می‌کند» ✅ — ولی **تو در نقطهٔ بحرانی تأیید می‌کنی.**
- تجربه‌ای که خواستی را می‌دهد، بدونِ عبور از خطِ قرمزِ recursive.

### 🔴 سطح B — خودمختاریِ کامل (بدونِ تأییدِ انسان)
```
مغز patch می‌نویسد → تست → خودش اعمال می‌کند (بدونِ تپِ تو)
```
- این **recursive self-modification** است = عمیق‌ترین خطِ قرمز.
- **توصیهٔ صادقانه: نه — یا فقط برای یک کلاسِ ذره‌ای، برگشت‌پذیر، whitelist‌شده** (مثلاً فقط microcopyِ یک فایلِ مشخص)، آن هم با همهٔ گاردهای §۳ + سقفِ روزانه + freeze خودکار.

## ۳. پشتهٔ سیفگارد (هر سطح، تخطی‌ناپذیر)
۱. **allowlistِ محدودهٔ فایل** — فقط چند فایلِ نامیده‌شده (مثلاً `telegram_center/*`, `cortex/*` اغیرِ حساس). **هرگز:** `.git`, ژنوم/ledger, secret/`.env`, `budget/*` پول, schema, kill-switch, σ, `human_append_guard`.
۲. **شادو-اول** — هر patch اول در worktree ایزوله، سوییتِ **کامل** سبز؛ قرمز = هرگز به درختِ زنده نمی‌رسد.
۳. **تنها نویسنده** — فقط EffectorGate می‌نویسد (cognition ≠ effect).
۴. **دروازهٔ تأیید** (سطح A) — تپِ ✅ با توکنِ HMAC؛ بدونِ آن هیچ اعمال.
۵. **canary + auto-rollback** — بعدِ اعمال، سوییتِ زنده؛ قرمز → `git revert` خودکار + freezeِ خودمختاری + هشدارِ فوری.
۶. **refractory + سقف** — حداکثر یک اعمال در هر پنجره (مثلاً ۲۴h)، سقفِ روزانه.
۷. **کیل‌سوئیچ + لِجِرِ append-only** — پاک‌کردنِ `ACTIVATION-CODE-AUTONOMY.flag` = توقفِ آنی؛ هر اعمال با diff/تست/rollback در ledger.

## ۴. رجیستری ریسک (صادقانه)
| ریسک | مهار |
|---|---|
| patchِ بد که تست‌ها نگیرند | canary زنده + auto-revert + freeze؛ allowlistِ فایلِ کم‌خطر |
| تپِ اشتباه/جعلی | HMAC + owner-only + refractory + diff در کارت پیش از تپ |
| حلقهٔ خودتشدید (runaway) | سقفِ روزانه + refractory + کیل‌سوئیچ + freeze روی هر قرمز |
| گسترشِ محدوده (scope creep) | allowlistِ فایلِ hardcode؛ تغییرِ allowlist = رأیِ جدا |
| فسادِ ژنوم/پول | این‌ها در deny-list؛ EffectorGate ردشان می‌کند |

## ۵. مسیرِ ساختِ گام‌به‌گام (هر گام رأیِ جدا)
- **P1 — Shadow patch-tester (۱۰۰٪ امن، صفر اعمال):** ماژولی که یک patch را در worktree ایزوله می‌زند، سوییت را می‌گیرد، و نتیجه+diff را برمی‌گرداند. هیچ نوشتنی به درختِ زنده. → **اینجا شروع می‌کنیم؛ می‌بینی مغز patch می‌نویسد و خودش تست می‌کند، بی‌هیچ خطری.**
- **P2 — سطح A، نیمه‌دستی:** خروجیِ P1 → کارتِ تلگرام با diff → تپِ ✅ → **من merge می‌کنم** (هنوز دستِ انسان روی merge).
- **P3 — سطح A، خودمختار:** تپِ ✅ → EffectorGate خودش merge می‌کند + canary/rollback. **این همان «خودش اعمال می‌کند» است، با تأییدِ تو.**
- **P4 — سطح B (فقط اگر اصرار داری):** روی یک کلاسِ ذره‌ایِ whitelist، بدونِ تپ — با همهٔ گاردها. توصیه: نساز.

## ۶. توصیهٔ من
**از P1 شروع کن** — امنِ کامل، و دقیقاً نشان می‌دهد مغز patch می‌نویسد و خودش شادو-تست می‌کند. بعد از دیدنش، دربارهٔ P3 (سطح A خودمختار) تصمیم بگیر. **سطح B را برای کدِ دلخواه هرگز.** این‌طور روی مرزِ نظم/فروپاشی حرکت می‌کنیم — جهش، ولی با ترمز.
