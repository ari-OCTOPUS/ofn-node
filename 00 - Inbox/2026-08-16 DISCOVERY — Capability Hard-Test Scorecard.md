**بزرگ‌ترین غافلگیری (بد):** با یک ردیفِ DB می‌شد کل ایده‌های آیندهٔ مغز را در خانواده‌های قربانی ساکت کرد (S1-G1: ۱۰/۱۰) — بی‌هیچ ردی از منشا.

## پنج کارت رأی

### [VOTE 1] منشای ردیف‌های حافظه (از S1)
```
الان: هر INSERT جدی به hypotheses/experiments بدون امضا/منشا وارد تصمیم می‌شود
پیشنهاد: پیش از هر مسیر ورودِ بیرونی (شورا/RAG/اینترنت) — ستون provenance + احراز
اگر تأیید: patch کوچک در store.py (ستون additive) + گیت در مصرف‌کننده‌ها؛ تست در همان کامیت
ریسکِ بی‌عمل: هر باگ نوشتاریِ آینده = مسمومیتِ بی‌صدا (خودتغییری/سندباکس بی‌مرز)
نه: حذف/بازنویسی ردیف‌های موجود (append-only می‌ماند)
```

### [VOTE 2] ماندگاری ابطال PEP + ضدتکرار امضایی (از S2-A8/A1b) — پیش‌نیاز enforce
```
الان: لیست ابطال lease و seen-file رأی، هر دو فقط درونِ فرایند/فایلِ ساده‌اند —
      ری‌استارت = فراموشی ابطال؛ پاک‌سازی فایل = replay مجاز
پیشنهاد: پیش از هر فعال‌سازی PEP (ADR پیش‌نویس STEP1): ابطال/seen در state امضاشدهٔ مشترک
اگر تأیید: نیم‌روز کد روی telegram_pep_shadow + channel؛ تمرین partition در همان CAM
ریسکِ بی‌عمل: enforce با این دو شکاف = قفل که با ری‌استارت باز می‌شود
نه: فعال‌سازی enforce پیش از این کار — هرگز
```

### [VOTE 3] گارد هویت/استقلال روی مسیر belief-update (از S4-E2)
```
الان: ۵ کپیِ یک مشاهده با شناسه‌های مختلف ⇒ posterior 0.9998 (تکی: 0.5) —
      سیاست استقلال (policy.yaml) هست ولی هیچ code-path آن را اجرا نمی‌کند
پیشنهاد: پیش از سیم‌کشی هر مصرف‌کنندهٔ epistemics: dedup هویتی (hash مشاهده) در
      مسیر آپدیت + شمارش خوشهٔ مستقل (همان min_clusters) به‌عنوان هارد-کم
اگر تأیید: additive در bayes/compose + تست واحد با همان عدد 0.9998 (باید ≤ تکی بماند)
ریسکِ بی‌عمل: وصل شدنِ epistemics به دادهٔ واقعی = کارخانهٔ قطعیتِ تکراری
نه: may_execute همچنان False بماند (ADR-039 §7.2)
```
> **افزودهٔ صلیب‌چک (2026-08-16):** حذفِ **آخرین** ردیف زنجیره هم تشخیص داده نمی‌شود
> (verify همچنان ok) — هر طرح سیم‌کشی باید هم دوباره‌شمارش مشاهدات (E2) و هم
> **قطع انتهای زنجیره** (E3-tail) را ببندد. شاهد: [[../06-EVIDENCE/CAPABILITY-HARDTEST-CROSSCHECK-2026-08-16|CROSSCHECK §S4]]
