# Scout: tools — 2026-07-04

## سؤال امروز

اگر سیستم architect بخواهد روی یک پلتفرم اتوماسیون self-hosted استاندارد شود (جولای ۲۰۲۶)، بین n8n / Activepieces / Windmill / Node-RED کدام برای اپراتور تک‌نفره با کانال تلگرام + اسکرپینگ کریپتو + لیدگیری بالاترین ROI را دارد — با لحاظ قیمت و ریسک lock-in؟

## یافته‌ها

### ۱. n8n — پیش‌فرض منطقی برای ستون فقرات workflow

- Self-host نامحدود و رایگان برای استفادهٔ داخلی؛ ~۵۰۰+ نود رسمی (Telegram بالغ، HTTP polling، cron)، بزرگ‌ترین جامعه (~۱۸۶K ستارهٔ GitHub، ژوئن ۲۰۲۶)، ۲ کانتینر (n8n + Postgres)، idle ~۳۰۰–۵۰۰MB و توصیهٔ عملی 4GB RAM. منبع: [StackScout Jun 2026](https://www.stackscout.net/articles/cc_20260619_171656.html) + [elest.io Jun 2026](https://blog.elest.io/n8n-vs-activepieces-which-self-hosted-automation-platform-in-2026/)
- از ~آوریل ۲۰۲۶ MCP دوطرفه دارد: «MCP Server Trigger» (ورک‌فلوها به‌عنوان ابزار برای Claude) و «MCP Client Tool» + MCP server سطحِ instance (Public Preview). منبع: [n8n docs](https://docs.n8n.io/advanced-ai/mcp/accessing-n8n-mcp-server/) — نکتهٔ epistemic: مقالهٔ مارس ۲۰۲۶ devcrea هنوز می‌گفت «MCP ندارد»؛ داکیومنت رسمی جدیدتر است و می‌بَرد.
- **برای ما:** پُل Telegram→vault (webhook واقعی به‌جای polling)، polling منابع کریپتو (lunarcrush/cryptoquant)، پایپ‌لاین لید AiFarm — همه بدون هزینهٔ نرم‌افزار روی همین لپ‌تاپ همیشه‌روشن.
- **قیمت/lock-in:** self-host صفر دلار؛ Cloud از $20/mo (لازم نیست). لایسنس Sustainable Use (fair-code): استفادهٔ داخلی آزاد، اما embed/فروش مجدد ⇒ قرارداد پولی؛ خروجی JSON ورک‌فلوها قابل‌export ولی فرمتش مختص n8n است (هزینهٔ مهاجرت = بازسازی). ریسک: متوسط ولی فقط اگر روزی اتوماسیون را به‌عنوان محصول بفروشیم.

### ۲. Activepieces — گزینهٔ MIT و MCP-first (هج استراتژیک)

- Community Edition تحت MIT (تنها گزینهٔ کاملاً permissive)؛ ~۴۴۰ piece (~۶۰٪ community) و **~۴۰۰ piece به‌صورت MCP server عرضه می‌شود** + MCP client — یعنی Claude/Cowork می‌تواند مستقیم pieceها را به‌عنوان ابزار صدا بزند؛ نزدیک‌ترین فلسفه به استک Claude-محور ما. منبع: [StackScout](https://www.stackscout.net/articles/cc_20260619_171656.html) + [devcrea](https://www.devcrea.com/self-hosted-ai-workflow-automation)
- سنگین‌تر از ظاهرش: ۳ کانتینر (app + Postgres + Redis)، حداقل 2GB RAM عملی؛ کاتالوگ از n8n کوچک‌تر. Cloud: free tier، بعد ~$10–25/mo با مدل «per active flow» نه per run. منبع: [elest.io](https://blog.elest.io/n8n-vs-activepieces-which-self-hosted-automation-platform-in-2026/) + [ohaiknow review](https://ohaiknow.com/reviews/activepieces)
- **برای ما:** اگر روزی به مشتری (نقاشی/Ziman) اتوماسیون white-label بفروشیم، MIT تنها مسیر بی‌دردسر است. lock-in: عملاً صفر.

### ۳. Windmill — موتور سریعِ code-first؛ برای ما شکل اشتباه

- Python/TS/Go/Bash/SQL با UI خودکار از پارامترها؛ سریع‌ترین موتور اما استک کامل ۴–۶ سرویس و ~2GB+ RAM (توصیه 4GB)؛ AGPLv3 + EE تجاری؛ MCP/agent-builder بومی ندارد (LLM فقط via اسکریپت). منبع: [dev.to selfhosting](https://dev.to/selfhostingsh/windmill-vs-n8n-which-automation-platform-to-self-host-55a2) + [devcrea](https://www.devcrea.com/self-hosted-ai-workflow-automation)
- **برای ما:** اسکریپت‌های `_code` را همین حالا Claude ارکستریت می‌کند؛ Windmill لایهٔ تکراری اضافه می‌کند. Skip مگر روزی نیاز به صف/worker جدی برای اسکریپت‌ها.

### ۴. Node-RED 5.0 (ژوئن ۲۰۲۶) — نه برای vault، دقیقاً برای Mining

- بزرگ‌ترین بازطراحی ادیتور تاریخ پروژه؛ Apache-2.0 (OpenJS Foundation — بی‌ریسک‌ترین lock-in)؛ فوق‌سبک (~256MB RAM ممکن)؛ MQTT/GPIO/serial بومی. نیازمند Node.js 22.9+ و **پشتیبانی ARM 32-bit حذف شد** (RPi 3B و قدیمی‌تر بیرون؛ Orange Pi 5 Pro با ARM64 مشکلی ندارد). منبع: [Node-RED 5.0 release](https://nodered.org/blog/2026/06/09/version-5-0-released) + [n8n vs Node-RED 2026](https://n8nautomation.cloud/blog/n8n-vs-node-red-which-automation-platform-is-better-in-2026)
- **برای ما:** تله‌متری ESP32 و death-watch ماینرها روی خود Orange Pi؛ لایهٔ edge، نه control-plane.

### ۵. جمع‌بندی ROI

**توصیه: n8n روی لپ‌تاپ همیشه‌روشن (Docker، $0)** به‌عنوان ستون فقرات event-driven — اما فقط وقتی deploy کن که یک workflow مشخص به تریگر ۲۴/۷ نیاز داشته باشد که تسک‌های زمان‌بندی Cowork پوشش نمی‌دهند (webhook تلگرام، هشدار قیمت لحظه‌ای). پلتفرم بدون workflow مشخص = هزینهٔ نگهداری بدون سود. Activepieces = هج MIT/MCC اگر فروش اتوماسیون مطرح شد؛ Node-RED = فقط edge ماینینگ؛ Windmill = skip.

## اسپورهای رهاشده

1. کدام MCP server یا پلاگین Obsidian (Local REST API و جانشینانش) در ۲۰۲۶ امن‌ترین راه read/write ایجنت‌ها به vault است — با چه سطح دسترسی و چه ریسک prompt-injection؟
2. آیا n8n روی همین لپ‌تاپ ویندوزی واقعاً از تسک‌های زمان‌بندی Cowork جلو می‌زند؟ سنجش هزینه/فایده: Docker Desktop دائمی + نگهداری در برابر «فقط وقتی رویداد لحظه‌ای لازم شد» (کاندید تست: هشدار قیمت crypto با سقف AU$30).
