# Learning science — Research Digest 2026-07-06

## Today's question
Yesterday's digest found that blocked practice should precede interleaved practice for low-prior-knowledge learners — but is there an actual measurable **readiness signal** (an accuracy threshold, a number of consecutive correct sessions) that tells you *when* to make the switch, rather than a vague "once you've built some basics"? And does anything like this exist for AI/agent training loops (curriculum learning)?

## Findings

- **[peer-reviewed] Mastery-criterion *level* (not just "some" blocked practice) directly predicts how well the skill survives afterward.** A controlled study assigned learners to 50%, 80%, or 90% accuracy criteria before ending the acquisition/blocked phase. Three to four weeks later, the 90% group was the most stable (70–100% accuracy retained, converging on 90%+), the 80% group was more variable, and the 50% group ranged wildly (20–80%). **Takeaway for Ari:** "blocked practice until it feels okay" isn't a real criterion — a specific number is. If building any skill-drill loop (lead-quality judgment, pattern recognition, an agent's sub-skill), use a hard threshold of ~90% correct, not 70–80%, before allowing the harder/mixed phase — the gap in later reliability is large. [source](https://pmc.ncbi.nlm.nih.gov/articles/PMC5843573/)

- **[peer-reviewed/formal] "Readiness" can be computed as a running skill-estimate against a fixed threshold — this is already a solved algorithmic problem in intelligent tutoring systems.** A formal analysis of mastery-learning criteria (used in systems like ALEKS) shows the standard approach: maintain a skill estimate θ ∈ [0,1] via an exponential moving average of correctness (θ := (1−w)θ + wC), and declare mastery/readiness when θ crosses a threshold T (commonly ~0.90–0.95). The paper is explicit that the *choice* of T trades off mastery quality against over-practice/wasted time — there's no free lunch, but the mechanism is simple and battle-tested at scale (ALEKS: 7M+ students). **Takeaway:** this is directly implementable — architect's `selfimprove` loop or any Ari-facing skill tracker could gate the blocked→interleaved (or scaffolded→adversarial) switch with exactly this: an EMA of recent success rate crossing ~0.9. [source](https://www.fi.muni.cz/~xpelanek/publications/nrhm-mastery.pdf) · [background](https://en.wikipedia.org/wiki/Mastery_learning)

- **[peer-reviewed, 2025] Once you're already interleaving, *how* you sequence the mix barely matters — the switch itself is where the value is.** A new study (259 participants, painting-classification) tested whether *adapting* interleaving order to each learner's specific confusion pairs (i.e., a "smart" interleave) beats plain random interleaving. It didn't — no significant difference in outcomes. Blocking still felt easier and produced better in-the-moment judgments, but both interleaving variants beat blocking equally at delayed test. **Takeaway:** don't over-engineer the interleaving order (for agents or humans) — the hard problem is deciding *when* to leave blocked practice, not *how cleverly* to shuffle the interleaved phase afterward. Cheap random interleaving already captures most of the benefit. [source](https://www.sciencedirect.com/science/article/pii/S1041608025001803)

- **[preprint, 2026, ML] The closest machine-learning analogue to a "readiness signal" is now a real, tested technique: model-relative "transitional problems."** A new curriculum-learning paper defines difficulty *relative to a given model's current ability* rather than a fixed human-difficulty score, and identifies "transitional problems" — items that flip from wrong to right exactly as ability crosses a boundary. Training on a curriculum that "levels up" through these model-specific transitional problems (chess, math) outperformed static easy→hard curricula and got a small model to >20% accuracy in just ~2 training steps in one test. **Takeaway:** this is a genuine answer to last night's spore — yes, curriculum-ordering research in ML has converged on almost exactly the human mastery-threshold idea: readiness = current-ability-relative difficulty, not a fixed a priori ordering. Directly relevant to how `architect-selfimprove` could sequence its own backlog (REFACTOR_PLAN items, adversarial tests) by estimated current "ability" on that item class rather than a static priority list. [source](https://arxiv.org/pdf/2603.13761)

- **[preprint, 2024] Automated curriculum learning already operationalizes "difficulty ≤ ability" as a training-data filter, which is structurally identical to a mastery threshold.** A dynamic curriculum-learning framework (DDS-MAE) estimates a model's ability at each training epoch and selects only examples where item-difficulty ≤ estimated ability (≈50% correct-probability boundary), re-estimated every epoch from a single forward pass. **Takeaway:** the "criterion + re-estimate + gate" loop from human mastery learning and this ML technique are the same three-step pattern (measure → threshold → advance). This strengthens the case that a simple EMA-based readiness gate (finding #2) is a reasonable, low-effort mechanism to borrow for agent-training or curriculum decisions inside architect. [source](https://arxiv.org/html/2408.05326v2)
