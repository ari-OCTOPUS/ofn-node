# selfimprove — «Fleet Homeostat»: مانیفستِ حالتِ مطلوبِ ناوگان + حلقهٔ آشتی (drift-report) — پاسخ اجرایی به GAP 10

> لِینِ GENERAL / cross-cutting. تحقیقِ سبک (~۲ دقیقه)، نه deep-research. همه **propose-only**.

## ۱) آیتمِ انتخاب‌شده و چرا مهم است

**GAP 10 — «GitOps برای ناوگان <۵۰ نود بدون k8s»** از [[04 - Architect System/architect/02-Research/Report - Architect - Open Questions 2026-07-04|Open Questions]]. وضعیتِ ثبت‌شده: «pattern confirmed, no canonical tool → گلوی نازک را خودمان بسازیم».

چرا این آیتم برای لِینِ GENERAL درست است (و نه یک خانوادهٔ خاص): «چطور کلِ ناوگان مستقر می‌شود، هم‌گام می‌ماند و خودش را ترمیم می‌کند» را هیچ‌کدام از پنج خانواده (safety / memory / orchestration / nature / tooling) به‌تنهایی مالک نیست — cross-cutting میان orchestration + tooling + observability + safety-rollback است.

چرا حالا مهم است (ریسکِ واقعیِ دیده‌شده در [[01 - Dashboard/HANDOFF|HANDOFF]]): ناوگان از **۱۱ → ۲۲ → ۲۳ تسک** رشد کرد، cadenceِ selfimprove از **۳۰ → ۱۵ → ۳ دقیقه** تغییر کرد، اسکات‌ها spawn/retire شدند — اما **هیچ منبعِ حقیقتِ اعلانیِ (declarative source of truth) واحدی از «ناوگان چطور باید باشد» وجود ندارد.** این کلاسیک‌ترین شکلِ *config drift* است: یک اسکات می‌تواند بی‌صدا بمیرد، دوبار اجرا شود، یا با cadence/پرامپتِ عوض‌شده بماند و هیچ‌کس نفهمد. چون فلیت روی اشتراکِ Max و صفِ نرخ می‌چرخد، drift نامرئی مستقیماً به «سیگنالِ گم‌شده» ترجمه می‌شود.

**اسپورِ طبیعتِ نو (متمایز از پوشش‌های قبلی):** *homeostasis / negative-feedback / set-point*. دیجست‌های اخیر از evaporation (۱۸۳۵)، kin-routing (۱۸۲۶)، substrate-memory (۱۹۰۶)، requisite-variety (۱۸۵۰)، legible-trace (۱۹۲۲)، apoptosis (۱۹۱۱) و stigmergy استفاده کردند — اما **حلقهٔ کنترلِ بازخوردِ منفی برای بازگشت به set-point** هنوز به‌کار نرفته. این نگاشتِ نو دقیقاً همان چیزی است که GAP 10 می‌طلبد.

## ۲) یافته‌ها و prior-art

- **حلقهٔ آشتیِ (reconciliation loop) GitOps** یک الگوی ثابت است: `observe → compare(desired vs actual) → act → report → converge`. هر controllerِ Flux/Argo همین را می‌چرخاند؛ git = «حالتِ مطلوب»، کلاستر = «حالتِ مشاهده‌شده»، و diffِ semantic فاصله را می‌بندد تا سیستم به حالتِ مطلوب هم‌گرا شود. ([Flux reconciliation loop، گام‌به‌گام](https://oneuptime.com/blog/post/2026-03-05-flux-cd-reconciliation-loop/view))
- **Drift detection** = مقایسهٔ manifestِ رندرشده از git با حالتِ زندهٔ سیستم؛ منابعِ drift: تغییرِ دستی، mutationها، مقیاس‌گیریِ خودکار. تشخیصِ drift پیش‌نیازِ self-healing است. ([Configuration Drift Detection in GitOps](https://oneuptime.com/blog/post/2026-02-26-configuration-drift-detection-gitops/view))
- **نگاشتِ زیستی (چرا این «کپیِ طبیعت» است، نه استعاره):** حلقهٔ homeostatic فیزیولوژیک ساختارِ یکسان دارد — `sensor → error-detector (مقایسه با set-point) → controller → effector → بازگشت به set-point`. انحراف از set-point یک **error signal** می‌سازد که effector را فعال می‌کند تا متغیر را برگرداند (مثل تنظیمِ دمای بدن توسط هیپوتالاموس). ([Homeostasis & allostasis in physiological regulation, PMC](https://pmc.ncbi.nlm.nih.gov/articles/PMC4166604/))

**تناظرِ یک‌به‌یک (طبیعت → معماریِ ما):**

| homeostasis | Fleet Homeostat |
|---|---|
| set-point (مقدارِ مرجع) | `FLEET-MANIFEST` در vault (حالتِ مطلوبِ اعلانی) |
| sensor | `list_scheduled_tasks` (حالتِ واقعی) |
| error-detector | reconcile-scout که diff می‌گیرد |
| error signal | drift-report در `scout-digests` |
| effector | **آری** (چون گیت propose-only است) |

نکتهٔ کلیدی: در سیستمِ ما effector عمداً انسان است — ما error signal تولید می‌کنیم، آری اصلاح را اعمال می‌کند. این با §fail-closed (R-01) و Security Gate سازگار است.

## ۳) پیشنهاد — **needs Ari's verdict**

**الف) یک مانیفستِ اعلانیِ واحد:** `05 - Agents/FLEET-MANIFEST.md` به‌عنوان تنها منبعِ حقیقتِ «ناوگان چطور باید باشد» (DNA / set-point فلیت). vault-native بماند (markdown + جدول یا بلوکِ yaml داخلِ نوت) تا در Obsidian خوانا و لینک‌پذیر باشد، نه yamlِ بیرون از vault. هر ردیف: `task-id · cadence(cron) · prompt-slug · prompt-hash · lane · status(active|paused|retired)`.

**ب) یک reconcile-scout سبک** (پیشنهاد: پیوست به `fleet-selection` یکشنبه، یا مستقلِ ۶‌ساعته): `list_scheduled_tasks` را می‌خواند (sensor)، با `FLEET-MANIFEST` دیف می‌گیرد و سه دستهٔ drift را گزارش می‌کند:
1. **MISSING** — در مانیفست هست، در واقعیت نیست → اسکاتِ مُرده/حذف‌شده.
2. **UNDECLARED** — در واقعیت هست، در مانیفست نیست → تسکِ سرکش یا تستیِ فراموش‌شده.
3. **MISMATCH** — cadence یا `prompt-hash` فرق دارد → drift پیکربندی/پرامپت.

**ج) خروجی = یک `<date> <time> reconcile.md` در `scout-digests`** (propose-only، هیچ auto-apply). آری effector است و verdict می‌دهد.

**د) `prompt-hash` در مانیفست** پرامپت‌ها را *immutable-by-declaration* می‌کند — پلِ مستقیم به **R-10** («configuration as immutable settings») و **R-16** («prompt rollback floor validation»): هر تغییرِ پرامپت که با hash مطابقت نکند، خودش یک MISMATCHِ گزارش‌شونده است.

این یک آیتم است که چند آیتمِ دیگر را de-risk می‌کند (معیارِ انتخابِ STEP 2): پایهٔ observability برای کلِ فلیت، پلی به R-10/R-16، و پیش‌نیازِ هر self-healingِ آینده.

## ۴) ریسک‌ها و trade-offها

- **مانیفست خودش کهنه می‌شود** (اگر تسکی دستی اضافه/حذف شود بدون به‌روزرسانیِ مانیفست). پاسخ: reconcile دقیقاً همین را به‌عنوان drift می‌گیرد؛ + قاعدهٔ عملیاتی «هر spawn/retire اول مانیفست را update کند» (هم‌ارزِ قاعدهٔ `PROJECT.md`).
- **markdown vs yaml:** markdown خوانا ولی نیازمندِ parse؛ yaml دقیق ولی بیرون از Obsidian. توصیه: بلوکِ ```yaml داخلِ نوتِ markdown (بهترِ هر دو).
- **over-automation:** اگر روزی auto-remediate شود، می‌تواند اسکاتِ عمداً `paused` را دوباره زنده کند. لذا فعلاً **report-only**؛ auto-apply هرگز بدون verdict.
- **هزینه:** ناچیز — یک `list` call + یک diff؛ ثانیه‌ای، بی‌بارِ محسوس روی صفِ نرخ.
- **vendor lock-in:** هیچ. الگو tool-agnostic است (scheduled-tasks / systemd-timer / cron هر کدام)، برخلافِ Flux/Argo که k8s-bound‌اند و طبقِ GAP 10 همچنان SKIP می‌مانند.
