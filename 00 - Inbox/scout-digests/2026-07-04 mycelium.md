# Mycelium (nature → AGI) — Research Digest 2026-07-04 (live kickoff)

## Today's question
If a forest has no CEO, no central database, and no scheduler — yet survives droughts, fires, and centuries — what *specific* memory and coordination mechanisms let it do that, and which of them can our multi-agent, memory-based AGI copy on purpose (not by metaphor)?

## Findings

- **Fungal mycelium as a trainable, dehydratable memristor (shiitake retains memory after drying, reactivates on rehydration; ~90% memristive accuracy up to ~6 kHz).** Nature stores state *in the substrate itself*, and that memory survives being powered-down and revived. Lesson for our architecture: treat memory as a **durable, dormant-then-reactivatable artifact**, not a live process. Each scout should persist its state to disk (the digest note = the dehydrated spore), so an agent can be killed between runs and "rehydrate" full context on the next daily kickoff. Bias memory tooling toward cheap, biodegradable, append-only files over expensive always-on stores. [source](https://www.biorxiv.org/content/10.1101/2025.07.11.664296v1.full)

- **Mother/hub trees are the most-connected nodes and preferentially route surplus carbon/nitrogen to kin seedlings, raising their survival.** The network is not flat — a few old, information-rich hubs subsidize the young and weak, and they *recognize kin*. Lesson: our orchestration should be a **hub-and-spoke mycorrhizal topology, not a mesh of equals**. Designate a small number of long-lived "mother" agents (e.g. the Architect/consolidator) that hold accumulated context and *push* relevant memory + budget down to fresh, low-context scouts on spawn. Route resources by relevance/kinship (shared project tag), not uniformly. [source](https://suzannesimard.com/research/)

- **Emergent collective memory in decentralized multi-agent AI: individual memory gave +68.7% over no-memory, but environmental traces *without* per-agent memory failed completely — traces need cognitive infrastructure to be read.** A shared scratchpad is worthless unless agents can interpret what they find there. Lesson: don't just dump artifacts into a shared inbox and hope; pair every **environmental trace (the note) with a memory/parsing convention** (strict frontmatter + wikilinks + tags) so any agent can decode a peer's deposit. Individual agent memory and shared traces are complementary, not substitutes — build both layers. [source](https://arxiv.org/abs/2512.10166)

- **Robust-to-downtime distributed systems rest on four principles: separate processes, isolatability, diversity, and redundancy.** Forests apply the same recipe (many species, many independent trees, overlapping roles). Lesson for tool/agent design: run scouts as **isolatable, independently-failable processes** (one scout crashing must not poison the fleet), keep them **diverse** (different domains/prompts so blind spots don't correlate), and accept **redundancy** as a feature — overlapping coverage is antifragile, not wasteful. Staggered daily scheduling already gives us process separation; formalize the isolation guarantee. [source](https://link.springer.com/article/10.1007/s00607-020-00895-6)

- **Stigmergy: ants coordinate with zero direct messaging by leaving/reading pheromone traces in a shared environment, and *unused trails evaporate* so effort self-reallocates.** No central planner, and the system forgets stale paths automatically. Lesson: our fleet should coordinate **through the vault (the shared environment), not through direct agent-to-agent chatter** — a scout "deposits" a digest, the consolidator "reads the trail," and priorities emerge. Critically, add **evaporation**: give traces a decay/TTL (status: inbox → aged → archived) so stale findings fade and the fleet naturally re-focuses on fresh signal instead of drowning in accumulation. [source](https://gc-bs.org/articles/decentralized-intelligence-stigmergy-simple-rules-future-organizational-coordination/)

- **Autopoiesis / requisite variety: a living system continuously *produces its own components and its own boundary*, and needs internal variety at least matching the variety of the disturbances it faces.** Life is defined by self-maintenance and a self-generated membrane, not by any fixed structure. Lesson: the AGI should be **self-building** — agents that create and refresh the very notes, indexes, and (eventually) other agents that constitute the system (this vault already does this: agents write their own registry/handoff). And by requisite variety, **match fleet diversity to problem diversity**: as the domains we track grow, grow the *kinds* of scouts, or a low-variety fleet will be blind to high-variety threats. The system's boundary (what's in-scope vs `.agentignore`) should be produced and maintained by the system itself. [source](https://arxiv.org/pdf/1409.7475)
