# طرح — مرکز فرماندهی تلگرام (اختاپوس)

> **وضعیت: نقشهٔ اولیه — منتظرِ تأییدِ مالک قبل از هر کدنویسی.** رأی مالک: «اول نقشه، بعد بپرس و تأیید بگیر.»

## ۱. مدلِ فرماندهی (هلدینگ)

- **مغز فرماندهی (HQ)** = دکترِ تکاملی (تصمیم/ممیزی) + قلب (ضربان). مثلِ دفترِ مرکزیِ هلدینگ.
- **ضربانِ قلب = سیاستِ دنیای ماشین‌ها**: کادنسِ پیام‌ها، بودجهٔ توکن/مدلِ AI (organ_gate/model_router)، پول. استرسِ بالا → پیامِ کمتر و مهم‌تر (هومئوستاز).
- **۸ پا** — هر پا جعبه‌سیاهِ خودش (PROJECT.md + لوپِ business_brain)، فقط دو چیز به HQ می‌دهد: سلامت (🟢🟡🔴) + escalation:
  ۱. Lead-نقاشی · ۲. Ziman Galerry · ۳. Mining · ۴. Crypto-etoro · ۵. Accounting (۵ بیزنس)
  ۶. استودیو (**content-free** — هویت هرگز در تلگرام، §۱۰) · ۷. سیستم/architect · ۸. دانش/هیپنوتیزم

## ۲. قانون‌های UI (شخصیت‌محور: تصویری، ADHD-first، بدونِ بارِ حافظه)

۱. یک نگاه = کل وضعیت (پیامِ پینِ زنده که **ادیت** می‌شود — اسپم ممنوع)
۲. هیچ پیامی > ~۵ خط؛ رنگ/آیکن زبانِ اول
۳. هر تصمیم = یک لمس (دکمهٔ اینلاین)، نه تایپ
۴. سکوت = سلامت (فقط استثناها پیام می‌شوند)
۵. هیچ‌چیز نیاز به یادسپاری ندارد (/now همیشه هست؛ تصمیمِ بی‌پاسخ دوباره می‌آید)
۶. ریتم از ضربانِ قلب (نه cronِ ثابت)

## ۳. سطح‌های تلگرام (ابزارهای گرافیکیِ Bot API — همه $0)

| ابزار | استفاده |
|---|---|
| sendMessage + **editMessageText** | داشبوردِ پینِ زنده (بدونِ اسپم) |
| pinChatMessage | وضعیت همیشه بالای چت |
| InlineKeyboardMarkup + callback_query | دکمه‌های ✅تأیید/❌رد/⏳بعداً |
| **Forum topics** (سوپرگروپ) | HQ + هر پا یک تاپیک (۹ تاپیک) |
| setMyCommands | منوی /now /legs /money /brain |
| sendPoll / setMessageReaction | رأیِ چندگزینه‌ای / ackِ سبک |
| web_app (Mini App) | نسخهٔ گرافیکیِ /ops — **اختیاری، نیازِ HTTPS عمومی → رأی جدا** |

## ۴. خوراکِ داده (همه از قبل ساخته و تست‌شده)

- `execution_board.board()` → پیامِ پینِ وضعیت (۶ لِین)
- `guidance_box.guidance()` → تاپیکِ تصمیم‌ها (سؤال‌های high-leverage با دکمه)
- `business_brain.summary()` → دایجستِ هر پا
- `stress/innervation/registry` → هشدار + سلامتِ پاها
- heart period + organ_gate → کارتِ پول/ضربان
- دکمهٔ ✅ → `approval_channel` → **HumanAppendGuard.mint** (تأییدِ انسانیِ HMAC، جعل‌ناپذیر — گاردِ همین جلسه)

## ۵. فازها (هر فاز جدا تست و تأیید می‌شود)

- **T1 — کابینِ read-only:** بات (زیرساختِ موجودِ approval_channel) + `/now` + پیامِ پینِ زنده که هر beat ادیت می‌شود. صفر اکشن.
- **T2 — پاها:** تاپیکِ هر بیزنس + دایجستِ روزانه + فقط escalation.
- **T3 — تصمیم‌ها:** دکمه‌های اینلاین → approval_channel → mint (حلقهٔ انسانیِ واقعی).
- **T4 (اختیاری):** Mini App گرافیکی — فقط با رأیِ جدا (نیازِ tunnel عمومی، ریسکِ exposure).

## ۶. ریل‌های امنیتی (تخطی‌ناپذیر)

فقط chat_id مالک (whitelist موجود) · استودیو فقط با aliasِ content-free · هیچ secret در پیام · $0 (long-poll) · اکشن‌ها فقط sanctioned (همان‌های live cockpit) · هر callback در events لاگ می‌شود.

## ۷. رأی‌های مالک (۲۰۲۶-۰۷-۱۱ — ثبتِ نهایی)

۱. شکلِ سطح: **سوپرگروپِ فوروم** (۹ تاپیک: HQ + ۸ پا). ✔
۲. پای F: **پای اختصاصیِ کامل** («بیزنس هستش، نگهش دار»). اجرا: کلید در کد/لاگ content-free می‌ماند؛ نامِ نمایشیِ تاپیک مالک‌-تنظیم (config)، پیش‌فرض «استودیو» — نامِ واقعی را مالک خودش در تلگرام می‌گذارد. ✔
۳. Mini App (T4): **برنامه‌ریزی آره** — سندِ طرح ساخته می‌شود؛ ساختِ واقعی = گیتِ جدا (tunnel/exposure). ✔
۴. کدنویسی: **T1→T3 پشتِ هم — برو.** ✔

وضعیت: در حالِ ساخت (workflowِ ۴-لاینه: tg_api + render + center + طرحِ T4).
