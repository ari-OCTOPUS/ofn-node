# موج‌بندی ساخت — ترتیب مفهومی و مرزهای موازی

این سند فقط **ترتیب** را تعیین می‌کند. هیچ کدی اینجا نوشته نمی‌شود.
مبنای ترتیب یک قاعدهٔ ساده است: چیزی که مرز تعریف می‌کند، قبل از چیزی که از آن
مرز عبور می‌کند.

## تشخیص محوری این اسکن

بین هستهٔ OCTOPUS و لایهٔ بردها **هیچ قراردادی وجود ندارد**. قرار بود Envelope
لایهٔ Typed Events این مرز باشد و نوشته شد ولی ساخته نشد. نتیجهٔ عملی:

- بردهای جدید فقط با یکپارچه‌سازی دستی و یک‌به‌یک به هسته وصل می‌شوند
- هر برد جدید یک مسیر اختصاصی می‌سازد، پس هزینهٔ ادغام خطی نیست، درجهٔ دو است
- باگ H1 (یک verdict → N اجرا → N برداشت بودجه) با هر برد جدید **ضرب** می‌شود

پس ترتیب اجباری است: **اول Envelope و Run Store و اصلاح H1، بعد بردها.**
هر کس بردها را قبل از موج ۱ وصل کند، بدهی معماری تولید می‌کند نه قابلیت.

## شش مفهومی که در هیچ سندی نبودند

اسکن این شش را پیدا کرد که نه در چک‌لیست ۲۰۰آیتمی هستند، نه در ADRها، نه در
مگاپلن‌ها. این‌ها کشف این نشست‌اند، نه یادآوری:

| id | مفهوم غایب |
|---|---|
| B-01 | پروفایل Envelope برای لبه — یک برد محدود چه زیرمجموعه‌ای از فیلدها را می‌تواند بفرستد |
| B-02 | هویت و گواهی برد — کدام برد، کدام hash فریم‌ور |
| B-05 | تضمین propose-only در لبه — قاعدهٔ DNA برای پاها نوشته شده، برای بردها نه |
| B-06 | سقف بودجه و نرخ به‌ازای هر برد — رصدخانه سقف دارد، بردها ندارند |
| B-08 | رفتار offline و degraded وقتی برد شبکه را از دست می‌دهد |
| S-05 | اسکن وابستگی روی `pip install` ایجنت‌محور — تنها مسیر زنجیرهٔ تأمین بدون محافظ |

## چهار موج

### موج ۱ — ستون فقرات و ترازو (هیچ‌چیز دیگری قبل از این)

| لِین | آیتم‌ها | چرا اینجا |
|---|---|---|
| W1-SPINE | G-01 Envelope · G-02 run_id · G-03 Run Store · G-04 lifecycle | مرز هسته↔لبه |
| W1-MONEY | G-05 اصلاح H1 با payload fingerprint | باگ مالی، با هر برد ضرب می‌شود |
| W1-SCALE | M-06 اصلاح معیار P3 | با ترازوی شکسته نمی‌توان وزن کرد |
| W1-FREE | M-08 log mining · M-10 snapshot routing | صفرهزینه، فقط‌خواندنی، بدون وابستگی |

W1-FREE از همان دقیقهٔ اول موازی با سه لِین دیگر اجرا می‌شود. سه لِین دیگر هم
موازی‌اند چون فایل مشترک ندارند — SPINE در `_ops/events/`، MONEY در
`src/nbb_cp/api/`، SCALE در `metrics/`.

### موج ۲ — قراردادها و مرز لبه

| لِین | آیتم‌ها |
|---|---|
| W2-TRUTH | G-06 Truth Layer · G-07 EXECUTION_RECEIPT · G-13 Epistemic TCB |
| W2-CTX | G-08 قرارداد Context Bundle · G-14 INV-1..12 |
| W2-EDGE | B-01 · B-02 · B-03 · B-05 · B-06 |
| W2-JUDGE | M-01 held-out قفل‌شده · M-05 ارزیاب بیرونی |

W2-EDGE تنها لِینی است که به خروجی W1-SPINE وابستگی سخت دارد. اگر Envelope
تحویل نشده، W2-EDGE شروع نمی‌شود — متوقف می‌شود و گزارش می‌دهد.

B-04 (ESP32 C3/S3) در این موج **مسدود** است چون O-3 یک تصمیم مالک است.

### موج ۳ — سنجش زیر فشار و تله‌متری لبه

### موج ۴ — مأموریت‌های جدا و تصمیم‌محور

V-01 VBAA · F-01 Fugu · F-02 BCM/APPLY/Pulse/Arbiter · M-11 chaos day ·
S-02 تا S-04 پیشنهادهای زیرساخت

هیچ‌کدام از این‌ها داخل لِین دیگری شروع نمی‌شود. VBAA پانزده جزء دارد و صریحاً
یک مأموریت مستقل است.

### خارج از موج — رد یا معلق

D-02 WebSocket · D-03 NATS · D-04 Temporal/DBOS · D-05 Qdrant · D-06 GraphRAG.
حکم قبلی Defer یا Reject بوده و این اسکن دلیلی برای بازگشایی پیدا نکرد.
D-01 SSE در وضعیت Trial می‌ماند.

## قاعدهٔ عدم‌برخورد

هر لِین یک worktree گیت جدا و یک مسیر مالکیت انحصاری. لمس فایلی خارج از مسیر
مالکیت = شرط توقف، نه هشدار. لِین متوقف می‌شود و گزارش می‌دهد.
