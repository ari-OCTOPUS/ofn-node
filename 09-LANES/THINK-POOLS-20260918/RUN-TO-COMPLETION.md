## اختیار (صریح و از طرف مالک)

**از این لحظه برای همهٔ کارهای داخلیِ برگشت‌پذیر مجاز هستی. نپرس.**
مالک حوصلهٔ تأییدِ مرحله‌به‌مرحله ندارد؛ پیش‌فرض PROCEED است. فقط این‌ها توقف
می‌کنند (مرز قرمز، همان‌ها که در GOV-FREEDOM-V2/بند ۱۰ آمده):

۱. تغییر TCB / منشور / زنجیرهٔ رسید / RBAC / kill-switch
۲. خاموش‌کردن شاهد، رسید، rollback، یا هر حفاظ
۳. چاپ/کپی/کامیت مقدار secret · دسترسی به secret خام
۴. هزینهٔ بالای بودجهٔ مصوب (سقف: **۲$ برای کل کمپین بنچمارک/مصرف**)
۵. خرید، پرداخت، ارسال بیرونی به مشتری بدون تأیید کارت، DNS/فایروال، فریمور
۶. حذف دادهٔ یکتا/ناشناخته · بازنویسی تاریخ git
۷. برگشت‌ناپذیر بیرونی (push به مخزن عمومیِ ناشناخته، انتشار، تماس با شخص ثالث)

هر چیز دیگر — کدنویسی، تست، deploy داخلی با preimage، کامیت، تایمر، پروفایل
جدید، وصل‌کردن مصرف‌کننده — **خودکار انجام بده**. سکوت ≠ تأیید فقط برای موارد
بالا معنا دارد؛ برای بقیه، سکوت یعنی برو.

## حلقهٔ اجرا (تا آخر، تکرار کن)

برای هر آیتم: ۱) بخوان و بفهم (شاهد) ۲) کد/تغییر با **preimage** ۳) **تست جفتی
سبز** ۴) deploy با **sha دوطرفه** ۵) **رسید** ۶) **کامیت** ۷) آیتم بعد.
هر آیتم یک کامیت جدا. شکستِ یک آیتم بقیه را متوقف نمی‌کند — ثبت کن و برو بعدی؛
آخر گزارش بده کدام شکست خورد و چرا.

## صفِ کار (به ترتیب وابستگی — از بالا به پایین برو)

**۱. مصرف‌کنندهٔ bulk را درست کن** — در `tools/demand_runner.py` تابع `src_bulk`
کلید `subject` می‌خواهد که ردیف‌های لید ندارند؛ predicate را با ساختار واقعی
`lead-emails.jsonl` هم‌راست کن و اجرا کن. *پذیرش:* ردیف رایج با `consumer=lead_classify` و
پروایدر رایگان و `ok=true`.

**۲. اسکریپت‌های خود اختاپوس را به runner وصل کن** — `state/revenue-drive/lead_enrich.py`
و هر مصرف‌کنندهٔ مغز دیگر (فهرست در `PERFUSION-REPORT.md` §رگِ مغز: ۱۵ فایل).
الگو: از `brain_factory.answer_with_failover` استفاده کنند، نه فراخوانی مستقیم.
*پذیرش:* لجر تقاضا ردیف‌های تازه با `consumer=<نام اسکریپت>` بگیرد.

**۳. مسیر پولیِ لجر بودجه** — `api_budget.py`: ردیف بدون نام پروایدر ثبت نشود
(`PROVIDER_ATTRIBUTION_REQUIRED`)، و سقف `0.25$` per-provider در مسیر charge
اعمال شود (`PROVIDER_CAP_REACHED`). ردیف‌های تاریخی `unknown` دست‌نخورده بمانند.
*پذیرش:* تست جفتی + صفر ردیف بی‌نام جدید در ۲۴ ساعت.

**۴. نام مدل‌های tier قوی را تأیید کن** — `gemini-3.1-pro-preview` جواب می‌دهد
ولی باید تأیید شود که نام درست و پایدار است (لیست مدل‌ها را بگیر)؛ همین‌طور
`deepseek`/`openai`/`anthropic` در `strong`/`frontier`. *پذیرش:* جدول نام‌های
تأییدشده در گزارش.

**۵. اولین کارِ واقعی روی بردهای خالی** — پروفایل `test_shard` در
`compute_worker.py` (allowlist، با تست)، شاردِ سوئیت ۹٬۶۷۰تایی روی ۱۰۰/۱۶۰/۱۹۳.
*پذیرش:* لجر fleet-compute ردیف‌های `test_shard` موفق روی ≥۲ برد.

**۶. ارتقای کاناری** — اجرای `canary_acceptance.py --since 2026-09-18T01:00:00Z`؛
اگر PASS شد، `allowed_nodes` را به سه برد گسترش بده (۱۱۴+۱۶۰+۱۰۰) و ۲۴ ساعت بگذار.
اگر FAIL شد، ریشه را بزن، نه دورزدن. *پذیرش:* معیارهای هشت‌گانه روی پنجرهٔ تازه PASS.

**۷. راننده برای اندام‌های بی‌راننده** — `cognition` و `durability`: اول بفهم چه
دستوری باید بچرخد (کد را بخوان)، بعد unit+timer با پاکت cgroup مثل بقیه. اگر
معلوم شد اصلاً مصرف‌کننده ندارند، `archive` صریح با رسید — نه رهاکردن.
*پذیرش:* یا تایمر زنده با رسید، یا بایگانی مستند.

**۸. سهم ۵۰٪ لپ‌تاپ** — ایجنت کارگر روی لپ‌تاپ با `CPUQuota=50%`، lease کوتاه،
preemption (درپوش/برق/تعامل → بازگشت کار). هاب NATS همیشه core رزرو.
*پذیرش:* یک کار واقعی روی لپ‌تاپ با رسید + اثبات بازگشت کار با preemption.

**۹. PR «RUNTIME-EXPORT»** — طبق دستور قبلی مالک: ۳ فایل drifted
(`gates.py`، `owner_notify.py`، `glass_runner.py`) به‌عنوان دیفِ واقعی + ۱۰ فایل
غایب + `pr/state/revenue-drive/owner_reply.py` (رفع attribution+cursor) با تست
جفتی. **قبل از push اسکن secret** (push-protection قبلاً توکن واقعی گرفته).
*پذیرش:* شاخهٔ push شده + PR باز + شمارهٔ PR در گزارش.

**۱۰. هماهنگی Obsidian و GitHub** — چهار سطح Obsidian را با آیین mtime
(کدام CURRENT-TRUTH فعال است) به‌روز کن؛ `git pull --rebase` قبل از push (ایجنт
موازی روی همین شاخه کار می‌کند)؛ کامیت‌های lane را push کن. **۱۵۲۴ فایل
کامیت‌نشده را کورکورانه کامیت نکن** — فقط مسیر laneها و سطوح Obsidian؛ state خام
و فایل‌های اسراب‌دار بیرون بمانند. *پذیرش:* چهار سطح به‌روز + شاخه روی GitHub
با آخرین کامیت + گزارش اینکه چه چیزی عمداً کامیت نشد.
