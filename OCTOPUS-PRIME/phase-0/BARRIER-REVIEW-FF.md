### 2. Handled correctly (verified, no action)
- Case-insensitivity & `f:`/`F:` drive case: pathlib WindowsPath comparison is case-insensitive → caught.
- `..` traversal (`F:\backup\..\backup\x`): resolve() collapses → caught.
- 8.3 short name of an existing prefix (`F:\BACKUP~1\new`): resolve() expands the existing dir via _getfinalpathname → caught.
- Junction/symlink pointing INTO the vault from outside: resolve() follows it → caught.
- `shutil.copyfile`, `zipfile.extractall`: use call-time global `open` → caught **iff** install() ran before use.

### 3. Structural verdict
This is a Python-level deny-list of a handful of names. It cannot bound a "financially-capable agentic organism": os-level and C-extension write primitives (#1,#4,#5,#8,#9) are numerous and some (sqlite3, spawned processes) are fundamentally outside monkey-patch reach. Combined with fail-open (#7), Windows anchor evasion (#6), and the fact that it is not even wired in (§0), the barrier should be treated as **non-load-bearing**. Real isolation requires an OS boundary: a Windows ACL denying the sandbox principal WRITE/DELETE under `F:\backup`, or a restricted-token/job-object child. Keep this module only as a tripwire/evidence layer, not as the security control.
