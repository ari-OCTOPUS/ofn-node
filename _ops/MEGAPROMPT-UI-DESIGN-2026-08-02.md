# مگاپرامپت — طراحیِ UI: مینی‌اپ + دو بات + اعلان

> این سند برای **ایجنتِ طراحی‌گر/سازنده** نوشته شده. رأیِ مالک:
> **داشبوردِ کامل در مینی‌اپ (وب‌پیج)، تلگرام فقط اعلانِ فوری + رأی.**
> و **دو بات فعال شود** (split روشن). این مگاپرامپت معماریِ کامل را می‌چیند.

(همان §۰ از مگاپرامپتِ همگامیِ پاها — تکرار نشد. خلاصه: هرگز از ریشه اسکن نکن،

## ۱ · رأیِ مالک — معماریِ هدف

```
┌─────────────────────┐     اعلانِ فوری + رأی      ┌──────────────────┐
│   مینی‌اپ (وب‌پیج)    │ ◀──────────────────────── │  تلگرام           │
│   داشبوردِ کامل      │                           │  باتِ شخصی (outer)│
│   همهٔ پاها، اعداد    │                           │  باتِ ارگانیسم(inner)│
│   تاریخچه، نمودار    │ ──────────────────────────▶│                  │
└─────────────────────┘    تپِ رأی → مینی‌اپ/ارگانیزم │                  │
```

| سطح | نقش | چه می‌رود کجا |
|---|---|---|
| **مینی‌اپ** | داشبوردِ کامل، همهٔ اطلاعات، تاریخچه، اعداد | وب‌پیج در مرورگرِ گوشی/دسکتاپ |
| **باتِ شخصی (outer)** | گفتگو + رأی + فرمان | DM |
| **باتِ ارگانیسم (inner)** | هشدار + رسیدِ ترمیم + سلامت | DM |
| **گروهِ فروم** | فقط تاپیکِ پاها (مثل امروز) | هر پا در تاپیکِ خودش |

## ۲ · وضعِ امروز (نقطهٔ شروع)

### بات‌ها:
- **outer** (`@intergrade2725_Bot`, توکن: `TG_CENTER_BOT_TOKEN`) — poll + handle + send. فعال.
- **inner** (`@Robo2725_bot`, توکن: `TELEGRAM_BOT_TOKEN`) — send-only، صفر poll. فعال ولی...
- فلگ `OCTOPUS_TG_SPLIT_V1` **خاموش** است — یعنی فعلاً همه‌چیز از outer می‌رود.

### مینی‌اپ:
- وجود دارد! `telegram_center/miniapp/` + gateway روی پورت 8774 + tunnel.
- صفحهٔ `/` (200 OK، RTL)، `/api` (بدون initData = 403).
- پشتِ `OCTOPUS_WIRE_MINIAPP` + tunnelِ cloudflared.
- **ولی:** محتوای کامل ندارد — فقط صفحهٔ پایه. داده‌های پاها/اعداد/تاریخچه را
  نشان نمی‌دهد.

### governor-alerts:
- ۳۲۶۸ خط، **هرگز به تلگرام نمی‌رسد**. `event_bridge.py` می‌تواندش ولی پشتِ
  `OCTOPUS_WIRE_EVENT_BRIDGE` (خاموش).

## ۳ · پنج فاز

### فاز ۱ — فعال‌سازیِ دو بات (split) + alerts

> ⚠️ این فاز فلگ را عوض می‌کند — فقط با `OWNER_AUTH: ARM FLAG` انجام شود.

1. `surface-routing.json` را بخوان. دو بلوک دارد: `current` (امروز) و `target`
   (مقصد). `target` همان چیزی است که با split روشن می‌شود.
2. مسلح‌کردن به ترتیب:
   - `OCTOPUS_WIRE_EVENT_BRIDGE=1` — alerts از این به بعد به تلگرام می‌رود.
   - `OCTOPUS_TG_SPLIT_V1=1` — دو بات فعال.
3. **تستِ حیاتی:** بعد از مسلح‌کردن، تأیید کن:
   - outer همچنان poll می‌کند (pulse زنده).
   - inner پیام می‌فرستد (ارسالِ آزمایش به DM).
   - alert تازه از `governor-alerts.md` به تلگرام می‌رسد.
4. **تلهٔ ثبت‌شده:** پیامِ پین‌شدهٔ گروه (`center-status`) از split مستثنی است
   (هاردکد در `ensure_setup`). با split روشن، در گروه می‌ماند. عمدی است — تغییرش
   نده.

### فاز ۲ — دادهٔ مینی‌اپ: همهٔ پاها + اعداد + تاریخچه

1. `miniapp/` را بخوان. ساختارِ فعلی: صفحهٔ HTML + gateway.
2. یک endpoint بساز: `/api/state` که JSONِ کامل برمی‌گرداند:
   - همهٔ پاها (از `business_legs_beat`) با live/signal/note.
   - اعدادِ mining (۱۶۲، اندازه‌گیری‌نشده).
   - وضعیتِ lead (کاندیدها، pipeline).
   - نبضِ ارگانیسم (beat، halted، protective_skip).
3. صفحهٔ مینی‌اپ را ارتقا ده: هر پا یک کارت/بخش. اعداد فارسی. صادقانه:
   «اندازه‌گیری‌نشده» نه ۰.
4. **auth:** initDataِ تلگرام را gateway چک می‌کند (۴۰۳ بدونش). فقط مالک.
5. تست: صفحه با initDataِ مالک داده‌ها را نشان می‌دهد.

### فاز ۳ — اعلان‌های فوری در تلگرام (نه همه‌چیز)

منشورِ اعلان می‌گوید: **حداکثر ۵ اعلانِ فوری در روز.** تلگرام فقط برای این پنج
موارد است:
1. لیدِ تازه (آمادهٔ رأی).
2. پرداختِ گیرکرده / نیمه‌کاره.
3. نودِ ماینینگ بی‌جواب (>۲۴h) یا دما (>۸۲°).
4. تصمیمِ منتظرِ رأی.
5. هشدارِ بحرانی (از governor-alerts).

**کار:** مطمئن شو این پنج جریان از `center-urgent`/`center-alert` به DM می‌روند
(با split روشن). بقیه (دایجستِ روزانه، کارتِ پا) فقط در مینی‌اپ و گروه.

### فاز ۴ — رأی از تلگرام → ارگانیسم

دکمه‌های رأی (ok/no/later، mo:swap، tk:*) از تلگرام بیایند و به ارگانیسم برسند.
این تا حدی کار می‌کند (verbها در `GROUP_CALLBACK_VERBS` هستن). ولی:
- `authorize()` هنوز سیم‌نشده (فازِ ۳ مگاپرامپتِ همگامیِ پاها).
- مطمئن شو تپِ رأی در مینی‌اپ هم دکمه دارد (نه فقط تلگرام).

### فاز ۵ — پاکسازی و یکپارچه‌سازی

1. فرمان‌های DM: ۸ فرمان فعلی تمیز است. ولی ۲۶ فرمانِ مخفی هستن — کدام باید
   پنهان بمانند، کدام به مینی‌اپ منتقل شوند؟
2. راهنمای پین‌شده (`guide.py`): به‌روز شود تا بگوید «داشبورد در مینی‌اپ، اینجا
   فقط اعلان و رأی.»
3. دایجستِ ادغامي (`OCTOPUS_TG_MERGED_DIGEST`): روشن شود تا ۹ پیامِ پا → ۱ پیام.

## ۴ · مرزهای سخت

- **هرگز ایمیل نفرست.** transport مسلح است.
- **هرگز** `STOP-*`/`HALT-*` نساز یا پاک نکن. `power.py`/`run_all` را نَدوان.
- **هرگز فلگ بدون `OWNER_AUTH`.**
- **هرگز عددِ زنده جعل نکن.** «اندازه‌گیری‌نشده» بنویس.
- **حریمِ خصوصی + راز** (همان منشور).
- مینی‌اپ فقط با initDataِ مالک (whitelist). هرگز公开.

## ۵ · خروجیِ مورد انتظار

برای هر فاز: «تمام / نیمه / باز» + اثباتِ observable (نه فقط سبزیِ تست).
در پایان: به‌روزرسانیِ `Active Context`/`Progress` + HANDOFF (wikilink، <۲۰۰ خط).

و صادقانه بگو: کدام مسیر نیاز به ری‌استارت دارد (و فقط با رأیِ مالک).
