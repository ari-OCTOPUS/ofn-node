## ماتریس سطح اثر (مرجع)

| سطح | معادله چه می‌کند | مجوز |
|------|------------------|------|
| **advisory (امروز)** | فقط گزارش/توصیه، بدون اثر تصمیم | همیشه مجاز |
| **proposal** | پیشنهاد با تأیید انسانی | بعد از فاز M انتخاب ۲ |
| **limited-effect** | throttle/pause موقت فقط | بعد از فاز M انتخاب ۳ |
| **authority** | تغییر policy/ledger/code/send | **ممنوع** — هرگز بدون ADR جدا |

## فاز J — اتصال خودکار، مشاهده‌گر فقط

**هدف:** اختاپوس خروجی‌های معادلات را می‌خواند ولی فقط با برچسب `advice_only` نمایش می‌دهد.

**جریان:**
```
سؤال کاربر → تشخیص intent → owner_recall + cortex + business_brain + vault
  → ساخت پاسخ + شاهد
  → برچسب معادلات: equation_advice_only=true, decision_effect=false, apply_effect=false
```

**مجاز:** context جمع‌کردن · facts مرتب‌کردن · تناقض نشان‌دادن · پیشنهاد بهبود · گفتن کدام معادله مرتبط است.
**ممنوع:** هر خروجی معادله باید فقط `advice_only` باشد — نه فرمان.

**خروجی:** گزارش در evidence dir · هیچ تغییر فایل قفل‌شده.

**معیار عبور:** پاسخ‌ها شامل `equation_advice_only=true` · هیچ mutation خودکار · تست سبز.

---

## فاز K — Shadow Influence

**هدف:** بفهمیم اگر معادلات اجازهٔ اثر داشتند، چه تصمیمی می‌گرفتند. **بدون تغییر واقعی.**

**دو مسیر همزمان:**
```
مسیر واقعی:  تصمیم فعلی اختاپوس      → نتیجه واقعی
مسیر سایه:   تصمیم فعلی + امتیاز معادلات → نتیجه فرضی
```

**خروجی هر تیک:**
```json
{
  "tick": 32648,
  "real_decision": "continue",
  "shadow_decision": "slow_down",
  "equation_reason": "pain_score_high (0.82 > 0.7)",
  "equations_consulted": ["bcm", "nociceptor", "control_law"],
  "applied": false,
  "divergence": "real=continue vs shadow=slow_down"
}
```

**مجاز:** اجرای موازی محاسبات read-only · ثبت اختلاف در JSONL جدا.
**ممنوع:** مسیر سایه هرگز decision واقعی را تغییر ندهد · هیچ state/flag نوشته نشود.

**خروجی:** `_ops/state/shadow-influence/` · فایل‌های قفل‌شده دست‌نخورده.

**معیار عبور:** ۷ روز دادهٔ سایه · هیچ applied=true · هیچ mutation · پایداری در replay.

## فاز L — مقایسه و ارزیابی

**هدف:** آیا معادلات واقعاً مفیدند یا فقط پیچیدگی اضافه می‌کنند؟

**معیارها (حداقل ۷ روز):**
| # | سؤال | سنجش |
|---|------|------|
| ۱ | چند بار سایه بهتر بود؟ | شمارش divergence مطلوب |
| ۲ | چند بار هشدار اشتباه؟ | false-positive rate |
| ۳ | هزینه/زمان کم شد؟ | delta در cost/latency |
| ۴ | تصمیم امن‌تر؟ | شمارش incidents prevented |
| ۵ | با policy تضاد؟ | شمارش policy conflicts |
| ۶ | نوسان/توقف بی‌دلیل؟ | churn rate |
| ۷ | آسیب به memory/ledger/timing؟ | integrity check |

**شرط عبور پیشنهادی:**
- هیچ نقض امنیتی · هیچ secret خارجی · هیچ mutation خودکار
- نتیجه در چند اجرای تکراری پایدار
- رأی صریح مالک

**خروجی:** `shadow-influence-evaluation.md` با جدول معیارها + توصیه.

## فاز M — رأی سادهٔ مالک

**بعد از دیدن نتایج Shadow (فاز L)، فقط یک سؤال:**

> آیا معادلات اجازه داشته باشند فقط روی «سرعت و توقف موقت» اثر محدود بگذارند؟

| انتخاب | معنا | پیشنهاد |
|--------|------|---------|
| **۱. نه** | همه‌چیز advisory بماند | اگر Shadow نشان داد вред多于فائده |
| **۲. فقط پیشنهاد** | معادلات پیشنهاد دهند، تو تأیید کنی | **پیشنهاد اول** — دورهٔ آزمایشی |
| **۳. اثر محدود** | فقط throttle/pause موقت، بدون memory/policy/code | بعد از شواهد کافی فاز L |

**پیشنهاد:** انتخاب ۲ ابتدا. بعد از شواهد کافی به ۳.

**خروجی:** رأی در `owner-verdicts.yaml` (tracked) + ADR کوچک.

## فاز N — خودکارسازی محدود (فقط با رأی مثبت فاز M)

**اگر رأی مثبت، فقط این اثرها مجاز:**
- کم‌کردن سرعت loop
- پیشنهاد pause
- کاهش concurrency
- جلوگیری موقت از proposal مشکوک
- درخواست تأیید انسانی

**هر اقدام باید این ۵ فیلد را داشته باشد:**
```
proposal_hash       — هش محتوای proposal
policy_version      — نسخه policy فعلی
state_version       — نسخه state
expiry_at           — زمان انقضای اثر
idempotency_key     — کلید ضدتکرار
owner_verdict       — رأی مالک
```
**اگر یکی غایب → DENY یا QUARANTINE.**

**ممنوع (حتی در فاز N):**
- تغییر کد خودکار · ویرایش policy · بازنویسی حافظهٔ معنایی
- اجرای proposal بدون PolicyGate · پیام خارجی · انتقال secret/Project-F

**خروجی:** capability record جدید با `may_gate=true` (فقط gate_internal) + ADR + شاهد ۷روزه.
