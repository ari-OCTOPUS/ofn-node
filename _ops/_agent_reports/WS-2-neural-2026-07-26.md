# WS-2 · The Neural Stack — does it learn from data or from noise?

## 1. VERDICT

**The neural learning stack is currently OFF in production and its outputs have never changed a decision.**

All four learning rules (Hebbian, BCM, consolidation, sparse filter) plus the latent space and encoders are dead code in the live organism. The master gate `OCTOPUS_WIRE_NEURAL` is absent from `OCTOPUS-flags.cmd`, and `flag()` defaults to `"0" == "1"` which is `False` (VERIFIED: read `wiring.py:30-31` and grepped the flags file — zero hits for any neural flag). When this flag is off, `make_neural_stack()` returns `None` (VERIFIED: `wiring.py:986`), so `_neural_stack` in both `organism.py:310` and `brain_worker.py` is `None`, and every neural beat and consolidation beat is a no-op.

Even when the stack was previously active (historical data exists from 2026-07-09 through 2026-07-26), no learning output ever reached a decision path. The three consumers of `hebbian.json` are: (1) `hebbian.py:21` (defines the path), (2) `cockpit_readmodel.py:226-227` (display), and (3) `nervous-system/extract_neural_data.py` (external extractor) — all display/extraction, zero decision-makers (VERIFIED by grep). The `protective_override()` function in `wiring.py:1046` is the one neural output that DOES change behaviour (it can halt or throttle the organism), but it reads `pain_level` and `reflex` outputs — which come from `Nociceptor` and `ReflexArc` operating on raw sensor inputs (sigma, budget%, afferent ratio). These are simple threshold guards, not learning rules. No Hebbian weight, BCM threshold, latent vector, consolidation insight, or sparse filter output has ever influenced a single `if` statement that controls organism behaviour.

The neural stack is architecturally complete and well-engineered, but it is a **museum exhibit with the power cord unplugged** — and even if plugged in, the exhibits feed only the gift shop, not the machinery.

## 3. Three Highest-Value Next Steps

### 3.1 Wire one learning output into a real decision

**Smallest test:** Add a single line in `organism.py` that reads `hebbian.strong_associations(threshold=0.5)` and, if the list is non-empty, logs it to the heartbeat. Run with `OCTOPUS_WIRE_NEURAL=1` for 1 hour. Check the heartbeat log.
- **Proves:** The Hebbian rule produces output in the live environment (not just tests).
- **Pass criterion:** Heartbeat line contains a Hebbian association string.
- **Why smallest:** One log line, zero risk, no decision change.

### 3.2 Populate the latent space and verify retrieval works

**Smallest test:** In a test that sets `OPS_DIR` to a tmp dir, create a `SharedLatentSpace`, embed 3 keys using `encoders.encode_observation()`, then call `nearest()` on one of them and assert the correct key is returned with cosine > 0.5.
- **Proves:** The encoder → embed → retrieve pipeline is functional end-to-end.
- **Pass criterion:** `nearest(key_1)[0][0] == key_1`.
- **Why smallest:** No organism, no flags, no live state. Pure unit test of the pipeline.

### 3.3 Make BCM step produce a non-trivial weight

**Smallest test:** In the same isolated test, create a `BCMStabilizer`, run `step(activations={"key_a": 1.0}, known_keys=["key_a"])` 3 times, then assert `bcm.weight("key_a") > w_init` (because y=1.0 > theta=0 initially, so phi>0).
- **Proves:** BCM actually reinforces a repeatedly activated key (LTP).
- **Pass criterion:** `weight > 1.0` (w_init=1.0, eta*phi adds to it).
- **Why smallest:** No latent space, no consolidation. Just BCM + one key.
