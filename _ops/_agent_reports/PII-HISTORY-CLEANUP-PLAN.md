## ۰. توصیهٔ صریح: **الان نزن**

سه دلیلِ اندازه‌گیری‌شده:

۱. **هیچ چیزی روی اینترنت نیست.** تنها remote یک مخزنِ bare روی دیسکِ خودت است
   (`E:/germline/octopus.git`). نه GitHub، نه اشتراکی.

۲. **فایل به‌هرحال روی دیسک plaintext است.** هر کسی که بتواند تاریخچهٔ git را بخواند،
   می‌تواند خودِ فایل را هم بخواند. تا وقتی همه‌چیز محلی است، تاریخچه **سطحِ افشای تازه‌ای
   اضافه نمی‌کند** — فقط نسخهٔ دوم است.

۳. **هزینهٔ عملیات واقعاً بالاست.** بازنویسی هر SHA در ۸۵ ref (۴۲ تگ + ۲۰ `refs/rescue`
   + برنچ‌ها) لازم است، و همین الان ۴۰۱ فایلِ کامیت‌نشده (۱۱۰ تغییریافته + ۲۹۱ تازه) روی درخت هست.

**قاعدهٔ تصمیم — یک جمله:** untrack جلوی **کپیِ تازه** را می‌گیرد؛ پاک‌سازیِ تاریخچه فقط
در **لحظهٔ اولین اشتراکِ بیرونی** اهمیت پیدا می‌کند. تا آن لحظه نرسیده، این عملیات ریسک
است بدونِ سود.

**ماشه:** اگر روزی تصمیم گرفتی به GitHub (یا هر میزبانِ بیرونی) push کنی — **قبل از
اولین push** این پلن را اجرا کن، نه بعدش.

## ۳. مراحل

```bash
# ❶ ابزار (خارج از repo نصب شود)
pip install git-filter-repo

# ❷ آینهٔ کاملِ کار — روی خودِ درختِ زنده هرگز اجرا نشود
cd F:/
git clone --mirror F:/backup F:/pii-rewrite.git
cd F:/pii-rewrite.git

# ❸ بازنویسی: حذفِ مسیرها از تمامِ تاریخچه و تمامِ refها
git filter-repo --invert-paths \
  --path "_ops/state/OWNER-PROFILE.json" \
  --path "_ops/state/OWNER-PROFILE-LOG.md" \
  --path-glob "03 - Projects/*/08 - Partner (PII)/*"

# ❹ راست‌آزمایی — باید صفر باشد، در همهٔ refها نه فقط HEAD
git log --all --oneline -- "_ops/state/OWNER-PROFILE.json" | wc -l
for r in $(git for-each-ref --format="%(refname)"); do
  git ls-tree -r --name-only "$r" | grep -iE "OWNER-PROFILE|08 - Partner" && echo "باقی‌مانده در $r"
done
echo "اگر هیچ خطی چاپ نشد → تمیز"
```

**فقط اگر ❹ کاملاً ساکت بود**، نتیجه را جایگزین کن — و این جایگزینی تصمیمِ جداگانهٔ مالک
است، نه ادامهٔ خودکارِ همین اسکریپت.
