## ۰) پیش‌شرط‌ها — هر سه، قبل از هر کاری

**۰-۱) فایل‌های توقف.** وضعیتِ VERIFIED در ۲۰۲۶-۰۷-۲۸ ~۰۰:۵۰ سیدنی:

| فایل | وضعیت | معنی |
|---|---|---|
| `F:\backup\_ops\STOP-TG-CENTER` | **نیست** (جست‌وجوی کل درایو) | ری‌استارت آزاد است |
| `F:\backup\_ops\HALT-ALL` | چک کن | اگر هست، watchdog هرگز revive نمی‌کند |
| `F:\backup\STOP` و `04 - Architect System\STOP` | چک کن | همان — پانیکِ سراسری |

اگر `STOP-TG-CENTER` موجود بود: حضورش یعنی «عمداً خاموش». حذفش تصمیمِ مالک است،
نه ایجنت. دو خطِ آخرِ watchdog-log (`14:27` و `16:07` ِ ۲۷ جولای) دقیقاً همین را
می‌گویند.

**۰-۲) خطرِ دو لانچرِ هم‌زمان.** `RUN-TG-CENTER.bat` خودش یک حلقهٔ
خود-راه‌انداز است. اگر یک نسخه زنده باشد و دومی را باز کنی، دو مرکز روی یک
توکن با هم 409-fight می‌کنند (کامنتِ خودِ watchdog). اول چک کن:

```powershell
Get-CimInstance Win32_Process -Filter "Name='python.exe'" |
  Where-Object { $_.CommandLine -match 'telegram_center\\center\.py' } |
  Select-Object ProcessId, CreationDate
```

**۰-۳) نویسنده‌های هم‌زمان.** ری‌استارت فایلی نمی‌نویسد، ولی طبق قاعدهٔ §0/۱۷
اول `git status --porcelain`. این درخت الان یک نشستِ فعالِ دیگر هم دارد
(`initiative.py`, `COMMIT-PATHS-2026-07-27.txt` — mtimes ساعت ~۰۰:۰۰–۰۰:۰۶).

## ۱) مسیرِ نرم (ترجیحی) — فقط پایتونِ مرکز را بکش

**چرا کار می‌کند (VERIFIED از خواندنِ `.bat`):** لانچر در **هر دورِ حلقه**
دوباره `call "F:\backup\_ops\OCTOPUS-flags.cmd"` می‌زند و بعد `center.py` را
اجرا می‌کند. پس کشتنِ فرزندِ پایتون کافی است — ~۱۰ ثانیه بعد یک پروسهٔ تازه
با فلگ‌های تازه بالا می‌آید. بستنِ پنجره لازم نیست.

```powershell
# یک) قربانی را پیدا کن — باید دقیقاً یکی باشد
$victim = Get-CimInstance Win32_Process -Filter "Name='python.exe'" |
  Where-Object { $_.CommandLine -match 'telegram_center\\center\.py' }
$victim | Select-Object ProcessId, CreationDate   # چشمی: دقیقاً یک سطر

# دو) فقط همان PID
Stop-Process -Id $victim.ProcessId -Force

# سه) ~۱۵ ثانیه صبر؛ لانچر می‌نویسد «tg-center exited - waiting 10 seconds»
#     و با فلگ‌های تازه respawn می‌کند.
```

⛔ **هرگز** `taskkill /im python.exe /f` بی‌هدف — ارگانیسم پایتون‌های دیگر هم
دارد (`organism.py`, `live_loop.py`, مغزِ پولی). فقط PIDِ هدفمند.

اگر **هیچ** پایتونِ مرکزی نبود و پنجرهٔ لانچر هم نبود: watchdog
(`schtasks "OCTOPUS-TG-Center-Watchdog"`، هر ۵ دقیقه) خودش بالا می‌آوردش — یا
برو به مسیرِ سخت.

## ۲) مسیرِ سخت — بستن و بازکردنِ لانچر

نتیجه همان است، فقط کندتر و با ری‌استِ کلِ حلقه.

## ۳) پروب — سه مرحله، هر مرحله یک عدد

**P1 — پروسه زنده است (≤۱ دقیقه):** کوئریِ ۰-۲ باید **دقیقاً یک PID** برگرداند.

**P2 — پروبِ فعال (≤۲ دقیقه):** داخلِ تاپیکِ 🦑system بنویس `/now`.
- جواب در **همان تاپیک** (topic_id=28) → فلگ LIVE است. تمام.
- جواب در **General** → هنوز بارگذاری نشده. **ری‌استارتِ دوبارهٔ کور ممنوع** —
  برو به قاعدهٔ تشدیدِ P3.
- هیچ‌جا نیامد → مسئلهٔ تازه است؛ BS-1.

**P3 — پروبِ غیرفعال (مجانی، ≤۱۵ دقیقه):** مرکز ~هر ۱۰ دقیقه خودش می‌فرستد.
تازه‌ترین رکوردِ `stream=center` به گروه را بخوان:

```
python -c "import json;rows=[json.loads(l) for l in open(r'F:\backup\_ops\state\tg-send-log.jsonl',encoding='utf-8')];c=[r for r in rows if r['stream']=='center' and r['chat']==-1004475788460];print(c[-1])"
```

| نتیجه | حکم |
|---|---|
| `"topic": <عدد>` | **BS-2 در ران‌تایم بسته شد.** رکورد را در گزارشِ جلسه ثبت کن |
| `"topic": null` **بعد از ری‌استارتِ تأییدشده** | env دیگر اثباتاً تازه است → نقص در مسیرِ free-formِ **کد** است → ارتقا به §6 fix-bug (فلگ + تست + مشاهده‌پذیر). **ری‌استارتِ مجدد ممنوع** — چیزی را عوض نمی‌کند |
| رکوردِ جدیدی نیامد (۳۰+ دقیقه) | کِیدنس عوض شده یا مرکز بیکار است → P1 را تکرار کن، بعد حرکتِ `last_offset` در `center-config.json` |

> نکته: آخرین رکوردِ فعلیِ لاگ `2026-07-28 00:25:36` با `topic: null` است —
> یعنی baseline قبل از ری‌استارت را داری؛ هر رکوردِ بعد از ری‌استارت، تستِ
> ابطال است. مجانی.

## ۴) بازگشت (Rollback) — همیشه مجاز، بدون رأی (عدم‌تقارنِ §6)

```
echo. > F:\backup\_ops\STOP-TG-CENTER
```

مرکز در دورِ بعد خارج می‌شود و watchdog هم revive نمی‌کند. برای برگشت:
فایل را حذف کن و صبر کن (watchdog ≤۵ دقیقه) یا مسیرِ ۲ را اجرا کن.
