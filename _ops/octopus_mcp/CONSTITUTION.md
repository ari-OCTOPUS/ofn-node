## ۲. سطحِ MCP (سرور: `_ops/octopus_mcp/server.py`، ثبت: `.mcp.json`)

پنج ابزار — چهار خواندنی، یک پیشنهادی:

| ابزار | چیست | سقف |
|---|---|---|
| `list_tree` | درختِ یک پوشه | ۵۰۰ ردیف، عمق ≤۴، برش اعلام می‌شود (`truncated`) |
| `read_file_slice` | برشِ بایتیِ فایل | ۶۴KB در هر فراخوانی |
| `hash_file` | SHA-256 (برای dedup/راستی‌آزمایی) | — |
| `search_hybrid` | محتوا (rg؛ بدونِ rg → فقط فایل‌های tracked) + نامِ فایل | ۲۰۰ خط؛ **هرگز os.walk روی کلِ درخت** |
| `propose_action` | تنها نویسنده: JSON به `_octopus/queue/pending/` | فقط kindهای مجاز؛ `delete_file` ساختاراً رد می‌شود |

گاردهای هر پنج ابزار (نمادها در `server.py`):
- `_resolve` — **اول resolve، بعد قضاوت**؛ خروج از ریشه = `outside-root`.
- `_denied` — الگوهای `.agentignore` + `_HARD_DENY` (`.git`, `_code`, …)؛ روی **خروجیِ جستجو هم** اعمال می‌شود، نه فقط ورودی.
- فقدانِ `.agentignore` = **fail-closed** (همه‌چیز بسته).
- هیچ ابزاری برای delete/move/overwrite ِ مستقیم وجود ندارد و اضافه نخواهد شد؛ اثر فقط از صفِ تأیید.

## ۳. پروتکلِ چندمغزی (نگاشتِ ۹ مغزِ طرح به ابزارِ واقعی)

| مغزِ طرح | تجسمِ واقعی در این مخزن |
|---|---|
| ۱ هماهنگ‌کننده | جلسهٔ اصلیِ Claude — تنها نقطهٔ merge و تنها تصمیم‌گیر پیش از ارائه به مالک |
| ۲ کاوشگر | ایجنتِ `Explore` / ایجنت‌های read-only ِ workflow |
| ۳ آرشیودار (**تنها نویسنده**) | خودِ جلسهٔ اصلی: فقط او حافظه/HANDOFF/نوت می‌نویسد؛ زیرایجنت‌ها **فقط برمی‌گردانند** |
| ۴ متفکر | سنتز در جلسهٔ اصلی با ارجاعِ file:symbol (نه شماره‌خط — درسِ cite-symbols) |
| ۵ DevOps | Bash/PowerShell ِ جلسه؛ کدِ آزمایشی فقط در scratchpad |
| ۶ خواننده | Read (تصویر/PDF-خوان) |

| ۸ لاشخور (dedup) | `hash_file` + قاعدهٔ §۹ vault: فقط byte-identical؛ **فقط propose، هرگز اجرا** |
| ۹ ابزارساز | خودِ همین پوشه — ابزارِ جدید فقط با آزمونِ اثباتی و ثبت در همین سند |

**قاعدهٔ single-writer** (از طرحِ اولیه، پذیرفته و از قبل رایج): خواندن موازی، نوشتن سریال
از یک نقطه. دو نویسنده روی یک فایلِ حالت = نوسان (درسِ which-process-restarted).

**فازبندی:** MVP = همین ۵ ابزار + صفِ موجود. توسعه (extract_text/OCR، مغزهای بیشتر) فقط
بعد از اینکه صفِ پیشنهاد **مصرفِ واقعی** پیدا کند — ماشینِ بی‌مصرف را بزرگ نمی‌کنیم.

## ۴. حافظه و ماندگاری

- ماندگاریِ ساختار = **همین فایل، tracked**. تغییرِ پروتکل = ویرایشِ همین فایل + کامیت.
- «کهنه‌شدن» خطرِ اصلی است نه «فراموشی» — قانون هم از کدش عقب می‌افتد. پادزهر:
  `constitution_drift.py` در هر مرورِ هفتگی، کنارِ دو validator ِ موجود.
- این سند **نامِ نماد** می‌برد (`_resolve`، `_denied`، `t_propose_action`) نه شماره‌خط؛
  خودآزمون وجودِ نمادها را می‌سنجد.
